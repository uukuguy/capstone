# brainstorming

Form a useful question and success conditions from the user's intent. When the request is clear, proceed without a question sequence. Open exploration needs a bounded scope, not a preselected anomaly or hypothesis.
Compare approaches only where they change the decision: available evidence, interpretation, cost and reversibility. Ask only for missing information that blocks the next useful action; continue independent work.
Record accepted scope, assumptions and unresolved choices in the current task plan. Do not create a software specification, repository commits or approval gates as a default. Do not expand permissions.
Hand the accepted objective to task-planning-and-tracking when sustained work needs a plan.

When the native skill record tool is available, load this exact admitted skill and report meaningful public phases with related tool IDs and product references. Loading does not prove application or successful verification. Use a bounded summary; never include credentials or private reasoning.
