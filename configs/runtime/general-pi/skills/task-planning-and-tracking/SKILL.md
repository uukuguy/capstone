# task-planning-and-tracking

Use one task plan. Extend the existing task organization and state before creating a task-private working note. Files are a storage method; do not start a separate ledger for each skill. Never write task notes into the skill package or host repository.
State the objective, constraints, selected inputs, useful steps, actual dependencies and acceptance conditions. Keep known calculations distinct from decisions that require unseen results. A Provider plan/job is an execution reference within the investigation, not the investigation itself.
Track completed observations, selected immutable input versions, products, supporting and opposing evidence, quality gaps, remaining budget and the next useful action. Save concise public decision reasons, not private chain of thought. Read bounded summaries rather than all source files.
Revise the plan when evidence changes the next action; preserve the reason and previous references. Reuse saved results before expanding source access. Do not count ancestor and descendant cumulative pages twice.
At recovery, verify current authorization, instance, environment, contract, reference versions and actual job status. Read saved outputs before deciding whether to resume, replace or cancel. Reads do not advance jobs. Unknown source effects are not safe retries.
Stop at the budget or evidence boundary and deliver useful partial findings, missing scope and recovery conditions. Never mark the whole task complete merely because its current queue is empty.

When the native skill record tool is available, load this exact admitted skill and report meaningful public phases with related tool IDs and product references. Loading does not prove application or successful verification. Use a bounded summary; never include credentials or private reasoning.
