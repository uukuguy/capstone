# verification-before-completion

Read the current goal and acceptance conditions. Verify each important claim against actual saved observations, calculations or products. Tool success, job completion, complete sampling and a supported conclusion are separate checks.
Check source identity, selected reference versions, coverage, quality, comparison definitions and algorithm prerequisites. Use data-quality-and-comparability for an unresolved evidence prerequisite. Preserve partial, unknown and failed scope.
Check that required products exist, can be read and have the expected content. Required persistence failures are fatal; a persuasive narrative does not replace a saved result.
Cross-check descriptive labels against the saved numerical observations. A correct table does not validate a contradictory sentence such as a flat curve with varying samples. Verify reported change times against observed adjacent samples; separated windows do not locate an intervening transition.
Separate observed facts, associations, hypotheses and established causes. Similarity is not causality; no match is not absence; sampled findings are not population laws.
Record what was checked, the evidence references, the actual outcome and remaining limits in shared task state. A model-reported verification is not host-certified truth. Report partial completion honestly. Do not launch a new full investigation merely to improve polish.

When the native skill record tool is available, load this exact admitted skill and report meaningful public phases with related tool IDs and product references. Loading does not prove application or successful verification. Use a bounded summary; never include credentials or private reasoning.
