## 研究判断

优先延伸现有引用与指令路径。BusinessObjectRef 可作为统一概念，但具体对象需保留严格类型；不先新增通用对象表或另一套 Task 实体。
模型负责解释用户意图；宿主负责引用归属、版本、权限与执行目标检查。视图选中对象不授予操作权限。
工作空间转换应尊重用户手动选择。业务成果与诊断视图共享实际执行身份及因果引用。

## 首个建议切片

选择已有成果中的一个对象，显示来源和版本，发出局部指令，交付新成果，并保留旧版与来源关系。
具体选用结果行还是报告段落，待核实已有局部锚点契约后确定。

接受场景：引用准确送入执行；局部指令不覆盖整体目标；新成果不覆盖旧版；刷新后引用和成果可恢复；引用失效有明确反馈；历史内容不自动成为当前 Authority 证据。

## 第二轮：引用路径的确定缺口

1. `threadProducts.ts:7` 的 ContextProductRef 仅有完整 ProductRef、historical-context 和 excerpt.max_bytes。它没有段落、表格行或单元格定位字段。
2. `CapstoneAssistantThread.tsx:1337` 将显式成果引用加入输入草稿，按 productRefKey 去重。现有入口可复用，但同一成果的多个局部选择需要重新检查去重语义。
3. `thread_input.py:59` 调用 checked_selections；`thread_products.py:59` 严格检查字段。因此不能只在前端附加局部锚点，必须同步公共契约与服务端校验。
4. `thread_products.py:346` 的 freeze_product_selection 解析显式引用并冻结内容。第366行的 excerpt 是 UTF-8 字节前缀截取，不是用户选中的段落。当前界面引用不能据此宣称支持精确局部引用。
5. 冻结记录标记 historical_only，专业路径接收有界文本上下文，通用路径形成材料。局部引用扩展必须保留这一历史来源边界，并单独核实大文件按需访问路径。
6. `ThreadWorkAdapter.tsx:312` 的 prepareSourceQuestion 创建新的 enterprise-research 会话，上传冻结源视图摘要并设置草稿。当前路径提供新会话探索，尚不满足同一工作内选中对象后连续追问的目标。

## 协议范围建议

首个切片限定为已有文本成果的局部续作。复用父 ProductRef；新增按内容格式区分的局部选择，并绑定父版本、局部定位和内容摘要。不得把字节前缀 excerpt 当作局部选择。

待设计的关键点：
- 局部锚点由可验证的解析器生成；重复文本须可区分，DOM位置不能成为唯一身份。
- 同一成果的多个选择需要独立身份；当前 productRefKey 去重及由父ref生成 material_id 的逻辑必须一起审查。
- 提交时冻结选择，后续切换视图不改变已提交指令；失效引用返回可操作原因。
- 新成果记录派生来源，旧成果保留；是否替代正式交付物需明确的用户操作。
- 全文读取、局部读取和模型上下文预算分别约束，不能把当前内联材料路径作为GB级资源方案。

研究接受仍缺：稳定局部锚点方案、真实模型续作、PostgreSQL恢复及浏览器刷新验证。当前阶段足以确定复用方向，尚不足以批准完整实现。

## 局部引用协议草案（待审阅）

推荐采用版本固定的解析块引用。父对象沿用 ProductRef；局部选择包含解析器版本、块ID、块内容摘要和选择用途。块ID由服务端对固定版本内容解析生成，不接受浏览器任意声明为可信身份。块序号可以参与同一固定版本内的定位，但必须与父身份、解析器版本和块摘要共同校验。

首期支持 UTF-8 纯文本与 Markdown 的完整段落块。复杂表格、PDF、DOCX及跨块范围另设类型协议和接受标准，不假定格式转换保留原锚点。相同文本的两个段落仍有不同块ID。新父版本生成新锚点；跨版本重定位只给候选，由用户明确采用，不能静默改写已提交引用。

其他选择：字符偏移加摘要实现简单，但解析转换和Unicode边界容易失配；纯引文匹配便于解释，但重复文本存在歧义。两者可以辅助定位，不能独立替代版本固定的块引用。

选择身份由父ProductRef、解析器版本、块ID和块摘要共同确定。完全相同的选择去重；同一父成果的不同块分别保留。材料ID也使用完整选择身份，避免现有按父ref生成ID时发生碰撞。显示顺序保留用户选择顺序；它不自动成为工具执行顺序。

提交时服务端重新检查访问权、父版本、解析器与块身份，再冻结本次选择。UI显示来源成果、版本和段落预览，可移除选择。旧父版本仍可访问时允许明确引用历史版本；内容缺失或校验失败时提供重新选择入口。解析失败只阻止依赖该引用的指令，不改写历史成果。

应用层拥有引用封装、准入与UI投影；内容解析服务拥有块定位。Kernel只接收已准入的有界上下文，不解释报告段落或电网对象。新成果保存输入选择来源；专业证据仍按当前运行准入。

建议验收集：重复段落、多选去重、伪造块ID、父版本变化、中文与组合字符、提交后切换选择、源文件丢失后的幂等重试、刷新恢复及新旧成果共存。先以真实文本成果验证再扩展格式。
