# 引用执行的可行性研究与实施建议

2026-11-06。效率优先，安全性并行评估。本报告依据本地源码检查与公开一手资料；没有运行性能实验，所有收益均为待验证假设。

## 判断

适合增量实现。采用服务端可组合的确定性算子、客户端引用编排、模型在需要判断时介入的混合方式。保持工具集自由选择，不编写迎峰度夏专用固定流水线。纯引用且无语义反馈会削弱调查能力；首期允许有界摘要和质量信息，记录其出境性质。

## 依据与适用边界

- [Anthropic MCP code execution](https://www.anthropic.com/engineering/code-execution-with-mcp)：中间数据不必经过模型上下文，程序可完成工具组合和过滤。启发是减少机械往返；文中收益不能转用为本项目预测。
- [Ray object references](https://docs.ray.io/en/latest/ray-core/objects.html)：引用传递与远端对象分离可支持依赖计算。借鉴身份、生命周期和依赖，不引入 Ray；对象引用不自动提供权限或永久持久化。
- [DuckDB optimizer](https://duckdb.org/2024/11/14/optimizers)：尽早筛选和减少参与计算的数据有价值。但总线未必支持源端聚合，网关本地计算下沉不能冒充源查询下推。

## 源码发现

Capstone 的 `packages/capstone-agent/src/capstone_agent/resources/tool-composition.mjs` 已支持独立 calls、tools.map、逐调用来源记录、有界结果及相同请求复用。复用受明确只读、幂等及非破坏标记约束；不是跨会话语义缓存。`tool-composition-worker.mjs` 提供程序执行帮助。无需重建批量调度器。

网关 `providers/epri-service-bus/src/epri_service_bus/investigation.py` 已提供 derive_measurements、aggregate_measurements、compare_measurement_periods、prepare_measurement_aggregation。分析计划最多 20 步，以先前步骤引用建立依赖，但 advance 实现按步骤顺序运行，单次最多 4 步；不是并行 DAG 执行器。

`streaming.py` 支持分批读取已保存制品、累积聚合状态和恢复。当前准备阶段会读取并运行各输入的聚合验证，正式执行时再次聚合，需测量这部分重复计算。限制包含单数据集 50,000 行、聚合计划最多 128 个不同引用及总行预算最多 1,000,000；这些是当前有界实现，不代表 GB 级整体架构已经完成。

`implementation.py` 将调查工具声明为 readOnlyHint=True，只有部分工具声明幂等。因此不能把“创建结果对象”直接当作当前客户端串行的原因。需核对每个工具的真实副作用与 job 锁：同一 job 应串行，不同 job 的并发仍需存储和源端能力实测。

这些是源码能力，不等于三套实例均已部署。实际发布目录、身份与契约需在实验前记录。

## 建议的执行模型

1. 模型选择目标、切片、方法及需要观察的结果；不是每次取页都重新规划。
2. Capstone 在已准入工具上执行有界引用程序，未知语义不自动推断；已有 server plan 可合并确定的步骤。
3. 网关完成数据计算，返回引用、类型、结构、口径、质量、覆盖及有界摘要；大结果不进入模型上下文。
4. 模型读取决策所需摘要，选择进一步计算、补证据、交付或响应用户转向。
5. Work 保存目标修订、动作和结果关联。网关 job 保存计算进度；两者通过引用关联，不能互相冒充权威状态。

引用对象描述是候选接口，至少包含原始引用、对象类型、来源实例、版本已知性、父引用、结构与语义、完整性和质量、可读取的有界投影。缺少的字段记 unknown；不能自行制造数据版本。先在 adapter 的可选扩展边界适配，不把 provider 字段塞入 Kernel。

模型决策边界：输入/方法出现歧义、观察到值得追查的现象、结果不满足前提、用户改变方向。机械执行边界：已知分页、明确依赖、已验证算子链及受限状态续进。执行步骤必须保留实际事件，不能只显示整个程序成功。

失败恢复需要关联任务和动作身份，处理“服务端已完成、客户端未收到”窗口。只有明确幂等或可查证完成的操作才能重试；客户端取消不等于撤销已创建对象。失效引用按来源解释，不能静默换源重算。

## 效率模型

总耗时由模型决策、控制往返、源访问、服务端计算、制品 I/O 和报告生成组成；并发后的总耗时由关键路径决定，不能简单求和。优化优先减少模型决策次数及输入量、重复取数和重复计算，再评估批量控制调用。只有少量数据且一次调用的任务可能因对象落盘变慢。

服务端对象保存也带来容量、清理、版本及恢复成本。首期显式复用选定引用，不建立任意重叠查询缓存；缓存键至少需操作版本、输入版本、参数和权限范围，源版本未知时不能假定重新查询相同。

## 实施切片与代码边界

### A：测量与最小引用闭环

扩展 tool-composition.mjs 的既有回执，记录模型可见字节、源/计算调用、排队及执行时间、对象引用复用。新建聚焦测试，验证摘要有界且保留真实引用、错误与来源。使用实际发现名称选择网关已有算子，不新增通用 SQL 或任意服务端代码执行。

交付：同一份数据执行两个分析并生成可读取结果，不重复取源；模型不接收原始行。先用本地受控数据确认算术等价，再运行授权真实切片。

### B：引用描述与恢复

在 data_gateway_mcp.py 所属适配层消费可选对象描述，配合现有 general_pi_server.py 的准入及 thread_service.py 的 Work 快照关联。新增独立对象描述模块，避免扩大服务器单文件职责。测试跨实例拒绝、旧版本保留、无响应后的查询恢复、取消后不启动新动作。跨提供方引用只能按已发布的显式转换规则使用。

### C：调查反馈与自由跳转

扩展 enterprise-cycle-state.mjs、enterprise-research-runtime.mjs 的既有发现/检查点，核查默认轻量路径的实际接入。让发现引用和选定数据集随 Work 恢复，用户改基线只使受影响结论失效。ThreadWorkAdapter.tsx 复用现有过程与成果组件呈现摘要。测试“先报告—改对象—回旧问题—刷新继续”，不要求固定阶段。

### D：成果与出境测量

在内网成果通道使用结果引用制作图表、CSV、PPT，并记录报告与输入版本关系。先复用 Capstone 隔离原生执行器；若数据仍被下载到该执行器，要明确它只是内网客户端计算，不算网关计算全下沉。网关托管渲染属于后续独立能力，不能假定已存在。

对模型请求单独保存受保护的字段类别及字节审计；原始输入、工具错误、摘要、历史、图像及遥测均纳入评估。默认在内网模型上完成执行等价验证；真实内网信息交给外部模型前明确可外发类别，研究授权不等于数据出境授权。

## 对照实验

比较 A 当前方式、B 仅服务端计算下沉、C 下沉加引用程序与有界反馈，以分离两项收益。固定数据快照、模型、任务、并发和交付要求，交错执行至少三组配对试验，区分冷/热缓存。样本少时只报告各次值和中位数，不声称稳定 P95。

迎峰度夏覆盖目标/基线、质量、比较、一个局部追查、PPT/CSV、用户改基线及恢复。另用不同主题排除业务硬编码。比较正确性、来源、缺口诚实性、成果可打开性，以及首个有效发现、总耗时、模型调用、上下文量、源请求、字节、错误和重复工作。先定相同质量要求，再判断速度；不预先承诺提升百分比。

## 未决项和决策条件

### 2026-11-07 接入核验

通过 Capstone 实际 DataGatewayMcp 适配器连接本机 18001 主入口，成功发现 57 个工具，但没有 measurement 分析工具。网关 `runtime/validation/bus-server-analytics-20261106/deployment.json` 同样记录 bus_groups=0、bus_tools=0。因此源码已实现和主入口已发布是两个状态，当前不能在该入口完成真实服务端引用分析。

网关 installed-mcp.json 记录 28 个工具的安装包 MCP 验证，但明确使用 synthetic bus transport、live_bus_verified=false，不能代替真实源验收。63、66 在本次探测中均无路由。本机引用组合回归 ee3c9123 的 41 项检查通过，只证明客户端机制。

接入验收前提：目标网关通过正常配置发布相应工具集，主入口发现结果包含分析工具；服务预检说明来源可用性；使用既有授权小切片取得真实 dataset_ref。随后以同一引用完成至少两项分析，检查实际源请求未重复、结果可读、摘要有界。工具名称取自发现结果。当前未更改网关注册配置或向外部模型发送业务数据。

需验证：实际网关发布版本、对象存储耐久性和租户隔离、并发/锁范围、准备阶段重复计算成本、服务端结果摘要是否足够支持调查、成果端数据搬运量。上述不确定性不会阻止最小闭环，但阻止宣称整体性能或安全验收完成。

推荐先交付 A；若源等待占主导，转向请求范围和源端能力；若模型往返占主导，推进 B/C；若报告耗时占主导，优化 D。用实测选择下一步，不把基础设施建设当作收益。
