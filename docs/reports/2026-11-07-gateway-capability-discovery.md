## Proposed data-gateway changes

1. Publish a compact, version-bound capability summary with discovery. Include
   purpose, applicable questions, prerequisites, input/output reference kinds and
   composition constraints. Describe dedicated operations versus generic exploration
   in provider-owned semantics. Missing metadata must remain explicitly unknown.
   Avoid returning all full input/output schemas in this overview.
2. Allow bounded contract sections to be read separately: usage/composition first,
   exact input/output schemas when constructing calls. Return the same stable tool
   identity and contract revision in each section. Preserve the existing complete
   contract response for compatibility.
3. In the compact summary, distinguish source pagination units, output sampling
   units and the scope of each budget. State which discovery provides configured
   mappings versus which operation reads business records. Counts and applicability
   must remain source-backed; the client must not infer overflow from resolution alone.

These are proposals, not assumed endpoints or fields. During this trial the model
read many complete contracts to build its plan. The trace supports investigating
contract retrieval cost; it does not establish a measured speed improvement from
either proposal. Capstone must not fabricate missing provider semantics.
