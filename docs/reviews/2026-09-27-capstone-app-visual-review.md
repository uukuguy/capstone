# CAPSTONE 演示工作台视觉评审

评审日期：2026-09-27。对象：已部署的 Railway App，源码基线 `941fdfb`。检查了 375、768、1280、1920 CSS px 的首屏、1280 px 的完整初始页面，以及已完成运行的操作区和报告。此文只记录评审结果，不改变当前页面。

## 结论

现有浅色、青绿色的视觉语言与电网图白底相容。顶图和中栏内容对齐，三栏桌面结构清楚，自动完成按钮位于右侧。四种检查宽度均未出现水平溢出；375 px 手机端纵向排列可用。顶图原图、内容与外框不建议重做。

最影响实际演示的不是局部留白，而是整页缩放导致桌面文字和控件过小。其次是拓扑图绘图区的比例与页面呈现不匹配，以及报告把技术记录直接作为访客正文展示。

## 发现与优先级

| 优先级 | 发现 | 实测依据 | 建议 |
| --- | --- | --- | --- |
| P1 | 桌面阅读和操作尺寸过小 | `styles-light.css` 对 `.app-shell` 设置 `zoom: .67`。1280 px 下案例说明的 13 px CSS 字体实际显示约 8.7 px；电网图工具按钮实际高约 23 px。1920 px 下仍使用同一缩放。 | 取消整页缩放，用明确的容器宽度、等宽侧栏和断点保持现有比例；正文和操作控件分别设定真实尺寸。先做桌面前后截图对比，再决定是否上线。 |
| P2 | 长页面下两侧栏失去导航和状态作用 | 本地 1280 × 900 页面滚动 383 px 后，标题栏和两侧栏标题都已滚出视口；长报告会使中栏继续向下延伸。 | 桌面端让标题栏固定在上方，左右栏贴在标题栏下方且高度不超过视口；侧栏内容超高时各自可滚动，中栏保持页面主滚动。手机端维持自然纵向排列。 |
| P2 | 拓扑图在白色画布中偏小 | 1280 px 下 IEEE-39 的 SVG 画布约 762 × 197 px，`viewBox` 为 1000 × 600；图形约占视图坐标宽度的 51%，受画布宽高比影响，实际仅占画布宽度约 22%。 | 在不拉伸电气/地理形状的前提下，提高画布有效高度并按容器尺寸适配全图；保留平移、缩放、任务对焦。 |
| P2 | 报告的阅读层级偏技术化 | 完成态中栏报告直接显示 `Application report`、`Question`、`Guarantee scope`、多条长哈希引用及原始 JSON。 | 保持原始报告和证据不变；访客视图先显示中文分析结论、步骤和限制，再将完整引用及机器记录折叠为可核查详情。 |
| P3 | 少量浅色小字对比度不足 | 案例路径 `#6c8383` 对背景 `#eef3f1` 约 3.59:1；顶图辅助文字 `#637b76` 对该背景约 4.05:1。 | 在桌面字号修正时一并加深这些文字；不改变整体配色。 |
| P3 | 手机端首个执行动作距离首屏较远 | 375 px 视口下整页约 3287 px 高，案例库、顶图和拓扑图都在时间线操作区之前。 | 当前可用，不作为本轮改动；若手机访客成为主要受众，再设计目录收起或执行入口。 |

## 实施边界

第一轮处理 P1 与桌面侧栏定位，并在 375、768、1280、1920 px 下对比当前截图。若真实字号和长页面操作明显改善，且不破坏已确认的顶图、三栏留白和电网图位置，再处理拓扑图与报告两个 P2。避免再次通过全局缩放、随意增减图片尺寸或重画顶图来修复页面比例。
