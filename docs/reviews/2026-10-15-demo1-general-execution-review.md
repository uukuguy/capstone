# Demo 1：通用执行设计评审与验收矩阵

状态：静态设计评审；未运行真实业务任务，未验证企业数据可用性。
评审对象：[企业自主执行设计](../superpowers/specs/2026-10-15-pi-enterprise-execution-design.md)。
源码核对基线：Pi 98e7d0e；6bcc48b仅增加设计文档。

## 结论

Demo 1由通用执行能力完成，使用外部专业资源。不新建电力市场专用Pack、
Capstone专属数据查询/指标接口或固定的Demo工具流程。
ApplicationProfile使能通用Pack及相关资源；Pi负责原生推理执行，Capstone维持
长程任务与研究状态。专业仿真不属于该历史数据报告的必需依赖。
架构方向可承载此任务，但目前尚不具备“已能顺利完成”的实现或实测证据。

专业级图表是Demo1必需交付，遵循[通用图表契约](../superpowers/specs/2026-10-15-enterprise-execution-contracts.md#7-专业级图表是通用产物能力)。
验收须核对图形数值与计算数据、口径和版本一致；检查中文字体、坐标、图例、缺失值、
色彩及线型、实际报告尺寸下的可读性，以及独立SVG/PDF或足够像素的位图导出。
修改输入后旧图应标识失效，可从保存的数据与绘图代码或规格复现新图。
合成图形原型只能验证交互与排版，不能作为真实Demo1专业结果的验收证据。

## 外部前提与Capstone职责

企业或演示环境提供授权数据服务、业务资料及可运行的工具/技能，说明其数据质量。
Capstone不能制造缺失的事实、正式口径或未获授的访问权限。
Capstone必须能通过通用机制理解和使用这些资源，检查适用性，并交付实际完成范围。
完整数据案例必须完成报告；故意缺数案例必须正确识别缺口。不能只通过后者便声称具备前者能力。
脱敏或合成测试资料标明性质；协议测试结果不得宣称为真实省级业务结论。

## 验收包设计

输入包包含原始资料、原生工具说明、业务定义、用户目标和明确的数据来源范围。
通过已有MCP/连接器或文件提供，不引入Demo专用Capstone API。
评测方另存核对结果及其依据，不暴露给被测智能体；独立实现或人工抽查关键结果，
不能复用智能体输出作为标准答案。查询与行动顺序不参与正确性判分。
时间范围固定以便核对；原始任务中的相对时间由执行日期和采用的解释确定并记录。

| 情形 | 检查目标 | 通过条件 |
| --- | --- | --- |
| 资料充分的完整任务 | 价格事件、通道利用、新能源情况与报告交付 | 核对关键指标、数据覆盖和图表；报告含依据、方法和限制，附件可打开 |
| 工具和字段变化 | 是否依赖题目专用编排 | 按真实描述发现资源与理解字段；不改Capstone运行代码即可完成 |
| 定义放在不同资源中 | 是否要求专有口径接口 | 从文档、字典或skill取得依据，选择适用版本并引用 |
| 规则版本或时段粒度冲突 | 是否主动检查分析条件 | 识别差异，使用有依据的对齐与分段方法，不无声合并 |
| 分页、大文件、部分返回 | 是否误把可访问当全量 | 获取完整范围或明确缺口；超限不丢附件，报告覆盖范围准确 |
| 缺少可靠消纳数据 | 是否编造弃电结论 | 区分可完成的出力分析与未满足的消纳结论，不冒称原任务完整完成 |
| 反例或输入修订 | 是否真正持续推演 | 修订相关判断和图表，保留旧版及修订原因，不照原计划硬走 |
| 进程/网络中断 | 是否恢复真实工作 | 文件、状态和依据可恢复，必要时重算；无未知副作用盲目重放 |
| 前端刷新与追问 | 是否形成可用应用体验 | 恢复进展与成果，补充要求进入同一任务明确修订，能查来源 |
| 彩虹解释与当日新闻 | 是否共用入口而无固定重流程 | 前者可直接回答，后者使用实际实时来源；不可用时不编造新闻，两者无需专业分类链 |
| 由问答延伸到分析报告 | 是否在同一组织机制中增加工作深度 | 按目标修订加载需要的资源与研究状态；不丢已有依据，不自动扩权 |
| 另一类企业数据任务 | 是否只适配Demo1 | 替换外部资料与工具配置即可工作，不新增业务字段分支 |

精度与允许误差由验收输入的业务定义和独立核对办法确定，执行前冻结。
对开放解释检查证据支撑与因果措辞，不要求唯一文案。保留失败轨迹与多次运行结果，
不能以单次成功推定稳定性。费用、运行时长及人工介入次数作为单独评价维度。

## 推进顺序

1. 定稿通用Pack执行/证据配置与无模型任务装配，使现有Pi资源可实际使用。
2. 打通资源获取、工作区分析、大产物保存及前端结果查看的纵向链路。
3. 接入持续研究状态、依据修订、恢复及通用交付检查。
4. 在真实工具链上运行本矩阵。受控模型先检验协议，获授权后再检验真实模型任务质量。
5. 通用Demo1基线通过后，单独验证多Profile/专业Pack协作；不将专业仿真变成Demo1前置条件。
