# 执行约束与持续推进审查

状态：用户认可的设计方向，具体修订未实现。适用于企业执行总设计、D1–D7、状态矩阵和实施计划。
目标是保留权限与事实边界，避免局部缺口升级为整项任务失败。

## 限制作用于最小相关范围

业务缺口和正常工具失败通过结构化观察返回智能体，不直接抛出任务级致命异常。
行动拒绝说明原因、受影响依赖和恢复选项，不指定必须采用的业务步骤。

| 原限制或风险 | 修订边界与继续路径 |
| --- | --- |
| 输入未全部齐备就等待 | 启动只需可理解目标及获准基本执行能力；边发现边取资料，处理不依赖缺失输入的工作 |
| 一个Profile/Authority不可用导致整体失败 | 关闭对应能力并说明原因；其他能力继续，不能把缺失Authority装成有效专业能力 |
| 分页结果不完整就不能使用 | 标partial/unknown，可分析已取得范围或继续获取；禁止声称全量或把缺测当零 |
| 口径冲突或缺检查器就拒绝报告 | 限制相关确定性声明；允许查证、比较解释、带来源假设及有限成果 |
| 一个附件失败禁止发送消息 | 未finalized附件不作为可用输入；文本和就绪资料仍可提交，显式显示未提交附件 |
| 一个导出失败使所有成果失败 | 该文件不发布，保留其他成果；可局部重试、分片或换允许格式 |
| 一个外部动作unknown阻塞全部恢复 | 禁止重放该副作用及依赖未确认结果；新租约可继续无关工作，同时核对该分支 |
| 所有历史产物都有效才能交付 | 只检查本次声明和交付实际依赖；过期历史草稿不拖累无关成果 |
| 预算不足自动failed | 对耗尽维度停止新增消耗，预留结算/保存余量；交付已有成果或暂停，不绕过总额 |
| 校验失败重跑全任务 | 仅重验受影响对象和依赖，保留其余有效成果 |

## 保留的硬边界

越权、跨租户引用、失去租约后新分发、参数违反工具契约，拒绝对应行动。
智能体可修正参数后重新提出，不放宽专业schema以求成功。
普通分析不能冒充Authority事实；缺验证不能声称已验证；历史专业证据仍须当前运行准入。
必要答案/证据持久化失败不能报告成功；账本不可用时停止需持久记录的新副作用，
按最后确认状态恢复。不能以持续推进为由虚构回执或吞掉错误。

## 状态与交付

- 存在合理且获准的下一行动时保持running，局部失败作为观察。
- waiting_input仅用于确需外部输入且当前没有可继续路径；无需穷举所有可能工具才允许等待。
- paused用于用户暂停、预算或可恢复的执行基础阻塞；failed用于无法建立或恢复可信执行基础的致命故障。
- partial表示有用交付已形成但原目标仍有缺项；允许主动交付，不无限重试追求completed。
- completed只要求履行明确约定的保证，不要求所有结论独立验证。模型提出的额外检查不自动成为硬门槛。
- 用户明确要求的验证或文件缺失时保留partial，不删除要求或自动降级目标来冒称完成。

运行状态、成果可用性和保证范围分别呈现；授权范围内的未验证或历史成果可查看并标明状态。
前端不把每个局部失败显示为整个会话失败。

## 验收要求

中性故障fixture同时验证拒绝和推进：缺一个资源仍能处理其他资料；缺独立检查器仍可形成
限定保证的报告；unknown外部写入不重放但无关读取继续；导出失败不丢已保存回答；
授权撤销只阻断相关能力；历史草稿过期不拒绝无关交付。
同时验证错误可见、明确要求未被删减、必要证据保存失败不能假成功。
业务任务质量与恢复测试仍开放；本轮只修订设计，不声称运行已改善。
