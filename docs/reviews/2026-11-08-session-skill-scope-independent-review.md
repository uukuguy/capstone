## 已确认、需修正的实现问题

### R1 / P1：排除信息没有完整进入实际执行合同

- `session_skill_preferences.py:79–82`：当本轮排除全部已选方法时，freeze仍保存excluded，但method_guidance直接返回空串。
- `delegated_runtime.py:209–245`只通过该字符串传递偏好；原生allowedSkills仍由完整资源profile生成
  （`native_resources.py:266–270`、`resources/general-sdk.mjs:1346–1350`）。没有任务级排除过滤。
- 纯函数实际复现：一个已选方法被排除后，冻结值为`skills=[]、excluded=['method']`，执行提示为`''`。
- `CapstoneAssistantThread.tsx:1688–1689`还有另一条确定路径：pi_reference模式下，若只有本轮排除而没有其它显式输入设置，
  构造出的metadata不会传给onSend，排除字段在发送前丢失。

后果：当前“本轮不沿用”的成功试跑依赖额外用户文字及模型遵循，不能证明界面排除本身得到保障。
先明确排除是“取消偏好”还是“本轮禁止自动选用”。无论取哪种语义，都要完整传输并测试全部排除与direct模式；
若保证本轮禁用，应在原生加载边界执行，不能只靠提示。显式本轮选择与排除冲突也应有明确优先规则。

### R2 / P1：保存偏好未绑定内容身份，同版本内容变化可静默接受

- `session_skill_preferences.py:17–23、39–46`只保存id/version/role，不保存loaded_identity或选定目录修订。
- `:26–36`只比较标签version，并在下一轮采用当前目录修订；现有目录已提供loaded_identity（`runtime_resources.py:39–47`）。
- 实际纯函数复现：保存1.0.0/content-A后，将目录换成1.0.0/content-B，freeze成功使用新目录，配置revision仍为1。

这不满足设计中的“技能升级不静默替换”。任务内读取文件的哈希检查只能保护任务内变化，不能补回用户选择时的身份。
建议保存选定内容身份，并在准入及实际加载时核对；区分无关目录更新与所选技能内容更新，后者必须显式重新接纳。
不要求冻结整份目录来阻止所有无关更新。

### R3 / P2：失效偏好阻断普通消息，但缺少针对性的恢复说明

`session_skill_preferences.py:33–34、49–58`与`thread_input.py:125–132`在技能下架、版本变化、ready=false或角色变化时拒绝整条消息。
`threadFeedback.ts:122`的文案表没有session_skill_unavailable/skill_exclusion_invalid；用户得到通用失败提示及诊断码，
不是设计要求的“哪项方法失效、如何重选”。设置可清空，草稿也保留，因此不是永久锁死或输入丢失。

建议给出准确失效项、配置修订和可见的重选/本轮不用入口，保持用户草稿，不自动更换版本或扩大授权。
是否允许与该方法无关的普通消息继续，应作为明确的产品决策。

### R4 / P2：设置冲突后缺少显式重新同步入口

`SessionSkillSettings.tsx:8、12–13`仅在打开面板时取得revision；冲突后只保留错误与草稿。
即使value已更新，继续点击保存仍提交原修订。关闭重开可以恢复，所以原评审“无法恢复”过强。

建议在冲突后提供“读取最新配置并重选”，保留本地选择和差异；不要直接把旧选择静默覆盖到最新修订。
补组件测试验证冲突、同步、再次提交，不只验证错误文本保留。

### R5 / P2：已接纳草稿的恢复比较遗漏本轮排除字段

`ThreadWorkAdapter.tsx:364–365`重建acceptedDraft.submission时没有复制excluded_session_skills；
`CapstoneAssistantThread.tsx:1189–1194`却将当前完整submission与其逐字段JSON比较。
带本轮排除的原请求在断线确认/恢复路径中会被判成不同草稿，不执行已接纳内容的清理，增加重复发送风险。
常规同步发送另有清理路径，不能由此推断所有发送都会重复。

建议复用统一submission投影，补“带排除的已接纳请求→断线恢复→原草稿只清理一次，后续编辑保留”的测试。
当前结论依据完整直接消费者的静态路径，尚未做该断线场景的实页复现。

| D7 永不生效的偏好 | 未证实，保留适用性设计问题 | 可选方法可能仅在某些指令使用，暂未使用不等于永不使用；需明确非原生会话的适用状态 |

| D10 无停用状态/配置修订 | 拆分 | 集合删除加事件历史可以表达停用；不是必须加enabled布尔。用户选择时的内容/目录身份缺口按R2处理 |

## 设计准备度

整体方向可保留，四层分离与不设固定流程是正确边界；以下合同应在对应包实施前明确：

1. **技能作用域**：可用、偏好、停用、本轮排除、显式选择的精确定义及优先级；选择时内容身份和加载时核对。
2. **IG2**：新会话可以读取的授权/连接投影、静态示例与真实能力提示的区别、只在空草稿填入的交互合同。
3. **IG3**：建议的类型化载体、同一模型响应内的产生方式、证据引用、三条上限的执行位置、范围修订键与失效规则。
4. **IG4**：哪份既有记录拥有调查状态，如何把指令关联到调查、另起问题、返回原调查，以及旧返回的版本隔离。

业务关系与是否继续调查仍由模型和用户判断；来源归属、引用版本、配置修订和失效状态应由代码执行。
不能为了实现连续性而固定业务工具顺序，也不能把模型判断全部改成关键词路由。
