## 跟踪规则

1. 每个研究实现切片开始前检查本地与远端 dev 差异、工作区状态及新提交；在允许的网络条件下获取远端引用。
2. dev 有新能力时，以普通 merge 合入研究分支，保留实验提交与合并来源；不重写共享历史。执行链、工具协议、持久状态发生变化时立即同步并运行受影响检查。
3. 主线尚未合入的修复作为显式依赖记录。确需提前验证时选择精确提交并记录来源，不能复制整个脏工作区或声称已跟上 dev。
4. 网关在每轮真实试验前记录实例身份、发布版本、工具契约修订及实际可用能力。代码能力、已部署能力和真实源可用性分别记录。
5. 必须读取未提交网关代码时记录具体文件摘要或补丁身份；仅记录仓库 HEAD 不足以复现实验。不得改变网关开发者的工作区。
6. 研究复用当前 Capstone 推理执行链，只实现实验所需增量。研究成果回流 dev 需单独审查；跟踪 dev 不意味着自动把实验反向合入。
7. 研究试验使用隔离运行配置和数据空间，不占用或改写三套既有 dev 服务。引用跨实例仍需授权和来源核验。
