## 1. 自研有界 JSON 解析与磁盘语义原型 — 优先评估移除

- 位置：`tools/experiments/op08_semantic/`，包括strings、numbers、object_index、document、document_store、verified_source、scratch七个模块；对应`tools/tests/test_op08_semantic_*.py`。
- 状态：已提交隔离原型（`1d5cc40`、`0b6696b`、`80e2ae3`、`c9c0708`、`f4a5712`、`ebd472e`）；目前冻结。此次搜索`packages/`未找到对`op08_semantic`的引用，尚未接入生产。
- 问题：为任意JSON、重复键、大标量及严格内存目标增加了独立解析/存储系统，偏离能力包接入目的。历史上确实发现并修复过索引扫描等缺陷；通过原型测试不等于领域语义等价或实际接入价值已证实。
- 后续方向：先确认无生产依赖，再考虑连同专项测试一起移出维护面；不因既有投入继续生产化。

## 2. 分段上下文日志和恢复机制 — 暂缓生产化

- 位置：`packages/capability-agent-kernel/src/capability_agent/application/context_segments.py`、`context_store.py`、相关导出与测试。
- 状态：读者切片已有提交`3bc24a2`；写入/恢复等后续实现仍是优化worktree中的未验收修改，包括额外generation/processes/writer_faults测试。默认仍为legacy；未纳入已接受的生产实现。另有未批准的kernel `uv.lock`，不得误暂存。
- 问题：大规模基准证明过写入放大，但尚不能据此证明当前能力包验证工作负载需要复杂事务/恢复机制。新增持久化分支、兼容与故障路径存在维护和潜在正确性风险；未完成整体验收，不能声称已无缺陷。
- 后续方向：保留和隔离现状，先评估真实使用需求；再决定保留简单实现、整体移除未启用分支或另期处理，不迁移用户数据。

## 3. 工件预览与下载的资源/协议机制 — 复核必要程度

- 位置：`packages/grid-agent/src/grid_agent/trajectory/api/artifacts.py`、`api/app.py`、Workbench `src/evidence/preview.ts`。
- 状态：前缀Range、快照流式下载等已提交`ab247eb`；128 KiB预览和256 MiB单次下载限制已实现。
- 风险：协议分支、临时文件生命周期和固定额度增加维护成本；256 MiB限制也可能限制合法验证工件。该限制不是总磁盘配额。完整摘要校验仍需线性I/O，不能宣传为整体请求恒定资源消耗。
- 后续方向：依据实际调试需求判断是否保留全部机制或采用更简单的展示/下载方式。路径约束和证据身份不能在简化时被无意删除。

## 4. 上下文投影、省略、状态比较与缓存版本 — 评估展示复杂度

- 位置：`trajectory/context_projection.py`、`projection_models.py`、`materialize.py`、`api/projection_pages.py`；Workbench `ContextView.tsx`、`AuditInspector.tsx`及类型/测试。
- 状态：本轮省略/未知状态/恢复、独立原因和缓存schema3.0尚未提交；具体最新状态以Git与执行账本为准。既有比较界面并非全部由本轮新增。

- 风险：展示层引入状态传播、可空字段、比较限制和缓存失效耦合；可能超出验证框架需要。后续应评估只保留必要轨迹/工件查看是否足够，避免把未加载状态伪装成空状态。
