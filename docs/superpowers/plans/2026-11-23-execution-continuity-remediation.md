# 执行连续性修复

依据 [执行连续性审查](../../reviews/2026-11-23-execution-continuity-audit.md)
逐项实施。单个输入、步骤或子任务的故障要保留可追查记录和已保存成果。
可安全执行的独立工作继续。原请求身份、授权、显式停止、预算和证据完整性保持有效。

| 执行范围 | 实施与验收 |
| --- | --- |
| 共用执行 | 隔离 worker 各维护操作。验证某操作异常后仍能领取工作，并运行其他维护操作。分别验证 Pi 接纳回执确认、结果未知和存储异常。完成原请求恢复前，确认原执行和副作用状态。 |
| Instruction | 对自动加入的材料及可独立保存的文件逐项处理。将不能在本轮接纳的追加保存在后续指令队列。验收不可用资料、队列容量、文件传输和已保存答复。 |
| Goal | 为规划暂态故障提供有界重试。复盘异常时保留已准入的后续工作。对确定性续接拒绝记录待恢复原因。验收预算、依赖、记录保存和刷新后的状态。 |
| Mission | 逐任务核对派发与交付，保持独立任务可运行。区分组织者等待、需恢复和整体交付。验收一个任务不可用、其他任务各自继续，并保留逐条件核验。 |
| 集成 | 运行各层定向回归，重建 local-dev 5174，核对 API 和 worker 镜像以及 Pi 运行依赖。用真实会话确认错误被记录，已准入的独立工作完成。 |

前置工作区包含多轮修复。部署回执需记录实际候选镜像、源码基线和验证范围。
本计划的每个条目以相应回归和真实验收结果结算。

## 当前实现

- Mission Task 以子会话为默认执行位置。需要在主会话多轮执行时，组织者可为
  Goal Task 选择 `placement: origin`。执行器等组织者释放原会话的执行位置，
  再按委托回执在同一会话中接纳独立 Work。该 Work 沿用 Goal 规划、复盘、
  续接和交付核验，对原组织者 Work 保留独立的执行归属。

- 共用执行：维护操作各自记录异常。原生接纳校验依赖缺失时返回明确的接纳前错误。
  恢复探针优先检查尚未检查的租约。未知状态每条 Attempt 发布一次，后续确认结果仍能更新。
  恢复交付逐项保留可读取文件。正式答复及必需证据未完成时保持未交付状态。
  Pi 恢复探针按任务标识、原 Attempt 和执行端身份检查持久接纳记录。接纳、运行、
  终态与未知分别投影。未知记录不触发重跑。
  新增租约结算路径。当前拥有者的租约已过期，且恢复探针已核对其原生终态时，
  可以释放会话并检查旧交付。原拥有者已续租、原生执行仍运行或状态未知时，保留原租约处理。
  未知状态提供独立会话入口，保留原会话执行和恢复记录。用户可带入未发送的文字
  草稿，在新会话提交指令。原请求及其资料仍属于原会话。
  Pi 升级后可在同一持久存储上按原任务、父 Attempt 和原执行器摘要只读核对。
  原接纳与终态分别返回。没有匹配记录时仍保留未知状态。
  Pi 已保存接纳但执行线程启动失败时，保存明确的未执行终态。启动门保证该
  任务没有调用执行端。Goal 在剩余预算内可据此重试一次。
  失联指令结算为失败时，继续只读查询原执行。如果取得迟到的完成回执，按原
  Attempt 保存答复和制品。只有同一 Work 修订仍有效时才恢复原 Goal 或 Mission 状态。
  对普通会话，原 Work 未变化且终态已核验时，回执结算与接纳下一条待发指令
  使用同一事务。用户已提交的新指令保持自己的执行顺序。
  迟到交付的扫描优先检查尚无检查记录的执行，再按最近检查时间轮转旧执行。
- Instruction：自动加入的会话材料逐项读取，缺项写入执行上下文。普通原生交付可
  保存成功的文件，并在回复中公开剩余保存缺口。普通原生会话的文字追加超过
  本轮执行端容量时进入后续队列。前一轮成功或确认失败后，宿主自动接纳尚未
  投递的下一条。用户停止、前一轮结果未知或输入投递状态未知时，保留相应记录。
  普通原生会话的附件追加以独立后继指令执行。接纳事务保存精确资源版本和摘要，
  排队期间保护该版本。后继接纳与原执行终态一起提交。
  显式选择的历史制品逐项读取，记录未接纳的选择位置。显式材料批次保留读取及
  完整性校验通过的材料。批次无任何可用项时返回资源不可用原因。
- Goal：规划暂态故障有限重试。中途复盘异常保留下一步，最终复盘失败保留原交付
  及重试入口。确定性续接拒绝保存原因和原待执行步骤，停止重复提交同一拒绝。
  理解指令阶段超时且 worker 确认业务执行未开始时，在剩余预算内自动重试当前
  步骤一次。原失败、步骤顺序及验收条件仍保留。
  已结算的失败步骤进入目标复盘，保存整体部分答复和逐项验收状态。复盘不可用时
  保留失败说明和已保存的制品，未核实的验收项标记为未知。
  Goal 计划可以声明对更早步骤的依赖。已结算步骤失败后，宿主记录不能执行的
  下游步骤，按原计划顺序继续依赖已满足的步骤。旧计划默认依赖前一步。
- Mission：任务接纳和交付核验逐项进行。全部不可接纳时保存原因并有界重查。
  组织者复盘失败时，已放行且依赖满足的独立 Task 仍可派发。规划时单个任务的
  资源准入问题保存在该任务上。被本轮规划排除的技能需要修订任务。已保存但
  待核验的交付不会被提前结算为部分完成。
  部分交付支持原 Mission 续作。恢复操作安排新的组织者复盘，保留已核验子任务、
  验收条件和部分交付记录。活动 Mission 的复盘不会被普通队列自动接纳抢占。
