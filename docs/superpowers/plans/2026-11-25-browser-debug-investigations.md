# 浏览器调查实施与验收

归属 capstone-agent 与 capstone-app，目标 dev。设计见 [调查契约](../specs/2026-11-25-browser-debug-investigations-design.md)。

1. 在 capstone_agent.debug_commands 定义用户输入语法。定向测试覆盖普通指令、粘贴代码、参数错误、多行目标、未知命令。解析只产生结构，不能授权或派发操作。
2. 在 host_api 的认证与工作空间检查后绑定现场认可的研发身份。复用 Thread 访问范围检查。开放访问、演示凭据、伪造请求体及跨工作空间均需真实 API 拒绝测试。
3. 在 Thread 服务的事务中持久化调查及轮次，并把启动、停止接入现有 Work 和 Attempt 生命周期。验证幂等键冲突、重启恢复、并发追加及结果未知。对内存与 PostgreSQL 实现使用相同契约测试。
4. 在 ThreadWorkAdapter 的原输入框提交调试请求，显示活动调查、目标与停止状态。验证普通输入、草稿、刷新和历史记录，复用现有制品与执行面板。
5. 在 Pi 技能配置中发布调查方法并按任务授权加载。网关工具由实际发布契约选择。data_gateway_mcp 负责关联已认证的回执。验证拒绝、空页、截断、未知诊断和版本差异。
6. 用项目规范入口重建，执行真实浏览器调查、停止和恢复，核对制品与现场引用。网关实际发布后验证双端版本和离线回放，登记受检源码、回执及仍未知的阶段。
