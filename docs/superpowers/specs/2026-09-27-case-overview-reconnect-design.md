# 案例概览与会话断开重连设计

## 目标

提高右栏的信息密度，让用户在不回到中栏查找的情况下理解当前案例；同时提供一个能脱离失败、卡住或过期会话的明确操作。

## 界面结构

右栏保留当前运行的状态、进度、已提交回答、证据引用、运行编号和证据边界。在这些内容之后增加“当前案例概览”区块，集中展示：

- 当前案例标题；
- 案例摘要；
- 电网模型或数据来源；
- 情景假设；
- 分析边界。

这些信息来自当前案例目录数据，不由前端重新编写。中栏移除重复的“电网模型 / 情景假设”事实表，只保留标题区与电网图之间必要的视觉分隔。

中栏不再重复显示当前案例标题。案例名称、摘要、模型、情景假设和步骤数量全部归入右栏概览；中栏移除 `REGISTERED ANALYSIS / 03 STEPS`、大号案例标题和右上角装饰图标，电网图直接接在顶图说明之后。

中栏分为三个同级区块：“电网模型”“推演过程”“分析报告”。电网模型区眉题为 `MODEL / OVERVIEW`，图卡内部标题为“拓扑图”，眉题为 `TOPOLOGY / VIEW`；副标题继续说明模型来源、母线和支路数量。这样外层表示当前案例使用的电网模型，卡片表示该模型的拓扑可视化，两个层级的含义明确区分。推演过程区使用 `ANALYSIS / PROCESS`，报告区使用 `ANALYSIS / REPORT`，去掉“本轮”这种内部运行措辞。

右栏提供“断开重连”操作。它属于当前运行控制，不放在案例选择区，也不与“重置案例”混用。

## 断开重连流程

1. 用户点击“断开重连”。按钮进入处理中状态，防止重复提交。
2. 若存在当前会话，调用会话断开接口；服务端将会话标记为 `interrupted`，释放 worker 租约，不生成报告。
3. 前端清除该案例的本地会话 ID、创建幂等键、自动执行键和已缓存的运行回答。
4. 前端为当前案例立即创建一个新的 provider 会话，并将其作为当前运行；界面回到“尚未开始 / 0 / 3”的工作台状态，案例选择与案例概览保留。
5. 断开接口和创建接口都使用幂等键。重复点击或网络重试不得创建多个新会话。

如果断开请求失败，前端保留当前运行信息，显示可读错误，并允许再次点击；不得静默清除本地会话记忆。

## 服务端边界

断开接口只接受已认证的当前会话，必须校验会话归属和幂等键。对已完成、已失败或已中断的会话重复断开视为成功，保证刷新后恢复失败会话也能重连。断开操作不删除历史运行的账本和证据，只释放其活动状态。

## 验证

- 前端测试覆盖概览字段渲染、重复信息不再出现在中栏、断开重连状态和错误恢复。
- API 测试覆盖断开接口的正常、重复、错误会话和幂等行为。
- 集成验证：创建会话、执行一条指令、断开重连、确认新会话为 `0 / 3`，旧会话为 `interrupted`。
- 运行前端定向测试、capstone-agent 定向测试、`git diff --check` 和构建验证。
