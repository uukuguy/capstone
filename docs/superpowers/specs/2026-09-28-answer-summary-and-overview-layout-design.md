# 回答摘要与案例概览布局设计

## 目标

让推演过程卡片显示一段与正式回答一致的语义摘要，同时把右栏案例概览中的长短字段排版清楚。完整正式回答继续用于运行记录、报告和 CLI 输出。

## 回答双字段契约

每次工具调用完成后，模型在同一次最终响应中返回两个字段：

```json
{
  "answer": "完整正式回答",
  "summary": "正式回答的 1–2 句过程摘要"
}
```

`answer` 保持当前 `answer_output` 的含义和公共 CLI 契约。`summary` 只用于网页推演卡和脚本过程日志，不进入正式报告正文。摘要必须压缩正式回答，不得添加正式回答没有的数值、结论、证据或状态；使用简体中文，目标长度约 80–140 字，并允许保留 AC/DC、Line 等规范技术名称。

Capstone/Kernel 在统一响应解析处拆分和校验两个字段。摘要随已提交步骤写入运行事件和答案记录，刷新页面后可以恢复。旧运行或模型未按新格式返回时，正式回答继续提交，摘要回退到现有规则摘要并记录摘要格式诊断；不得因摘要格式问题阻断主分析。

报告生成只读取正式回答，保持现有证据绑定、Markdown 和完整内容。CLI 标准输出仍只包含 `question_id` 和 `answer_output`。

## 案例概览字段布局

右栏案例概览使用统一的字段组件：

- 短值（例如“电网模型”“分析步骤”）使用 key/value 同行两列；
- 长值（例如“情景假设”“结果边界”）使用 key 一行、value 下一行；
- 长短由字段内容自动判断，案例目录不需要为每个案例写专用样式；
- 每个字段都有底部分隔线，包括最后一个字段；
- key 与 value 保持相同基础字号，key 通过强调色、半粗体和字距区分，避免缩小后显得像辅助说明；
- value 保持正常正文样式并允许自然换行。

## 验证

- 单元测试覆盖双字段解析、非法或旧格式回退、摘要持久化和刷新恢复；
- 前端测试覆盖摘要优先展示、完整报告不受影响，以及短值/长值概览布局；
- 使用一个 pandapower 和一个 PyPSA 真实 LLM 案例确认过程摘要与报告正式回答一致；
- 运行前端定向测试、相关 Python 测试、构建和 `git diff --check`。
