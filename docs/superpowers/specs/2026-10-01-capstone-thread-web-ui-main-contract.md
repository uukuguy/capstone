# Capstone Thread Web UI 主合同

**状态：** Approved primary contract

**适用范围：** Capstone Web Thread 的右侧对话区、状态反馈、Composer、助手回答和工具活动展示。

**生效日期：** 2026-10-01

**上位约束：** 本合同只规定 Web presentation 和交互方式，不改变
capstone-thread/1、ThreadSnapshot、EventPage、CommandEnvelope、Capstone Harness、
Domain Pack、Authority 或当前运行证据准入契约。旧的 Thread/TUI/CLI 状态语义继续以
既有设计合同为准；本合同覆盖 Web 对话表面的视觉和交互细节。

## 1. 产品判断

当前 Thread 已具备真实发送、Harness 执行、工具事件、最终回答和 IEEE-39 模型联动能力，
但界面仍处于调试投影阶段。截图暴露出以下必须修正的问题：

1. 字体整体过大，标题、用户气泡和助手正文同时抢占空间，核心回答密度过低。
2. 原始 Markdown（##、表格分隔线）直接展示，回答不可读。
3. 空闲提示、accepted 回执、Harness 标识、工具完成列表形成重复状态层。
4. 工具活动只显示 tool completed，无法判断执行了什么能力、属于哪个阶段。
5. 消息容器边框和留白过重，像调试面板，不像成熟对话产品。
6. Composer 是普通表单，尚未形成固定底部、可持续追问的 AI 对话输入区。

因此，下一阶段不是继续堆叠状态卡，而是以 assistant-ui 的成熟 Thread 骨架为基础，
重做信息层级、字体密度、Markdown 内容层和运行反馈。

## 1.1 主流对话界面从哪里继承

本项目不另起一套聊天框视觉语言。对话区默认沿用 assistant-ui 官方 GPT、Perplexity、Grok、
Claude 和 Gemini 示例已经验证的主流模式；Capstone 只增加领域所需的模型上下文、工具活动、
结果卡片和证据入口。官方示例明确展示了以下模式：

- GPT：居中空状态、固定底部 Composer、用户消息操作栏、助手 Copy/反馈/重新生成操作栏。
- Perplexity：紧凑阅读宽度、模式/模型选择器、粘性 follow-up Composer。
- Grok：pill Composer、附件入口、模型下拉、输入为空/有文本/运行中时动态切换尾部动作、
  消息计时提示和 hover 操作栏。
- Claude：无头像、轻量用户气泡、扁平 Composer、hover/focus 才出现的小图标操作栏。
- Gemini：头像-free 助手 Markdown、右侧灰色用户气泡、单行 Composer 和 disabled/ready/stop
  三态发送按钮。

因此，以下做法被禁止：为 Capstone 自创一套厚重的消息卡、永久显示大头像、把每个工具事件做成
独立大卡片、用大块页签代替 Composer 内的模式选择、用文字按钮代替精致图标操作。

## 2. 不可违反的架构边界

- CapstoneThreadClient、ThreadProjectionStore 和 typed public events 是状态真相。
- @assistant-ui/react 只负责对话交互骨架、Composer 状态和消息渲染生命周期。
- 前端不得从助手 prose 推导模型、拓扑、结果数值或证据状态。
- 工具活动必须来自 Harness public projection；不得直接透传 Pi/DSH 原生事件。
- 结果卡片和证据引用必须来自当前 Run 的 admitted projection。
- Markdown renderer 只渲染受控文本，不开放任意 HTML。
- UI 视觉变化不得创建、修改或隐式重试 Thread、Turn、Attempt。

## 3. 目标界面结构

保留当前 App 标题栏、左侧电网模型区和右侧对话区。右侧采用四个层级：

    Thread 标题栏
      当前模型 / Run 状态 / 连接状态
    消息滚动区
      用户消息
      助手回答（Markdown）
      当前运行结果摘要（有结果引用时显示；证据默认从操作栏展开）
      工具活动摘要（附在所属助手回答下，默认折叠）
      回答操作栏
    Composer（固定底部）
      模式选择 · 多行输入 · 发送/停止

### 3.1 右栏标题栏

- 第一行只显示 Thread 标题、当前模型短名称、连接状态和 Run 状态。
- run_id、ModelContext ID、revision 等详细信息进入诊断抽屉或复制详情，不在主标题中展开。
- 空闲只作为紧凑状态徽标，不再使用大面积说明卡。
- command receipt 保留在事件与审计投影中；普通对话流不展示 `automatic · accepted` 这类没有决策价值的协议状态。
- 标题栏高度目标为 48–56 CSS px。

### 3.2 消息滚动区

- 消息区独立滚动，Composer 固定在右栏底部。
- 初始空 Thread 使用居中欢迎语和 Composer；有第一条用户消息后立即切换为普通消息流。
- 不使用每条消息一个大白色面板的嵌套卡片结构。
- 助手消息最大阅读宽度为右栏的 86%，用户消息最大宽度为 72%。
- 长回答不得把 Composer 推出浏览器底部。

### 3.3 工具活动

默认显示一行摘要：

    已完成 6 个步骤 · 查看运行过程

展开后显示：

    ✓ 读取当前电网模型       pandapower-static-analysis
    ✓ 获取模型约束           model.constraints.describe
    ✓ 校验证据引用           current-run admission

每一步最多展示：人类可读名称、状态、来源 Pack/能力、耗时和结果/证据入口。Attempt 运行中必须即时显示已运行时长，并随运行持续更新；Attempt 结束后保留最终运行时长。
活动摘要必须挂在产生它的助手回答下面，不能作为整个 Thread 的全局尾栏；这样多轮对话中每个专业指令都能独立展开和排错。默认只显示当前 Attempt 的最后摘要；历史工具事件通过该回答展开查看。

## 4. 字体、密度和可读性硬规范

截图中的字体巨大是本合同的明确缺陷，必须单独验收。以下尺寸均以浏览器 100% 缩放、
CSS px 为基准：

| 元素 | 目标字号 | 行高 | 备注 |
| --- | ---: | ---: | --- |
| 页面品牌/全局标题 | 16–20px | 1.2 | 不进入消息区 |
| THREAD / RUN 标签 | 10–11px | 1.2 | 等宽、字距有限 |
| 对话标题 | 18–22px | 1.25 | 禁止使用 30px 以上 |
| 用户消息 | 11px | 1.5–1.6 | 侧栏中文正文 |
| 助手正文 | 11px | 1.5–1.6 | 主要阅读内容，优先保证长回答密度 |
| 表格正文 | 10–11px | 1.4–1.5 | 允许横向滚动 |
| 工具活动 | 11–12px | 1.45 | 默认折叠 |
| receipt / metadata | 10–11px | 1.35 | 不承担正文阅读 |
| Composer 输入 | 12px | 1.45–1.55 | 多行输入，保留原生拖拽调整高度 |
| 辅助提示 | 11–12px | 1.45 | 不得低于 11px |

硬性规则：

- 普通正文不得超过 11px（受控标题除外）；助手回答不得使用 display/hero 字号。
- 对话标题不得超过 22px；右栏标题与空状态标题不得同时使用大字号。
- 同一视觉层级只允许一个主标题，不得同时显示“智能体对话”和大面积空闲标题。
- 主要消息间距 12–16px，卡片内边距 12–16px；禁止 28px 以上的默认消息留白。
- 字体权重以 400/500 为主，700 只用于标题、状态和按钮。
- 颜色必须满足正文对比度，不能用浅灰色承担主要信息。

## 5. 消息视觉合同

### 用户消息

- 右对齐，单一浅蓝/青灰气泡，圆角 16–20px。
- 不显示大头像；可保留 24px 内的轻量身份标记。
- 路由方式不在默认消息流中显示；必要时只在诊断或 Attempt 元数据中保留。
- 支持复制和编辑入口，但默认只在 hover/focus 时出现，不额外撑高气泡。

### 助手消息

- 左对齐，使用小型 Capstone 标识或状态点，不使用大头像。
- 正文采用 Markdown/GFM 渲染：标题、列表、表格、代码、引用、链接必须有明确层级。
- 助手正文使用无重边框的阅读面，必要时只保留左侧状态线或极浅背景。
- 回答底部提供固定槽位：复制、重新执行、查看分析详情、证据、运行过程、更多。
- 固定槽位不得因单条回答缺少引用而改变位置；暂不可用的操作保留禁用图标、明确
  `aria-label` 和原因提示，例如“暂无证据”“证据同步中”或“分析详情模块尚未启用”。
- 回答没有文本但 Attempt 尚未终止时，显示“正在生成回答…”和活动指示。
- Attempt 失败、取消、中断时必须显示对应终态和下一步动作；不得继续显示生成中。

### Markdown 和领域内容

- 首先实现安全的 Markdown/GFM renderer。
- 表格、代码块和长引用必须有独立视觉层级；证据标识默认不塞进回答正文，点击“查看证据”后才展开当前 Run 的证据引用与模型上下文调试信息。
- 电网结果使用受控 ResultCard：指标、单位、模型 revision 和结果来源分开显示；EvidenceCard 只作为操作栏打开的证据面板，避免回答正文重复展示长证据标识。
- 拓扑定位、结果表、证据回放通过显式操作联动左栏，不将大型图形塞进消息气泡。

## 5.1 消息气泡下的精致操作栏

每条消息的操作栏是必要的产品细节，不是后续可有可无的装饰：

- 用户消息：编辑、复制。
- 助手消息固定顺序：复制、电网图、分析结果、证据、运行过程、重试、更多。当前回答没有对应内容时保留常用图标并禁用；赞成/反对暂放入“更多”并禁用。
- 桌面默认隐藏，hover 或键盘 focus 时淡入；助手操作使用已有的运行时间行，不另占一行空白，用户消息操作不额外撑高气泡。显示切换不能改变消息布局高度。触屏常驻显示并保留44px点击区域。
- 使用统一 SVG 图标和 tooltip，禁止使用 emoji、文字堆叠或没有含义的圆点。
- 开关型操作使用 `aria-expanded`/`aria-pressed` 表达状态：开启为淡青底色和更深图标色，关闭为普通样式；不增加边框、徽章、文字或图标尺寸，禁用态不使用开启样式。
- 图标按钮视觉尺寸 28–32px，点击区域至少 36px；每个按钮必须有 aria-label。
- 窄桌面中，悬停/聚焦时用工具条替代同一行耗时文字，离开后恢复耗时；不增加消息高度。
- 复制后显示短暂的 Copied 状态；已完成回答可重试原指令并创建新的 Turn/Attempt，失败回答继续创建原 Turn 的重试 Attempt；不得修改旧回答。运行中或连接不可用时禁用重试。
- 证据状态必须区分 `available`、`not_applicable`、`missing`、`pending` 和 `unavailable`，
  不能把没有证据和投影错误都处理成按钮消失。反馈评价暂放入“更多”并保持禁用，待反馈模块具备
  对话、上下文和引用持久化后再提升到固定栏。
- 运行时间必须在运行中的 Attempt 下即时显示并持续更新；完成、失败、取消和中断后保留最终运行时长。首 token 时间和 token/s 可以通过 tooltip 或详情显示，默认不占用消息正文空间。

## 5.2 Composer 的主流交互细节

Composer 采用 GPT/Perplexity/Grok/Gemini 的共同模式，而不是当前的大矩形表单：

- 使用圆角 pill 或 16–24px 圆角容器、细边框或 ring，避免厚重阴影和大面积白色面板。
- 输入区是主体，按钮围绕输入区底部对齐；输入内容增加时 Composer 可增高但有最大高度。
- 左侧保留一个可扩展的加号/附件入口；当前阶段没有附件能力时可以隐藏，但不改变整体布局模式。
- 当前阶段使用单一自动路由输入；未来的模型、Domain Pack 或操作选项放入紧凑菜单/工具栏，不使用两个大块模式页签。
- 右侧主动作是图标优先：空输入为 disabled、可发送为 send、运行中为 stop；状态转换要有轻量动画。
- `data-empty` 和 `data-running` 这类状态驱动视觉切换，不能由多个互相冲突的 React 布尔值拼接。
- 默认不显示快捷键说明；输入框保留可拖拽调整高度，细节控制不挤占消息区。
- Composer 必须在空状态和已有消息状态复用同一组件，只改变位置和宽度。

### 5.3 历史回答整理与单条折叠

2026-10-07 用户批准：取消全局阅读模式，区分历史整理动作与新回答显示。
目标是让大量历史回答便于查找，不设置持续生效的自动、完整或紧凑模式。

- 新回答默认完整显示，不继承历史整理动作。生成中、失败、取消和中断消息保持完整显示。
- 已完成的长回答提供双向操作；同一个轻量按钮在“收起／展开”间切换，固定宽度和位置，不分成顶部收起、底部展开入口。长回答阅读时按钮在消息区顶部轻量吸附，且只属于当前回答。短回答保持原样。
- 折叠条目不使用背景色；用细状态线与展开图标区别于完整回答。按钮只显示“展开”，不重复显示“已折叠”。
- 折叠只裁切正式回答的显示高度，保留开头约三行供定位；不是摘要或重点结论。
  不依赖 `answer_summary`，不新增服务端投影或 Provider 请求。隐藏区域的链接不能获得键盘焦点。
- 历史整理并入 Composer 底部的“设置”，包含“折叠历史回答”和“展开历史回答”，不单独占用工具栏入口。
  这是一次性批量操作，只作用于点击时当前 Thread 已加载的已完成回答，包括消息窗口外
  已加载的回答；未加载的历史、新回答及操作时仍在生成的回答不继承它。
- 批量操作后，每条回答仍可独立展开或折叠；再次批量操作明确覆盖当前已加载回答。
- 折叠状态按消息标识保存在当前 Thread 的客户端视图内，跨事件更新和窗口翻页保留。
  切换 Thread 或刷新后默认完整显示；不保存未来回答的显示偏好，也不读取旧阅读模式设置。
- **2026-10-08 用户修正：完整指令可见。** 单条切换保留同一个按钮与键盘焦点；收起和展开后，对应用户指令应完整可见。指令已在视口内时保持位置；否则只滚动到能完整显示指令的位置。指令已加载但位于消息窗口外时，调整窗口将其显示；未加载时不定位到无关指令。指令自身高于视口时显示其起始位置。
  布局高度缩短后在滚动范围允许时补偿滚动，使按钮仍处于点击前的位置；受滚动边界限制时至少保留按钮焦点与当前回答，不定位到无关消息。
  末条回答收起导致滚动范围不足时，补出保持按钮位置所需的底部阅读空间；下一次切换、批量整理或切换 Thread 时重新计算或清除，不保留原长回答的整段高度。
- 批量切换以当前可见的用户指令为阅读锚点，保持其屏幕坐标；连续折叠／展开或重复同一动作复用这个锚点。用户滚动后重新选择，不追随前一条长回答的起点。只有长回答中段可见、对应指令在视口外时，被折叠的正文无法作为锚点：先显示该回答自己的指令，再保持其位置；指令已加载但在窗口外时将其显示，未加载时不选择无关指令。菜单关闭后键盘焦点返回设置入口。操作保留 Composer 草稿，不创建命令、Turn 或 Attempt。
- 正式回答、结果、证据及失败恢复入口不变；复制始终复制完整正式回答。

### 5.4 对话设置的用途

- 历史整理提供“折叠历史回答”和“展开历史回答”两项即时操作，仅处理已加载回答，新回答仍完整显示。
  小组件保持紧凑，不堆叠多级展开、长说明和重复提交操作。
- 历史整理只显示“折叠历史回答／展开历史回答”两个操作，删除重复的“历史回答”标题及范围说明行。动作语义仍只处理已加载回答，不影响新回答。
- 所有已注册的工具组在设置中直接可见，缺省全部启用。启用／禁用是全局工具偏好，不按当前模型隐藏或禁用 PyPSA 等工具组，不在开关旁显示“需某种模型”。
  移除“高级”和“专业功能配置”套叠层级，工具组采用无卡片边框的勾选行。
  选择改变后才显示小型“保存”动作；关闭菜单丢弃未保存的选择。保存只修改全局偏好，不提交模型变更或重设当前模型。
  当前偏好由 App 持有，覆盖本次打开 App 的所有对话及模型；切换对话或模型不恢复默认选择。刷新后缺省全部启用。以后工具增多时支持配置持久化和重载：按稳定工具组身份保存覆盖项，启动时加载并支持重新加载；没有覆盖项的新工具遵循缺省启用。本轮不实现账户配置、跨设备同步或导入／导出。
- 自动路由为固定行为，不作为设置项展示。运行过程由各条回答下的入口打开，不提供重复的全局开关。
- 用户入口统一称“电网计算分析工具”，不使用“应用”“Profile”或泛化的“专业功能配置”。用户可分别启用或禁用工具组；内部 Profile 的选择粒度不是逐个工具开关。
  在 Capstone 电网语境中，ApplicationProfile 对用户代表一套电网计算分析工具。规模较大或业务跨度较广的工具体系按业务职责拆分为多个 Domain Pack，由同一 ApplicationProfile 组合；较小的工具体系可以只绑定一个 Domain Pack。
  Domain Pack 是实现与语义所有权边界，不要求用户逐个配置。工具体系的用户名称说明可执行的计算分析用途，不沿用“Business Cases”等内部测试或装配名称。
- 工具组显示明确的业务名称。兼容性属于执行约束，不是全局开关状态。每次任务从注册目录取“全局已启用且兼容目标模型”的精确 Profile 版本，后端再次校验；模型切换后的任务也使用该子集，不恢复已关闭的工具。
  对话消息命令可在 payload 中携带 `enabled_profiles`；后端在同一事务中校验并绑定到当前或待激活模型，写入选择／模型激活事件，再创建 Attempt。旧客户端不带此字段时保留原有选择语义。
  切换工具可用范围不删除或改变已打开的电网模型、历史回答及证据；已开始的 Attempt 使用其已绑定的选择，后续任务使用新设置。
  全部兼容工具组禁用后，应进入“未启用计算分析工具”状态；依赖这些工具的计算分析不可执行，不能偷偷恢复工具或伪装成计算成功。
  当前实现允许空选择，但创建专业 Pi 会话要求非空的已准备 Domain Pack；失败可能回滚选择。这是未完成的运行时处理，尚未验证为可用的全禁用状态。
  当前 Web 允许保存全局全关闭偏好。有效兼容子集为空时，在任务提交前显示启用工具提示并保留输入，不创建失败的 Attempt，也不偷偷恢复工具。当前运行时尚不支持零工具的普通对话或模型切换，因此这些操作也会受此限制；不能称零工具运行时已完成。
  零工具时的普通对话、模型浏览与切换需要明确实现并分别验收，不能仅依据选择 API 接受空列表就声称可用。
- 模型基础访问与可选计算分析工具分别管理：禁用计算分析工具后，目标仍是允许打开／切换模型，并通过注册权威的受限投影向智能体提供模型身份和可获准读取的基本信息。
  模型名称或已缓存拓扑不能替代实际结构读取。修改模型仍须有已注册、获准执行的模型操作能力；不因计算工具关闭而绕过能力合同。
  当前拓扑投影仍依赖选中 Profile 准备出的模型绑定。模型切换后的 Web 任务现在按全局偏好覆盖目标默认选择，但零分析工具下的完整模型访问尚未独立实现；不能宣称现有代码已经支持。
- 模型基础访问与工具启用分别管理，不表示任意工具兼容任意模型。当前注册的 pandapower 工具组只声明 pandapower 模型兼容，PyPSA 工具组只声明 PyPSA 模型兼容；后端拒绝不兼容的选择。
  若要用两套引擎分析同一实际电网，需要明确的已注册模型转换或适配、目标模型及其修订和证据来源，不能仅靠启用另一个工具组实现。当前未提供 pandapower 到 PyPSA 的转换联动。
- **2026-10-07 用户决定：高级能力延期。** “建立完整统一电网模型体系，使同一电网可由不同计算工具操作”属于高级能力，现在不实施。评估对象是完整模型体系，不缩减为两工具互转；该能力不作为当前对话或工具选择改进的前置条件。手动启用／禁用工具组继续保留，当前执行仍遵守已实现的模型兼容关系。
- 菜单支持键盘、Escape 与外部点击关闭。历史整理在断线或业务只读时仍可使用；后端注册、选择合同和运行上下文保持原有语义。

## 6. Composer 合同

采用 assistant-ui 示例中的 sticky footer 和多状态 primary action 模式：

- 空闲且有文本：显示发送。
- Attempt 运行中：显示停止；普通业务发送禁用。
- Attempt 运行中仍保留草稿，不清空用户输入。
- 无文本且空闲：显示普通的空状态操作，不显示无意义的 disabled 发送按钮。
- Composer 默认提交自动路由指令；专业能力由分类、硬门控和 Harness 决定，不要求用户先选择模式。
- 多行输入默认 2–4 行，随内容扩展但不能把消息区挤出视口。
- Enter 发送，Shift+Enter 换行；不在 Composer 中显示快捷键提示。
- 发送后必须立即出现用户消息和 accepted receipt；等待 Harness 时显示运行状态。

## 7. 状态层级

主界面只保留一个主要运行状态，其他状态降级到对应位置：

| 状态 | 主界面显示 | 详细信息位置 |
| --- | --- | --- |
| idle | 标题栏徽标 | 无需大卡片 |
| accepted | 已接受的用户消息；普通提交不重复提示 | 诊断抽屉 |
| running | Attempt 活动摘要 + 动态运行时长 + 停止 | 展开工具步骤 |
| completed | 助手回答 + 最终运行时长 + 操作栏 | 结果/证据抽屉 |
| failed | 对应回答内的系统提示 + 重试动作 | 错误详情 |
| cancelled/interrupted | 对应回答内的终态提示 + 新 Attempt 动作 | Attempt 详情 |
| reconnecting/resync | 消息区恢复提示 + 轻量连接徽标，冻结发送 | 提示内重新连接／同步动作 |

禁止同时显示多个内容相同的状态卡。状态必须说明“现在能做什么”。

- 指令拒绝、提交结果未确认和模型／工具选择结果进入消息区，以轻量“系统提示”区分于用户指令及智能体回答。
- 系统提示使用中性灰的小标签、图标和细横向分隔线，略微内缩；正文 10px、标签 9px，使用浅淡的中性灰背景。不使用回答的左侧状态线或绿色背景。错误只在图标／文字及小标签上使用温和的警示色，保持恢复动作可见。
  拒绝的指令保留在输入框；提示可标出相关指令，不伪造已接受的用户消息。
- Attempt 终态说明只显示一次，保留已有的部分回答、重试及诊断入口，不再在顶部重复错误。
- 连接中断和恢复更新同一条提示，不按每次重试追加。提交回执丢失已有恢复提示时，不再重复连接错误和恢复按钮。
- 提示出现或更新不得抢走历史阅读位置及键盘焦点。定位电网元素等局部界面反馈留在模型操作附近，不写入对话历史。
- 系统提示是客户端展示投影，不进入模型提示、指令、正式答案或证据。模型／工具启用结果由既有公开事件重放。
  本地异常提示在当前挂载的 Thread 工作区最多保留 100 条，不承诺刷新、跨设备持久化；旧历史页不混入之后发生的本地结果。
- 工作区尚未载入、没有消息区时，保留初始加载错误界面及重试入口。

指令拒绝、Attempt 失败和电网投影不可用必须说明原因、恢复操作及安全诊断代码，
不得向用户暴露原始异常、凭据或内部路径。目录应在打开前禁用不能提供完整拓扑的
模型，并显示限制原因；服务端执行同样的可用性检查。不能把完整视图静默截成预览。

## 8. assistant-ui 组件映射

保持 CapstoneAssistantThread 作为 Capstone 适配层，逐步替换其内部表面：

- ThreadPrimitive.Root：右栏整体运行边界。
- ThreadPrimitive.Viewport：消息独立滚动区。
- ThreadPrimitive.ViewportFooter：固定 Composer 和底部辅助信息。
- MessagePrimitive.Root：用户/助手消息布局。
- MessagePrimitive.Parts：受控 Markdown Text renderer。
- ActionBarPrimitive：复制、重新运行、证据、工具过程等回答动作。
- ComposerPrimitive.Root/Input/Send/Cancel：输入和运行中主动作。
- AuiIf 或等价状态条件：实现互斥的发送/停止/空状态动作。

assistant-ui 的 ChatGPT/Perplexity 示例作为结构参考；Capstone 的颜色、模型上下文、
工具 provenance、证据和电网联动保持自有设计。

## 9. 实施顺序和验收门

### Phase A — 结构和密度

- 重排右栏标题、消息区、活动摘要和 sticky Composer。
- 删除大面积空闲说明卡和重复 accepted 行。
- 按本合同字号表收敛字体、内边距、消息宽度和行高。
- 验收：100% 浏览器缩放下，首屏能看到标题、至少一条完整消息和 Composer；没有垂直裁切。

### Phase B — 内容可读性

- 接入受控 Markdown/GFM renderer。
- 增加标题、列表、表格、代码块和证据引用样式。
- 验收：IEEE-39 模型说明和潮流分析结果不再显示原始 Markdown 符号。

### Phase C — 运行反馈

- 聚合 tool events 为 Attempt activity summary/stepper。
- 完成 running、completed、failed、cancelled、interrupted、reconnecting 状态。
- 运行中的 Attempt 显示动态运行时长，终态回答保留最终运行时长。
- 验收：用户能从界面判断当前阶段、来源能力、运行耗时和下一步操作。

### Phase D — 回答操作和领域卡片

- 加入复制、重新运行、证据、工具过程、拓扑定位。
- 加入受控 ResultCard、EvidenceCard 和模型/revision 标签。
- 验收：所有动作都通过已有 CommandEnvelope 或 typed projection，不能绕过 Harness。

### Phase E — 视觉验收

- 使用真实新 Thread 验收：普通问答、专业分析、长回答、工具运行、失败、取消、重试、重连。
- 测试 1200px 桌面、900px 紧凑桌面和 600px 以下单面板模式。
- 检查键盘焦点、屏幕阅读器标签、动画降级和正文对比度。
- 必须提供浏览器截图作为视觉验收证据，不以单元测试代替。

## 10. 明确不做

- 不把现有三栏 Case App 一次性重写。
- 不复制 assistant-ui 示例的品牌、产品名称、营销文案或配色；但对话布局、Composer、消息气泡、
  hover/focus 操作栏、图标按钮和状态切换必须优先沿用这些示例的成熟模式，不得另起一套。
- 不在本阶段引入任意 Generative UI；先完成受控 Markdown、工具摘要和 ResultCard。
- 不把模型隐藏思维链直接展示给用户；可展示受控阶段摘要和工具活动。
- 不为逐工具增加独立开关；能力选择仍以 Domain Pack/Profile 层级为边界。

## 11. 完成定义

本主合同只有同时满足以下条件才可声称 Web 对话 UI 完成：

1. 字体和密度通过第 4 节硬规范，截图中不再出现当前的巨大标题和巨大正文。
2. 真实助手回答以可读 Markdown/GFM 呈现。
3. 工具过程从原始事件变成可理解、可折叠、带来源的活动摘要，并附在对应助手回答下。
4. 运行中的工具过程即时可见并显示动态运行时长；完成回答保留最终运行时长。
5. Composer 固定在对话区底部，发送、停止、重试和草稿行为正确。
6. 普通问答和专业电网分析都显示正确的模型、Run、Attempt 和证据边界。
7. 视觉回归截图和 focused tests、TypeScript/build、package boundary checks 全部通过。
