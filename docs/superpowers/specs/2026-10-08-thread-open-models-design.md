# 会话中的已打开电网模型与当前模型

日期：2026-10-08。状态：设计草案，待用户审阅；尚未实施或验收。
所属交付包：CONV-06，见[对话完成清单](../plans/2026-10-07-capstone-conversation-completion.md)。

## 1. 用户明确的要求

- 新会话默认打开 IEEE-39，始终至少保留一个已打开模型。
- 会话可以打开多个电网模型，其中恰好一个是当前模型。
- 输入框小工具条显示当前模型，提供已打开模型列表、切换和关闭操作。
- 后续任务使用当前模型；不能把会话永久绑定在最初的一个模型上。
- 模型基础访问与全局计算分析工具开关分开。不同引擎的注册模型可以共存。
- 完整统一模型体系与跨引擎模型转换仍延期，本方案不改变该决定。

关闭当前模型时的替代选择尚未收到用户答复。本文建议自动选择最近使用的其他已打开模型。

## 2. 已核实的缺口

当前行为不满足上述要求：

- `ThreadLiveEntry.tsx` 的新会话确实以 `ieee39` 创建。
- `ThreadModelDirectory.tsx` 展示注册目录，不是会话的已打开集合。
- `ThreadSnapshot` 只有 `active_model_context`，没有持久的已打开模型集合。
- `thread_service.py` 的切换从目录重新解析模型；在下一条消息入场时创建新 Context。
- Web 模型选择目前还会发送一条对话指令来触发激活，打开／切换未成为独立完成的应用操作。
- 客户端历史电网页面只是只读展示缓存；查看旧页不会改变后端当前模型。
- `parseThreadModelCommand` 要求中文动词后有空格。离线复现中，
  `切换至已打开的 IEEE-39 电网模型` 返回 `null`，从而进入仍绑定 case57 的分析路径。
  单独修正空格规则也不会补齐集合、关闭和已有模型身份。

以上是源码核对和解析器复现结果。没有为此次诊断调用 Provider 或修改用户会话。

## 3. 方案选择

| 方案 | 作用与限制 |
| --- | --- |
| 持久的会话模型集合与当前指针（推荐） | 支持明确的打开、切换、关闭和刷新恢复；需要补齐应用合同与存储。 |
| 把历史电网页面当作已打开模型 | 改动较少，但关闭状态、历史截断和只读结果页不能表达真实模型生命周期。 |
| 仅改模型目录与中文解析器 | 能处理部分指令，仍无法保证多个已打开模型和切回后的精确身份。 |

选择第一种。以下为可实施的推荐设计，不作为已验证行为。

## 4. 三种身份各有职责

**已打开模型条目**属于 Application 的会话状态。条目具有稳定 ID，保存注册模型 ID、
Authority 的类型化引用、精确 revision、引擎家族、显示名称及最近激活顺序。
客户端只接收允许公开的有界字段，不接收 Authority 原始对象。

**当前模型**是集合中的一个条目。集合非空，当前指针必须有效，打开与关闭都不能留下中间空状态。
同一注册模型及精确 revision 已打开时，再次打开它会选中已有条目，不制造副本。

**Model Context**仍是执行隔离边界。切换到已有条目使用它保存的精确模型引用，创建新的执行 Context，
符合[主线基线 §3.2](2026-10-01-capstone-mainline-rebaseline-design.md#32-统一模型目录)。
“新的执行上下文”不能被实现为“重新载入该模型的目录默认版本”。
每个 Attempt 在入场时固定 Context，运行中不改变；历史答案、结果和证据仍属于原 Attempt。

Authority 将来若通过已发布合同产生模型新 revision，只能在明确的成功提交点更新对应条目引用。
本包不新增模型编辑或存储语义，不能宣称未实现的修改保存能力。

## 5. 小工具条与菜单

复用现有“模型”入口，按钮改为当前模型名称，例如 `IEEE-39 ▾`。不再增加第二个重复入口。

- 弹层先显示已打开模型；当前行有轻量勾选标记。
- 选择另一行直接切换，成功后更新按钮名称及当前电网页面。
- 每行右侧有关闭图标和悬停／无障碍提示，图标点击不能冒泡触发行选择。
- 底部只有“打开其他模型…”入口，进入现有注册目录搜索；选定后加入集合并成为当前模型。
- 已打开集合保持稳定的打开顺序，不因切换而重排；最近使用顺序仅用于关闭当前模型后的替代选择。
- 短菜单只显示模型名称、必要的家族辨识和当前／关闭状态，不堆叠 Profile、revision、说明段落。
- 打开、切换、关闭保留输入草稿和消息阅读位置；完成后焦点返回模型入口。
  键盘 Escape／点击外部关闭弹层；手机操作目标至少 44px。
- 操作成功显示消息区的小字号浅背景系统提示；失败给出短原因，保留原状态和草稿。
  不生成伪用户消息、智能体回答或额外运行步骤。

浏览历史页仍是只读行为。当前按钮始终表示后端当前模型；显式选择当前模型可返回当前电网页面，
不会再次创建执行 Context。“查看历史模型”和“设为当前模型”必须有独立的操作含义。

## 6. 操作规则

| 操作 | 提交后的行为 |
| --- | --- |
| 创建新会话 | 原子建立 IEEE-39 条目及当前 Context；准备失败则新会话创建失败，不生成空模型会话。 |
| 打开其他注册模型 | 解析精确注册引用，验证可访问性；成功后加入集合并激活。失败保留原集合、Context 和图形。 |
| 切换已有条目 | 按条目 ID 选择其保存的模型引用，完成激活后下一条任务才可入场；不从目录隐式解析 latest。 |
| 再次选择当前条目 | 无状态变更，不创建 Context、Attempt 或重复成功提示；必要时仅返回当前电网页面。 |
| 关闭非当前条目 | 从已打开集合移除；当前模型和 Context 不变。 |
| 关闭当前条目（建议） | 先准备最近使用的其他条目；原子激活替代模型并移除原条目。准备失败时两项均不提交。 |
| 只剩一个模型 | 关闭按钮不可用，提示“会话至少保留一个模型”。后端也必须拒绝关闭最后一个。 |

关闭只结束会话中的打开状态，不删除注册模型、Authority 数据、历史消息、结果或证据。
关闭后的历史仍可查看。重新打开关闭的模型按明确的注册精确引用准备，不能悄悄恢复一个未知的最新版本。
“重新打开干净模型／重建上下文”保留为显式重置操作，与选择已有条目区分；不放进默认紧凑菜单。

有活动 Attempt、未解决的上下文变更或运行／等待中的 Case 时，仍可查看列表，改变集合／当前模型的操作被禁用。
后端实行相同锁规则，不偷偷取消运行、不提前排队改变当前模型。

## 7. 输入指令

模型管理在应用控制层执行，不交给绑定在旧 Context 上的模型解释它能否切换：

- 支持中文动词与名称之间有／无空格；支持“切换至已打开的 IEEE-39 电网模型”等明确指令。
- “已打开的”限定为当前会话集合。未知、未打开或多个匹配时给出明确提示，不猜测或静默改为打开新模型。
- 单纯打开／切换／关闭指令只执行应用操作，不调用 Provider，不创建分析 Attempt。
- 对“切换到 IEEE-39，然后运行潮流”等明确组合，先完成模型操作，再将后续任务提交一次。
  控制失败时不提交分析；受理分析时固定新的 Context 和适用且已启用的工具集合。
- 不把一般讨论模型、引用模型名称或任意长文字误判成控制操作。只接受可明确分离的控制前缀与任务边界。

全局工具选择不随切换改写或自动重新启用。模型打开／切换／关闭不要求某个计算工具开启。
当前模型基础投影仍有 Profile 准备依赖；实施时必须由应用选择已注册的基础访问／图形适配器，
通过 Authority 的明确合同准备模型，不用偷偷启用分析 Profile 来绕过全关闭状态。
领域计算语义继续属于 Domain Pack，Kernel 不拥有电网目录、关闭规则或引擎转换。
零工具普通对话运行时仍是现有独立缺口；不能以本包的模型管理完成代替该能力验收。

## 8. 应用合同、存储与恢复

推荐新增应用拥有的 `capstone-thread-model-workspace/1` 投影，
以 `GET /api/v1/threads/{thread_id}/models` 返回：Thread/Run 身份、同一 ledger 的事件游标、
当前条目 ID、已打开条目及有界操作可用状态。
投影不扩展现有 `snapshot/1` 的严格字段集合，也不向 `application_state` 随意加入键：
当前 Web 只允许 `case_execution`，后端 Case 序列化还会丢弃其他键。

打开、激活、关闭走现有 Thread command receipt／幂等／游标通道，使用明确类型化的新命令，
分别接受注册模型 ID 或已打开条目 ID，不接受任意地址、文件路径或 Authority 对象。
既有 `switch_model`、`reopen_model_context` 保留兼容适配，其成功变更也必须维护集合，
不能形成另一套互不一致的当前指针。旧客户端的延迟激活行为不在未经验证时静默改写。

服务端持久状态与当前 Context、事件、receipt 使用同一 Thread 事务及锁维护。
内存实现和 PostgreSQL 实现遵守同一不变量。
新操作完成时发出模型集合事件；当前改变继续提供已有的 `model_context_activated` 投影供兼容客户端使用。
客户端只有追到 receipt 对应事件且模型集合投影与 Context 在同一游标一致后，才开放后续发送。
并发标签页用已有 `expected_event_seq` 防止旧集合覆盖新状态，冲突重取后由用户重试。

目录与模型可访问性准备可在锁外完成；提交时必须重新校验游标、锁及精确引用。
任何准备、激活或持久化失败均不得留下半开的条目、悬空当前指针或被覆盖的旧图形。
网络断开后按幂等 receipt 恢复真实提交结果，不重复操作或分析。
刷新、跨设备和事件截断后从服务端集合恢复，不从历史页面或 sessionStorage 推断成员关系。

旧会话第一次读取／迁移时，幂等地建立其当前 Context 对应的唯一条目。
历史曾用模型不能自动算作仍打开。迁移无需 Provider，不改变历史证据或用户模型数据。
集合与投影必须有明确的数量／字节上限及超限拒绝；不能截断集合后丢失当前条目。
具体限值在实施计划中按现有 API 有界合同确定，不由 UI 自行决定。

## 9. 验收与范围

实施顺序：后端集合与原子操作／迁移 → 公共投影与恢复 → 小工具条 → 明确指令路由 → 本地集成验收。

- 内存和隔离 PostgreSQL 测试覆盖初始状态、多个模型、幂等、并发游标、运行锁、最后一个保护、当前关闭及失败回滚。
- 切回同一已打开条目保留精确模型 revision；新 Context 不继承旧结果为当前证据。
- 强制准备／提交失败，确认原模型、图形、层及集合仍一致；复用已有 Context 回滚验收。
- 刷新／断线／丢失 receipt／事件截断恢复集合；Case 状态与模型集合同时存在且均不丢失。
- 旧 snapshot 客户端与旧控制命令兼容性必须有测试；新增集合事件不得破坏事件游标处理。
- App 测试覆盖列表／目录区别、切换／关闭、草稿、焦点、状态提示、零工具模型操作及不调用 Provider。
- 后台真实浏览器覆盖桌面、手机、键盘及连续选择，使用隔离测试会话与注册模型，保留用户会话数据。
- 后端集成改变须通过 `make test`、`make test-e2e`、`make validate`、`make doctor`、App tests/build 和包边界检查；
  当前源码 `make capstone-local-rebuild` 后验证真实入口与 API/worker 一致性。

本次草案不提供完成声明。云端部署、Provider 验证、demo 晋级和各阶段验收标签仍按现有发布授权与规约执行。
本包不实施统一模型转换、任意模型跨工具执行、纯 Pi 参考路径、模型编辑器或新的多 Run 机制。
