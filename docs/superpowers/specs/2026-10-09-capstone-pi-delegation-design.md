# Capstone 与通用 Pi 的任务委托

状态：2026-10-09 用户批准联合设计并要求继续实施；委托路径尚未完成或发布。

用户提出：Pi 同时作为底层引擎和受委托子智能体；Capstone 负责专业能力和
整体回复。共同执行器及两个入口的方向已批准；本文中的契约细节由实施验证。
归属：[普通回答主线](../plans/2026-10-07-capstone-conversation-completion.md)。
延续[共享会话设计](2026-10-08-capstone-conversation-context-design.md)。

## 1. 当前缺口

当前普通执行确实调用 Pi，但使用 Capstone 的受限启动器。
[启动器](../../../packages/capability-agent-kernel/src/capability_agent/runtime/environment.py)
关闭内置工具、skills、扩展、模板和 context files 的自动发现。
[普通会话构造器](../../../packages/capstone-agent/src/capstone_agent/pi_intent.py)
复用该启动器，没有独立通用执行器。
[意图运行时](../../../packages/capstone-agent/src/capstone_agent/intent_runtime.py)
只提供业务 profile 目录，并拒绝可执行的 external_lookup。
因此，缺少领域工具可能在委托之前就被视为整个应用无法处理。

2026-10-09 用户截图还展示了执行计划字段。此前执行投影隔离了诊断文字，
但没有补齐通用执行能力。已有离线协议测试不能证明普通任务已经接通。

固定版本 Pi 的本地 README 说明，默认工具为 read、write、edit、bash，
并支持通过 skills、扩展和 packages 增加能力。它不保证裸运行时自带新闻
搜索服务。应验证实际通用配置的工具与网络条件，再报告能做什么。

## 2. 方案比较

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 独立通用 Pi 子智能体，Capstone 委托并汇总（推荐） | 符合任务分工；原生通用能力与专业事实边界可以分别维护 | 增加委托契约、执行隔离和生命周期管理 |
| 在专业 Pi 会话中直接开放所有通用工具 | 单一执行循环 | 通用操作与 Authority 环境混合，改变现有专业工具约束 |
| 切换到独立纯 Pi 对比模式 | 便于比较 | 不能承接同一专业请求中的混合任务；不能替代委托 |

推荐第一种。Pi 引擎是一套可复用的运行机制；专业 Pi 会话和通用 Pi
子智能体是不同执行角色。用户不需要切换对话才能获得通用帮助。
用户进一步指出委托路径与纯 Pi 模块实现相关，应一起考虑。两种入口
共同设计、复用同一个通用 Pi 执行器，不使用旧对比草案中禁用工具的
配置作为通用能力基线。

### 同一执行器，两种入口

委托入口由 Capstone 发送子任务、相关共享历史和必要依赖结果，接收
类型化结果并汇总。直接入口由用户在纯 Pi 模式发送任务，直接呈现执行器
的输出，不经过领域意图分工或领域执行准备。

两种入口共用 Pi 版本、原生配置加载、工具授权机制、隔离环境、RPC、
取消、预算、产物与来源记录。相同配置身份和授权下，委托不能无声禁用
直接入口拥有的能力。上下文投影分别记录，便于解释结果差异。

会话历史与内部执行记录分开：保留用户可见对话的连续性，同时只投影
当前任务需要的历史。直接入口不自动继承领域系统角色、内部模型状态或
Authority 引用。模式切换与重试固定入口身份，不能让已接受任务换路径。
旧草案中的逐模式历史隔离需要据此重新审阅，不直接作为实现要求。

纯 Pi 的回复保持通用结果身份；进入专业模式后引用它，仍须遵守外部
观察的准入规则。比较时记录版本、配置、授权、任务和上下文差异，避免
把能力被禁用的运行当成纯 Pi 基准。

## 3. 任务流与归属

1. 应用固定用户原文、共享历史截止点、当前对象和可发现能力快照。
2. 独立语义意图节点识别目标、关系、对象、依赖和所需能力。
3. 应用验证决策，为每个目标选择专业执行或通用 Pi 委托。
4. 专业目标沿既有 Harness、Domain Pack、Authority 路径执行。
   通用目标交给独立 Pi 执行器。混合目标按依赖次序运行。
5. 应用接收类型化结果，形成同一个 Attempt 的用户回复。

普通／专业标签仅供兼容展示，不再替代逐目标执行选择。
是否提到专业名词不能决定路径：解释概念、查外部信息、修改模型和计算
需要的执行权限各不相同。仍使用大模型节点，不引入关键词分类或兜底。

应用拥有执行器选择、授权和整体呈现。Kernel 可承载中性的子任务生命周期
和引用契约，不加入新闻、天气或电网语义。Domain Pack 保留专业工具和
事实准入；通用 Pi 不能绕过它执行专业模型操作。

当前架构明确限制模型的通用宿主访问。本方案需要在实施时修订适用范围：
专业会话继续只用已发布语义工具；受委托通用执行器只访问它自己的执行
环境。不能通过删除专业启动器的限制开关实现这一点。

## 4. 能力与原生配置

意图节点同时看到业务能力和通用执行器的能力描述，两者有独立身份、
启用状态、可用状态和配置版本。目录描述用于选择，不授予执行权限。

不要要求 Capstone 提前枚举通用 Pi 能解决的每一种问题。通用执行器可发布
其支持的通用操作范围及真实资源，由子智能体在范围内自行选择工具。
缺少具体业务 capability 不等于缺少通用委托能力；子智能体实际尝试后
也可以返回缺少来源、需要澄清或执行失败。

通用执行器使用独立、应用管理的 Pi 项目和 agent 配置目录。遵守固定
Pi 版本的 settings、context files、skills 和扩展加载约定，记录实际加载
来源与版本。运行时身份和有限任务上下文不是固定领域角色。
不继承开发者 HOME 中的配置，也不继承专业工作区、Authority 凭据、模型
资产或内部 endpoint。Provider 由执行器宿主配置，凭据不进入任务契约。

通用工具在独立执行环境内工作。仅创建另一个子进程不能构成隔离。
首版采用独立执行容器与私有工作区，通过宿主侧受控 RPC 管理；一般工具
不能读取专业 worker 的环境、数据库或私有存储。部署阶段沿用既有隔离
规则，本设计不授权远程部署或自动安装新的 skills/MCP。

## 5. 上下文与委托契约

用户只拥有一个连续 Thread。委托具有内部子任务身份，不创建需要用户
切换的对话。传入同一截止点的相关历史、原始请求、目标和必要依赖结果。
专业对象只传必要的公开身份或用户可见摘要；过去回答保持历史来源标签。
子智能体不复制整份专业系统策略、能力目录或执行计划诊断。

建议委托请求包含父 Attempt、任务身份、用户原文、目标片段、共享历史
投影、依赖结果引用、执行器配置身份、工具授权、截止时间和预算。
子智能体内部调用工具的自由受该执行器授权约束。

返回值包含完成状态、回答或工作产物、实际来源引用、未解决事项、执行器
身份、耗时和用量。状态区分完成、需要澄清、缺少能力、失败和取消。
结果身份由宿主分配；来源和产物由应用验证及保存，不能仅信任模型填写。
不记录隐式推理。内部状态字段保留在诊断与回放中，不直接作为用户解释。

## 6. 结果使用与整体回复

纯通用请求可呈现子智能体的已接纳回答，不强制再调用模型改写一遍。
混合请求由 Capstone 汇总专业结果和委托结果，明确二者的来源。

外部信息是外部观察，不自动成为 Authority 事实。若要作为专业计算输入，
必须先明确单位、时间、地点、目标对象和映射假设，再由应用授权并经
Domain Pack 的输入契约校验。不能用查到的天气直接修改测试网络负荷。
通用回答不得生成 simulator evidence 或伪造专业结果引用。

## 7. 生命周期与首版范围

首版支持一个父 Attempt 内有限的专业／通用子目标及依赖，不让通用 Pi
递归委托回 Capstone。父任务取消、超时和 lease 丢失必须终止子任务。
子任务记录状态、配置、来源和费用；回放展示已保存结果，不再次执行。
重试保留原输入和配置身份，不能自动重做已经完成的有副作用操作。
不能确认执行结果的操作先报告未知状态，禁止静默重试。

需要外部信息的目标完成后才准备依赖它的专业计算。无依赖的目标可以
独立完成；一个委托失败不把已成功目标改写成未执行。

首版交付路径、原生配置、隔离、共享上下文、结果接纳及生命周期。
纯 Pi 模块与委托路径一起设计并复用执行器。实施计划先落实共同执行器，
再接委托入口与直接入口；Capstone 普通／混合任务验收和纯 Pi 直接任务
验收分别记录，不用其中一项代替另一项。skills/MCP 的完整安装管理和
高阶递归多智能体规划仍分开。

## 8. 验收

- 普通文本任务确实调用通用执行器，专业路径不被准备或调用。
- 受授权的通用工具任务有真实调用与产物；不是受限普通 Pi 的文本模拟。
- 外部查询按实际来源执行，缺少来源时由真实委托结果报告。
- 业务目标继续通过 Domain Pack；通用工具无法访问专业资源或伪造证据。
- 混合请求覆盖有依赖、无依赖、部分失败及外部输入映射。
- 普通与专业交替时能理解历史指代，且历史事实不提升为当前计算证据。
- 取消、超时、恢复、重试和回放覆盖父子任务；公开回复不暴露协议字段。

离线测试证明契约、调用路径和隔离。真实 Pi 任务表现、来源质量、费用
与延迟另行验收；付费 Provider 验证仍需明确授权。
