# Pi 生态上的企业自主执行设计

状态：用户已确认概念与方向，授权继续设计；以下具体运行与前端契约供评审，尚未实施或验收。

## 概念与所有权

统一表述：Application 通过 ApplicationProfile 使能业务能力组合；Domain Pack 提供
可复用能力契约；Capstone 在一个持续自主推演过程中组织获准的 Pi 生态与专业能力。

| 概念 | 定义与职责 | 不应混同 |
| --- | --- | --- |
| Application | 企业应用的组合、授权、公共交互和交付责任 | 某个单独 Pack 或前端页面 |
| ApplicationProfile | 应用拥有的版本化业务能力组合，声明绑定、资源需求、协作与验收配置；前端称业务能力组 | 特定任务的计划、模型或运行进程 |
| Domain Pack | 可安装的业务能力模块，提供知识、方法、能力契约、投影及验证规则 | 业务数据源本身或独立主智能体 |
| DomainBinding | Pack 在 Profile 中的一次具体配置，确定命名空间、资源与隔离边界 | Pack 的发行身份 |
| Kernel / Harness | 中性任务状态、持续组织、运行边界、事件、工件及恢复 | 业务知识或事实来源 |
| Pi / registered Authority | 原生智能体执行生态／受契约约束的专业事实与计算来源 | 可互换的结果保证 |

ApplicationProfile 属于 Application 所有权层，不增设第五层。
维持 Application → Domain Pack → Kernel → registered Authority 的职责与依赖方向；
能力组合图、调用顺序及证据返回路径不等同这个所有权顺序。
同一 Pack 可由多个 Profile 复用；执行身份使用 Profile ID、版本及 binding ID 组成的
限定标识，避免不同能力组中同名绑定或工具冲突。首版不隐式合并两个绑定的状态或权限。

## 配置、使能与任务快照

应用发布 Profile 目录；工作空间保存用户使能选择，独立于模型选择。
Profile 声明资源和权限需求，实际授权由应用与企业权限系统签发。
安装、使能、可用和本次使用是四个状态：使能不保证依赖可用，也不要求任务调用全部能力。
资源暂不可用时保留能力说明及具体原因，不显示成可以调用的工具。

每次开始或继续执行，生成不可变的执行配置快照，至少含：

- 工作空间、Work、Attempt 和配置修订标识；
- 选中 Profile 的身份与确切版本、限定 binding 标识及 Pack 版本；
- 原生资源的身份、版本或内容摘要、执行环境身份；
- 授权引用、获准操作、跨绑定交接规则及产物检查规则。

快照不保存密钥，不取代实时授权校验。新版本安装不静默替换活动任务的资源。
正常配置变更在明确的行动边界生成新快照，不改写已执行事件。
新增使能由用户或既有应用策略授权；模型可以建议，但不能自行扩大能力范围。
禁用使该范围的新调用立即失效；已发出的调用请求取消，不能假称已撤回外部副作用。
晚到结果可保留为审计记录，须重新检查后才能用于后续执行。界面显示取消中或结果未知。
权限撤销始终优先于旧快照；恢复不得借旧配置绕过撤销。

工作空间至少可使能一个通用企业执行 Profile，其基础 Pack 不要求电网模型。
全部组禁用时可以查看既有任务和成果，启动执行时明确提示缺少已使能能力，不能暗中启用。

## 已确认的目标与边界

通用执行能力由 Pi 等底层智能体生态与 Capstone 长程自主推理组织能力共同形成。
推理与执行持续交互；不能将 Capstone 简化为一次委托，也不能把 Pi 定义为不参与推理的工具进程。
ApplicationProfile 是业务组合与使能单位，Domain Pack 是能力契约边界。基础 Pack 可使用已有 skills、MCP、
连接器与受控编程能力；无需逐个改写为 Capstone 专有工具。专业 Pack 保留语义工具和
注册 Authority 契约。业务分类级通用不等于无限权限，也不等于普遍业务胜任保证。

企业数据平台负责数据服务、来源和正式口径；专业系统负责模型、求解与专业事实。
Capstone 负责使用这些资源推进任务，不负责重建数据平台或补造缺失事实。
用户提供的历史市场分析和事故缓解案例用于检查责任边界，不是两个待开发应用。
Demo 1 已明确用作通用能力的验收案例：通过通用企业执行 Profile 和基础 Pack，
使用外部电力数据、业务资料及 skills/MCP 完成专业内容的分析。无需新建电力市场
专用 Pack，不为此新增 Capstone 专属查询、指标或口径接口。业务知识的专业性
不改变执行机制的通用性。专业仿真是按需扩展，不是 Demo 1 完成的前置条件。
无专用 Pack 不等于无业务知识；已有 skills/MCP 及其背后系统可能已经提供完整流程。
能否完成须依据任务实际条件，不能从安装了基础 Pack 推出。

## 运行结构

Application 通过 Profile 选择 Pack、资源授权、交付范围和交互入口。Pack 声明业务语境、可用资源、
执行配置及验收规则。Kernel 保存中性任务状态、事件、产物引用与恢复信息。
Harness 将这些契约接入 Pi 推理执行循环。Authority 继续拥有其专业事实。
这是一套职责分配，不增加第五所有权层，也不要求每次调用穿过所有相邻层。

一个主智能体读取目标和当前工作状态，选择下一步，调用获准能力，观察结果，
调整方法或继续执行，并检查交付条件。已有 skill 能完成工作时可以直接使用。
不强制每个请求经历分类、完整拆解、委托、反思和研究初始化。
复杂任务才增加研究记录、子任务或专业计算；不建立固定的双重 LLM 计划循环。

### 同一主链路，按需展开

普通问答、实时资料查询和复杂企业分析共用任务入口、Profile使能、Pi推理执行、
Capstone组织状态及交付机制。不以普通/专业分类器作为前置总开关。
默认可用的通用Profile支持模型直接回答；无工具需求时无需初始化分析沙箱、
生成完整研究结构或委托子任务。基础任务身份与消息记录仍然存在。

“解释什么是彩虹”可直接回答；“今天的国际要闻”需采用执行日期、用户相关时区及
实际实时来源，无法获取时明确限制；Demo 1按实际需要使用数据工具、分析环境、
持续研究状态和产物检查。它们是行为验收样例，不是按关键词分支的路由规则。
实时性、事实依据和交付要求决定需要什么能力，不由题目是否属于某行业决定。

执行中可逐步升级：普通回答后的追问可以要求检索，再要求分析和报告；
在同一Work中记录目标修订和新增资源使用，不因升级丢失已有发现。
新问题若与现有任务无关，可创建新的Work并保持同一Thread的交互历史。
能力需求增加不自动增加授权，实际使用仍限定在已使能且获准的资源内。
专业Authority调用保持隔离契约，同一主链路不意味着所有工具进入同一个无限权限会话。

建议宿主在三个时点介入：模型调用前提供有界状态与获准资源；行动前检查权限、
版本和输入契约；行动后保存执行回执、产物与状态变化。最终交付前执行适用的验收规则。
模型负责选择和解释，宿主负责真实授权与记录；提示词不能替代执行检查。

## 自主推演与专业结果

Profile 和 Pack 提供方法、适用条件、反例提示及实际能力，不提供必须照走的研究步骤。
主智能体按研究状态选择直接回答、查资料、调用工具、执行已有 skill、构造分析、
委托、修订认识或提交交付候选。研究节点记录可核验的行动理由和依据，不记录隐藏思维。

研究状态由目标、当前问题、已支持的判断、待检验解释、反例、关键缺口及成果组成。
每个重要判断引用依据与适用条件。工具返回首先成为观察，不自动成为已验证判断。
通用组织机制关注依赖、版本、状态与证据关系；专业适用性由 Pack 的知识和检查提供。
新观察可触发修改方法、补充数据、撤回判断或停止无收益的探索。
简单任务不强制创建完整假设图，也不为每次工具调用增加一次独立评审模型请求。

完成候选必须覆盖目标的当前版本，并通过相关交付检查。宿主执行可判定的规则；
开放的业务判断保留检查来源、局限及必要的人工确认，不以同一模型的自评冒充独立验证。
失败、预算耗尽、等待资料、限定交付与完整完成分别呈现。局部成功不能更改原目标为已完成。

## 多 Profile / Pack 协作

一个 Work 共用目标与研究认识，各绑定只保有自己的领域状态。
同一 Profile 内及不同已使能 Profile 间均可合作；使能双方不自动授予相互数据访问。
应用配置定向交接规则：来源、目标、引用类型、目的、允许能力及必要的目标准入。
主智能体选择交接时机，宿主验证授权、来源版本和输入条件，保存回执。
不允许一个 Pack 私自调用另一 Pack 内部接口或直接读取其工作目录。

交接失败返回结构化缺口；Capstone 可选择其他获准资源补齐、改变方法或限定交付。
跨 Pack 的整体判断还须检查时间、对象、场景和口径是否一致。
多个局部有效结果不能直接拼成因果证明。专业 Authority 证据与一般观察类型保持区分。

Demo 1 中，历史分析发现外送偏低后，可以研究是否存在网络约束。
若有匹配历史时刻的模型与状态，可按授权引入专业计算；只有当前网络模型时，
不得将当前仿真结果解释成历史事件成因。该例是对自主选择与拒绝错误组合的检验，
不是预设市场查询→仿真→报告的流程。

## Pack 与原生资源

基础 Pack 是一个可安装的企业工作能力包，不是所有工具和行业知识的集合。
其契约包含用途、版本、原生资源引用、执行环境要求、输入与产物类别、权限需求、
检查规则和限制。应用批准的权限与 Pack 请求的权限取交集。
skills 保留原生内容和依赖，MCP 保留真实工具协议；适配集中在发现、授权、
执行记录及结果接纳边界。安装、启用、可执行和已验证分别记录。

专业会话保持语义工具限制。需要代码或文件处理时，由应用授权隔离的通用执行上下文，
接收显式允许的资料副本或资源代理。不能给专业会话直接增加 shell，不能将 Authority
句柄、凭据或原始模型对象带入 Pi。基础 Pack 不能成为绕过专业约束的备用通道。
多个 Pack 通过应用授权的类型化交接协作，不共享彼此内部状态。

## 任务、资源与工作认识

建议以持久 Work 身份组织长程任务。Thread 管理交互，Attempt 表示一次执行片段。
Work 保存目标及修订、交付条件、资源引用、行动状态、产物与未解决事项。
Research Model 按需保存方法、假设、发现及证据关系，不等同业务模型。
模型是可选的业务资源；不能用空电网模型填补通用任务的身份。

资源引用记录来源、版本或获取时间、允许操作与适用范围；大数据保留在资源服务或
产物存储中。无法固定版本的外部数据明确标为可变，复现保证不能超过实际能力。
输入变化只使依赖这些输入的判断待重验，历史结果及其适用条件保留。

## 通用资源到专业内容的执行闭环

以下契约覆盖任何资料与数据分析，不为电力字段或指标建立专用 Kernel schema。

| 环节 | 设计契约 | 责任位置 |
| --- | --- | --- |
| 发现 | 按授权发布原生工具说明、资源与技能入口；支持按需查阅，保留不可用原因 | 应用配置、Pack资源声明、Pi原生发现 |
| 理解 | 读取资料及元数据，记录采用的定义来源和适用范围；冲突进入研究缺口 | 智能体与外部业务知识 |
| 获取 | 通过已授权MCP、连接器或文件取得内容；支持分页、服务端导出或流式落盘 | 外部服务与通用执行适配 |
| 处理 | 在工作区执行分析程序；保存输入引用、代码、环境身份、参数和输出 | Pi执行环境 |
| 核验 | 对关键结果使用适用的独立检查、重算或外部校验；记录实际覆盖与未核验范围 | 原生工具、skills及业务检查资源 |
| 交付 | 结论关联结果、方法及来源；导出产物有完整性、可读性和授权检查 | Capstone任务组织与应用呈现 |

表格列出必需的衔接能力，不规定调用顺序。智能体可直接执行已有完整skill，
也可根据观察逐步构造方法。原生工具名称、业务字段和指标定义不写入核心分支判断。
工具描述或外部文档不能自行授予权限，也不能覆盖应用的执行约束。

业务定义可来自文档、字典、工具元数据或skill，保留原有格式。
Capstone只保存来源引用、定位、获取时间/版本和被采用的解释，不要求企业迁移到
一种Capstone指标库。定义冲突时主动寻找适用依据，无法解决时保留分歧，不能默选。

大数据留在数据服务或工作区；模型获得有界摘要、抽样及可继续查询的引用。
获取完成与部分获取必须可区分；来源有行数、游标或摘要时保存核对记录。
服务未提供完整性保证时明确记录限制，不能把一次工具成功等同于全部数据已取完。
单文件和总量配额由运行配置决定。超限显式返回失败或可恢复的部分状态，不静默丢弃产物。
数据集、分析代码、图表和最终报告分别登记；报告可引用附件，不把所有字节塞进消息。

通用产物引用至少记录身份、类型、摘要、大小、访问范围、创建行动和输入依赖。
外部数据无法冻结时记录实际获取内容或可用的版本信息，并限制复现声明。
恢复需要可访问的工作文件和执行环境，不能仅恢复工具摘要；无法恢复的派生内容
按依赖重算。旧产物保留，失效状态显式投影到图表及报告，不只修改最终文字。

DomainRuntimeProfile目前强制authority_factory及authority_backed准入能力。
目标设计应将共同的Pack声明与执行/证据配置分开：专业绑定保留Authority准入，
通用绑定采用来源、执行回执及产物检查，不虚设模拟器Authority。缺失验证不能默降级。
这属于公共SPI演进，需验证专业Pack不失去现有检查；不是给Kernel增加业务计算逻辑。

## 直接执行与委托

默认由同一主智能体持续组织。只有并行、环境隔离、专门技能或上下文收益明确时委托。
委托契约包含子目标、获准输入与资源、预算、完成条件和预期产物。
子任务返回执行状态、结果引用、依据、失败或缺口；父任务检查后才更新自己的状态。
子任务成功不自动证明父目标完成。纯 Pi 入口可作为直接入口与对照配置，
不能成为另一条不受治理的企业接入路径。

## 恢复与交付

行动记录至少区分计划、已发出、已确认、失败及结果未知。操作身份在执行前持久化。
恢复先查询回执或外部操作状态；只有确认无副作用或具备可验证幂等语义时才能重试。
未知结果不盲目重放。工作区产物有版本与完整性检查；上下文摘要不替代持久状态。
恢复时重新检查授权；已撤销权限不能因旧检查点而恢复。资源版本变化形成显式新执行。

交付检查分别判断执行成功、来源可追溯、计算或方法核验、业务条件满足。
一般工具观察、脚本计算、业务系统记录、Authority 证据保持不同来源类型。
关键依据缺失时可交付已有部分并注明缺口，不能将局部成功标为全部完成。
面向用户呈现任务级发现、调整、缺口与结果，不暴露隐藏思维或用工具数量代替进展。

## 前端与 API 的共同契约

前端主对象是工作空间、任务和成果。聊天承载请求与追问，模型面板是业务资源的一种视图。
不以电网模型选择作为创建任务的先决条件，不要求用户选择纯 Pi 或委托 Pi 才能开展工作。

| 界面 | 内容与操作 | 后端责任 |
| --- | --- | --- |
| 工作空间能力组 | Profile 名称、用途、使能开关、可用性及失败原因；展开查看 Pack 和原生资源 | 目录、配置修订、权限过滤和真实依赖状态 |
| 新任务 | 目标、资料、交付要求；展示本次能力范围；模型按需附加 | 创建 Work 与执行快照，校验资源引用 |
| 任务进展 | 阶段发现、方法修订、缺口、待用户决定事项；工具详情按需展开 | 持久事件、序号、判断修订关系和明确执行状态 |
| 成果 | 报告、数据、图表预览或下载，版本与依据，核验状态 | 有界产物投影、受授权下载、内容完整性与来源关联 |
| 暂停与继续 | 区分暂停请求、已暂停、取消中及结果未知；补资料或修改目标后继续 | 真实取消结果、幂等命令和恢复协议 |

工作空间开关默认影响之后的执行；活动任务也立即禁止被禁用范围的新调用，
并显示当前快照与新配置差异。开关提交失败回滚界面并显示错误；并发编辑按配置修订
检查冲突，不静默覆盖其他客户端。已保存成果不会因禁用而删除，其读取仍受现行权限约束。

建议任务事件最小投影包含 Work ID、单调序号、时间、事件类型、Attempt ID、
配置修订及载荷。载荷按类型提供发现引用、状态、产物引用、缺口或待决请求；
来源可含限定 binding 标识。快照带最后事件序号，客户端按序恢复、去重并补取缺口。
断线不等于执行停止，刷新后从服务端快照恢复。进度文字必须指向真实任务变化。

命令携带 command_id 及预期任务或配置修订；重复提交返回原回执。
UI 区分已接收和已生效。读取状态、产物和执行外部动作分别授权。
不在浏览器下发存储凭据、原始内部状态或 Authority 对象。

桌面保留任务交互主区，进展与成果可并列；窄屏切换同一任务的对话、进展与成果视图。
业务能力开关使用可聚焦控件与可见文字，不以颜色独立表达状态。
耗时操作显示真实等待原因；重大判断修订保留旧记录并关联新记录。
不提供伪精确百分比，不用连续工具日志替代用户可理解的进展。

## 验收设计

- 已有 skill/MCP 流程：真实工具与产物，直接完成，无多余委托要求。
- 多阶段分析：来源充分的受控资料，检查真实计算、方法调整和产物引用。
- 条件不足：缺少必要口径或数据，识别具体缺口，不能伪造完成。
- 长程恢复：跨上下文压缩和进程中断，目标、发现、版本和产物关系保持一致。
- 外部动作结果未知：恢复不会重复发送或重复写入，撤销授权生效。
- 专业协作：普通产物不冒充 Authority 证据，模型引用按应用授权交接。
- 使能与撤销：Profile 未启用或依赖缺失时不能调用；禁用后阻止新调用，晚到结果不继续触发操作。
- 跨组协作：同名绑定隔离，无授权交接被拒；历史与当前场景不一致时不能产生错误综合结论。
- 前端闭环：无模型创建任务、真实进展、成果和依据、修改要求继续、刷新与断线补取。
- 自主性：变更资料顺序、加入口径冲突和反例后，按证据修订方法；不按固定工具序列判分。
- 统一入口：彩虹解释不强制查资料/委托/分析沙箱；当日新闻用实际实时来源；Demo 1可展开长程分析。
- 深度变化：同一任务从问答转为检索或报告后，目标与产物版本可追溯，权限不会自动扩张。

受控模型测试只证明协议和恢复语义；实际模型的任务质量另行评估。
付费 Provider 验证遵循单独授权，已有离线检查不构成本设计的实现验收。

Demo 1具体评审与通用验收矩阵见[案例评审](../../reviews/2026-10-15-demo1-general-execution-review.md)。
