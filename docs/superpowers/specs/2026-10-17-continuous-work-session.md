# 用户主导的持续工作会话

状态：2026-10-17 用户已确认的设计；实现未完成。补充并修正企业任务界面及执行契约中的单次目标/单次产出表述。

## 统一语义

会话围绕工作对象建立，初始具体目标可空。电网入口预配一个主要模型，企业研究入口支持文档及授权接口，通用聊天不绑定专业对象。资料缺失不阻止讨论。用户控制方向和范围；Profile提供方法与成果默认建议，不强制生成报告。

会话、阶段工作、用户指令、执行尝试、过程制品、成果汇总是不同身份。既有Thread承载会话，Work承载阶段工作，Attempt承载执行尝试；不得把第一条消息或最后一个Work当作整个会话的永久目标。一次回答或报告完成不结束会话。

统一Harness承担两个关联层次的组织：指令内分解、执行与检查；会话内关联成果、聚焦上下文、发现缺口、提出建议并推进已授权目标。不另造独立运行时。等待用户是正常状态；不得因会话存在而无限后台执行。停止、取消、预算及授权边界在两个层次共同生效。

## 工作记录与上下文

完整记录保存成功、部分完成、失败、取消及未知结果，不覆盖历史。过程制品归属会话、阶段工作、指令与尝试，记录实际输入对象版本、来源引用、状态、关联制品及后续替代关系。失败制品可以没有内容文件；保留已有部分和原因，不把空文件冒充产出。

后续指令可引用已有过程制品，依授权与用途解析版本；历史Authority结果仍是历史结果，不自动成为当前运行证据。涉及当前模型状态的断言必须重新计算或按既有准入契约显式核验。引用失败不会自动重放外部副作用。

任务级交付制品按用户提出的具体输出要求生成和修订，可以是报告、图表、数据表、方案文件或其他受支持形式，不能限定为文字总结。用户可以多次发起，智能体提供过程支持及适时建议；输出完成不结束任务会话。制品关联支撑及未解决的过程记录，不隐藏失败或捏造完整性。未请求交付制品时仍可探索并访问真实过程制品。

### 制品层级与归属

指令级过程制品记录一次指令执行的成果、局部产出和失败；任务级交付制品响应某项任务的交付要求。层级不能由触发它的指令、文件格式、最新时间或工具调用次数推断。一条指令可以发起任务级交付要求；生成过程中的多次计算仍是过程制品。

沿既有Thread、Work、Turn、Attempt及Artifact身份补齐关联，不重建另一套任务账本：

| 契约职责 | 需要保存的关系 | 不代表什么 |
| --- | --- | --- |
| 阶段任务 | 会话、工作对象、目标修订及研究身份 | 不是整个会话的永久目标 |
| 交付要求 | 所属Work、触发指令、内容范围、格式、要求修订 | 不是每条消息必须创建的表单 |
| 过程制品 | 所属指令与Attempt、输入版本、生成状态、内容及依据引用 | 不自动成为任务级交付 |
| 交付制品 | 所属Work、交付要求及修订、制品身份与版本、生成尝试、支撑过程引用 | 完成不等于会话结束 |
| 版本与依赖 | 替代关系、支撑关系、受影响状态、检查范围 | 新版本不删除历史或自动撤销全部旧成果 |

生成状态、检查状态及交付要求满足情况分别记录。失败可以无文件，但必须保留真实过程记录；任务交付失败不抹掉有效局部产物。分类和关系由主链路接纳并持久化；模型可提出关联，宿主核对身份，前端不编造。

跨Work复用采用同会话的显式制品引用与上下文选择，不能直接删除现有Work隔离测试或将全部旧回答作为有效依据注入。会话层提供工作与制品目录，当前Work研究状态保留独立身份，选中的历史事实仍遵循原Authority准入规则。

### 整体应用交互闭环

1. 用户从类型入口建立对象中心的会话，允许目标尚不具象。
2. 对话持续表达探索、修改、引用和交付要求，由同一Harness组织执行；不增加第二个“启动”步骤。
3. 回答下展示本轮过程制品及失败/部分状态，支持查看与引用；引用显示真实对象及版本，不隐式切换当前模型。
4. 右工作区区分任务交付制品与执行过程制品，可从一项交付查看其支撑过程，从过程返回所属指令。用户按需打开完整目录，默认不平铺全部中间项。
5. 用户提出具体交付要求后，主链路组织所需分析及生成，输出可多次修订。新版本不抢占用户正在阅读的历史版本。
6. 系统故障通过关联入口进入诊断侧滑窗；无可行解等业务结果留在工作区，不混为系统报错。
7. 任一输出完成后继续保留会话，可探索下一项任务；标题栏只呈现全局简洁摘要。

当前工作上下文是有来源的可恢复投影：对象与版本、当前关注点、已授权阶段目标、有效成果、未解决问题、失败教训、候选下一步。压缩记录来源范围及游标，完整记录保留；摘要不是Authority事实。刷新与恢复不重发指令、不重复执行。用户纠正形成修订，更新相关判断，不能只追加矛盾文本。

## 业务过程与系统诊断

业务无可行解、数据缺口、工具或系统故障需区分；不能判定原因时明确未知。用户过程制品给出结果、影响与恢复选择；系统诊断保存异常、事件链、持久化和传输细节。通过同一执行身份关联，不把所有失败都藏入诊断。

## 实现差距与切片

### 会话标题生命周期（用户确认）

- 新会话缺省按入口类型命名：电网分析与决策、企业研究与分析、通用聊天。没有具体目标也能创建。
- 标题是可编辑的会话识别信息，不是阶段目标、执行指令或授权。改名不修订工作目标。
- 自动命名使用当前关注点及已发生的工作概况；不能直接截取第一条消息，也不能把尚未完成的计划写成已完成成果。
- 自动更新优先由重要制品发布或实质修订触发，采用任务级重于指令级、完成完备性重于在途状态、当前相关重于历史的原则。结合当前工作关联判断，不以最新时间或工具数量直接排序，也不让历史完整成果永久压过新的工作方向。
- 无重要成果时保持稳定，首次具备足够工作内容可替换类型缺省名；必要的关注点变化可低频更新。撤销固定“三条指令且五分钟”的门槛，不得延误重要成果体现。合并同一批事件以防重复命名，不逐token、逐工具或每轮改名。实际完整性来自主链路投影，不由标题生成器判断。
- 自动命名属于辅助任务，超时或失败保留原名，不阻塞回答、成果持久化或下一条指令。优先复用已有上下文整理结果，不为每轮额外发起命名调用。
- 保存标题、命名来源（缺省/自动/用户）、标题修订、上次自动命名使用的指令游标与时间。命名更新使用独立标题修订，不能因执行事件增长制造无关冲突。
- 用户手动改名成功后持久设为用户命名，后续停止自动更新；刷新、重连、继续执行均保持。用户恰好输入原名也视为手动接管。空白标题不保存，保留编辑内容并提示。
- 自动候选提交时再次检查命名来源及预期标题修订，晚到结果不得覆盖用户改名或更新的自动标题。切换会话后的结果只能更新原会话身份。
- 左栏和顶部消费同一服务端标题，提供轻量编辑入口、Enter保存和Escape取消。保存失败保留草稿；长标题截断但提供完整名称。原始短ID保留在详情。

## 验收场景

- 仅选对象开始探索，不要求预先填写具体目标或成果。
- 连续请求产生多个成功与失败制品；引用早期结果开展比较，刷新后关系不丢失。
- 用户纠正对象或判断，旧制品保持原版本，受影响成果可识别。
- 多次生成、修订汇总，输出完成后仍可继续会话。
- 失败后利用已完成部分恢复，不重复已成功的外部动作。
- 自主步骤完成当前授权目标后回到等待；新方向不被系统擅自采用。
