# Task completion control

2026-10-24。用户已接受：任务结束设统一控制环节，缺省记录并放行；显式配置校验器后才按结果处理重试。
本文定义完整目标。当前产物接收的非阻断修正不等于全部控制器及校验器注册接口已经实现。

## 位置与职责

控制环节属于任务执行引擎内部生命周期，不是业务规划节点，不增加任务步骤号，不额外调用LLM。
现有执行账本、任务池和依赖调度继续使用，不建立第二套任务系统。

`执行结束 → 保留实际返回及产物 → 结束控制 → 提供本次结果 → 主链继续组织`

宿主事实接收与质量判断分离。前者核对所有者、版本、文件身份与引用；后者仅由显式注册的校验器判断。
接收不到的文件不变成有效证据，但不能因此丢弃整批可用结果或让LLM反复重交。

## 缺省行为

- 原始执行状态、生产者陈述、实际接收产物、未接收项、失败原因及未做检查均被记录。
- 没有校验器时决定为`release`，标记`validation_status: not_configured`，不得显示“质量通过”。
- 缺失文件、缺少检查、说明字段、关联不完整等形成诊断，不产生节点重试、重交要求或成功伪装。
- 执行本身失败仍记录为失败；`release`只表示本次结果可以交给主链，不把失败改成成功。
- 依赖缺少实际输入时，不编造输入。主链可用已有子集、说明缺口或等待用户指示，不能偷偷重跑原节点。
- 必要账本/答复持久化失败、取消及所有权完整性故障保留独立系统状态；不得伪报提交成功。

## 中性输入/输出契约

输入仅含只读版本化引用：任务/尝试/行动身份、实际执行状态、返回观察引用、已接收产物引用、
未接收项和原因、声明检查及已知限制、当前尝试次数、剩余时间/调用预算、策略版本。
原始大文件、凭据、可写全局对象和Authority内部对象不进入控制器。

输出包含`decision: release | hold | retry`、原因码、诊断、实际执行状态、
`validation_status: not_configured | passed | failed | unavailable`、校验器版本、重试请求与预算使用。
`hold`表示按显式策略等待处理，不代表自动拒绝并重做。输出不创造事实或证据。

建议配置：

```json
{
  "taskCompletionControl": {
    "mode": "record_and_release",
    "validator_id": null,
    "on_validator_error": "release_with_diagnostic",
    "retry": {"enabled": false, "max_attempts": 1}
  }
}
```

`max_attempts`计入首次执行；缺省1次、禁止自动重试。
validator_id由Application选择的受信注册表解析，模型和资料不能指定任意代码路径/端点。
Domain Pack拥有领域校验语义；Kernel只承载中性合同和生命周期，不包含业务判断规则。

## 校验器与重试

仅显式配置校验器才调用。校验器获得相同只读输入，返回结果与建议，不直接重跑任务或写主上下文。
校验器超时/异常默认记录为`unavailable`并放行；需要hold的应用必须显式配置，不能隐含变成硬门禁。
LLM校验器属于可选插件，成本和时长独立计量，不成为缺省结束步骤。

重试同时要求：注册校验器明确返回retry、重试已启用、存在具体修订建议、尝试和总预算均有余额。
预算耗尽时交付现有结果及限制或按显式策略hold，不再循环。普通工具/产物接收错误不会自行启用此策略。
新尝试获得新身份、独立上下文和明确修订输入，保留旧执行、旧结果及supersedes关系；
禁止重复使用同一拒绝收据、隐藏原失败或反复运行整条指令。

## 与现有实现的接缝

1. 原生task return与最终freeze使用统一产物接收策略：接收可用项、返回未接收项；不将缺项抛回模型要求重交。
2. 在现有`commitProposal`的执行结束提交处接入结束控制。记录与控制决定使用现有CAS检查点，
   以任务/行动/执行版本/策略版本形成幂等键；恢复时读取已提交决定，不重复校验或重试。
3. 默认自动记录只采用宿主已确认的关联；不完整关联保留诊断与子集，禁止猜测绑定。
   接通后主模型不必再手工抄写记录/评估协议，旧record入口仅作兼容和显式补充。
4. 校验器注册表、配置解析和重试调度通过现有组织/任务池接入。未完成接通前不得宣称已支持配置校验器重试。

## 验收

- 一批12个有效产物加1个缺失复现脚本：12项保留、缺失项有原因、无LLM重交。
- 只有缺项、空文件、不可读文件或不完整关联：记录实际可用内容与诊断，不伪造产物、不自动重跑。
- 无校验器：0次校验调用、0次重试；相同检查点恢复不产生额外调用。
- 有校验器但未启用重试：记录failed建议，仍按配置release/hold，不运行第二次任务。
- 显式有限重试：只产生预算内的新尝试，旧结果和诊断完整保留，取消立即传播。
- 接收、校验、记录和控制决定分别可观察；UI放行不等同质量通过，执行失败不伪装成功。
