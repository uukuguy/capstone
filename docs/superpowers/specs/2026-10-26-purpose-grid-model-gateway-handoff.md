## 1. 目标与责任

同一登记电网模型，在同一源版本上，提供四类用途：总览、设备电气拓扑、
潮流、优化。客户端按本条指令的实际执行上下文选择用途。附件、名称关键词、
会话入口及历史任务目标都不能单独决定当前图。手动选择仍有优先级。

这是通用模型组件，适用于任意已登记 gateway 电网；华北只是一个实际验收样本。
模型发现、源选择、设备语义、端子连接及准备度由 gateway 提供；Capstone 负责
受保护的契约接入、分层读取、布局、显示及经注册 Authority 的计算调用。
浏览器不得接收数据库凭据、调用方自选上游地址或任意查询工具。

“同一模型版本”指共同的源及选择基线，不要求各用途使用相同产物哈希。
潮流工况、优化约束、引擎转换会形成独立派生版本，必须可追溯到共同基线。
源拓扑图可有数据缺口；好看的单线图、生成成功的文件及安装好的 SDK 均不证明
真实潮流或优化就绪。未知开关状态不得用于母线归并或运行电气岛推断。

## 3. 当前实际数据与表示限制

Capstone 保存的华北未分组响应共有 53 页，使用同一 `view_ref`，合计
52,625 个对象、48,319 条关系，所有返回关系端点均在完整页集中。
其中有 825 个母线条、1,046 个变压器、2,722 个绕组、5,157 个断路器、
10,242 个隔离开关、14,290 个接地隔离开关、15,302 个连接节点、
2,006 个线路端子及 1,003 个线路对象。

返回图的引用完整不代表源接线完整：存在 5,926 条 `device_topology_missing`
缺口；37 个母线条、809 个断路器没有返回连接；2 个发电机均无连接，
30 个负荷中 28 个无连接。512 个绕组关联两个连接节点，其端子角色不能猜测。
连接节点没有站点归属字段，其中 7 个连接节点的相邻设备跨多个站点。
布局不得把这些对象静默归入某一站，或补造发电机/负荷接线。

当前 gateway `station` 投影明确删除连接节点及其关联边，仅保留设备清单、
部分线路端子关系和绕组归属。保存的一个站内样本为 44 个对象、10 条关系，
因此该投影本身不能用来还原完整站内电气单线图。

但当前代码还支持一个兼容读取路径：
`level: "equipment", selected_object_id: "station:<原始ID>"`。
该路径按站点选择设备，同时保留连接节点；已有电压分组的 `expand` 也指向它。
它可供 Capstone 实现局部接线视图，不必先下载全网未分组对象。
本次已核验该参数组合：首次经 Capstone API 返回503；随后宿主机直连 MCP
返回57个对象/56条关系，工作台受保护 API 再次读取成功（约237毫秒）。响应
保存在 `outputs/grid-scale-20261026/purpose-station-direct.json` 和
`purpose-station-closure.json`。这验证了此样本的兼容读取，不证明源接线完整；
首次失败与暖缓存后成功需分别记录，仍需改进初次加载及局部请求的成本。
当前 station 清单和设备接线视图应保留不同标签。

复核依据：

  至 `actual-053.json`，以及 `north-station.json`、`north-equipment.json`。
- gateway 实现：`src/data_gateway/topology_views.py` 中站点选择、
  `source_connection`、`winding_membership` 及 station 删除连接节点逻辑。
- gateway 源适配：`src/data_gateway/network_model_source.py`；当前对

## 4. NEW：用途发现与共同版本基线

建议扩展模型发现结果，每个模型返回以下结构。示例为字段形状，不是实际模型记录：

```json
{
  "schema": "gateway-grid-model-capabilities/1",
  "model_ref": "opaque-model-ref",
  "model_revision": "opaque-source-model-revision",
  "source_snapshot_ref": "opaque-source-snapshot",
  "selection_ref": "opaque-selection-revision",
  "purposes": [
    {"purpose": "overview", "support": "supported", "readiness": "not_checked"},
    {"purpose": "electrical_topology", "support": "supported", "readiness": "partial"},
    {"purpose": "power_flow", "support": "supported", "readiness": "blocked"},
    {"purpose": "optimization", "support": "unsupported", "readiness": "not_checked"}
  ]
}
```

每项还须提供版本化能力/准备度检查引用、检查时刻、阻碍与缺失输入、适用表示、
可请求的下一步动作。发现应保持轻量，不因列清单自动构建全部模型。
`support` 与 `readiness` 分开：尚未检查不能写成已就绪，不支持也不能写成源数据缺失。
准备度记录必须绑定模型、源、选择及用途修订，失效时重新检查。

用途语义：

- `overview`：来源范围、分区/站点及跨区连接导航，不执行电气等值。
- `electrical_topology`：设备端子与连接节点的结构；允许显式未知状态/缺口，
  不将其当作已核实运行母线模型。
- `power_flow`：区分 AC/DC 等具体方法、真实/演示场景、参数/状态/边界/工况准备度；
  已有 `demo_power_flow` 保留明确演示身份，不自动升级为真实工况。
- `optimization`：声明实际问题类别，如线性 OPF；分别核查成本、容量、可控量、
  约束、工况及引擎映射。潮流可运行不等于任意优化问题可运行。

派生产物记录 `artifact_ref`、`artifact_revision`、共同基线引用、用途、
`scenario_ref`/`scenario_revision`、格式与引擎版本、转换规则版本及哈希。
状态/时点未知必须显式保留。使用方按实际指令选择用途，不自动连做所有构建。

## 5. NEW：设备、端口、连接与分组契约

建议为 `get_network_topology_view` 增加显式新表示/版本选择，或提供独立的
版本化工具；二者择一发布清晰契约。不能静默改变旧 `nodes/edges` 的语义。
表示建议名为 `electrical_node_breaker`；它不是开关归并后的 bus-branch 等值。

| 记录流 | 必需语义及字段 |
| --- | --- |
| `devices` | 稳定 `id`、规范 `kind`、`source_kind`、名称、源记录引用；站点/电压层/间隔归属及依据；母线条、断路器、隔离/接地开关、线路、变压器、绕组、发电机、负荷分型 |
| `ports` | 稳定 `id`、`device_id`、源端子引用或明确缺失、已知 `sequence`/`role`、连接核实状态；未知端序/高低压角色为 null，附缺口 |
| `connectivity_nodes` | 原始连接节点身份、源引用、已知归属/电压及冲突；它不是默认已归并电气母线 |
| `connections` | 稳定身份、精确 `port_id` 与 `connectivity_node_id`、关系种类、来源和质量；多值或歧义不能静默取第一个 |
| `device_relations` | 如绕组属于变压器、线路端子属于线路；明确是构成关系，不作为普通导线渲染 |
| `groups` | 站点、电压层、间隔等显示/容器层级、稳定引用、父级、成员总数、分页成员及展开引用；不声明电气等值 |

规范种类不得取代原始 `source_kind`。未知种类保留原值和通用符号。
源中没有端子记录时，不得伪造“原始端子 ID”。若发布由源关系生成的结构端口，
必须标记 `identity_origin: "derived_incidence"`、提供确定性规则版本及源关系引用，
与 `identity_origin: "source_terminal"` 区分；未知角色仍为 null。
布局临时锚点仅存在客户端显示几何中，不能写回源端子数据或用于计算建模。

开关状态建议为独立结构：`value: open | closed | unknown`、`verified`、
`observed_at`、`source_ref`。字段缺失按 unknown 处理。`in_service`、
是否带电及测量质量独立，不从开关种类、图符、文件格式保护性默认值推断。
未知状态用中性图符；不得画成已断开/已闭合事实或据此做母线归并。

母线条保留实际设备身份；多个设备端口连接到同一确切连接节点时，客户端可为
清晰显示设置多个附着锚点，但不能新增不同连接节点间的导通关系。变压器需保留
各绕组与其端口；不能由节点电压排序伪称已核实额定侧角色。

## 6. NEW：分层下载、版本和边界

模型发现→范围/分区清单→站点→电压层/间隔→设备邻接闭包应可逐级读取。
任一已登记模型均使用同一契约，不通过名称或固定区域代码选择专用算法。
分层请求至少包含共同模型基线、用途/表示、目标分区/对象、边界策略、页预算、
预期源/选择/父视图引用。对未知能力明确返回 unsupported，不静默退为首 N 条。

新响应需包括：

- 各记录流的声明总量、已返回量、独立续页游标、完成状态及未展开子分区数量。
- 固定分页视图引用；游标绑定源、选择、用途、表示及过滤器。重试同一页幂等；
  错游标、源变化和失效游标返回明确错误，不能拼接不同修订。
- 子分区展开引用包含预期共同基线。初始子请求即校验，不能到全部下载后才发现漂移。
- 跨分区原始连接及显式边界端口，保留原始两端身份和未加载原因。未下载、过滤排除、
  源缺失、歧义是不同状态。重复边界记录用稳定 ID 去重。
- 聚束或折叠对象的完整成员总数及有界成员读取引用；显示聚合不能被当作一条原始线路。
- 对象级缺口和来源引用；大缺口集合单独分页，不在每页重复巨量质量数组。

已有节点/边独立偏移及 `expected_view_ref` 可继续兼容。新端口等独立流需要
各自的游标/总量，或明确的页内闭包规则，不能让客户端误判首屏端口不全为源缺失。
源坐标可选，需声明 geographic/single_line/schematic、来源与版本；gateway
无需为此实现客户端布局。100K+ 总量不要求每次进入视图全部下载。

## 7. Capstone 可立即实施的兼容最小范围

无需等待新契约即可开展下列工作，但必须保留当前数据能力上限：

1. 复用模型/范围发现及本 Attempt 已接收的源视图请求，移除固定区域作为通用行为。
   总览仅作为导航选项，电气拓扑指令进入设备接线；不以附件或会话名称代替用途。
2. 用现有 `equipment + station:<ID>` 请求验证并读取站内源接线闭包；保留源版本、
   电压选择及外部线路边界。旧 station 设备清单不冒充接线图。对不支持该组合的
   gateway 明确保留旧图/提示能力不足，不默默全量下载所有站。
3. 新增纯源接线投影，保留 `source_connection`、`line_terminal`、
   `winding_membership` 的不同语义。使用已有源端子 ID；设备与连接节点间只有
   原始关系时，保留该关系及质量，不构造源端子角色。
4. 在 worker 中做局部母线导向正交布局：母线条为长条锚点，按真实连接设置馈线
   通道、开关及绕组图符。无母线条的部分保持连接节点示意，不凭高连接度造母线。
   跨线不加接点；相同连接节点才有接点。缺失接线设备进入明确未接线区域。
5. 扩展共享 scene、折线几何及逐段拾取/裁剪，保持原始 ID、详情、搜索、相机、
   任务聚焦及历史重放。发电机/负荷使用对应符号，但不补源中没有的导线。
   大范围做有界分区布局，局部细化，不对全网运行精细正交全局优化。
6. 保留既有 IEEE39 小图及计算 Authority 路径。新增图是源接线表示，不能升级
   数据准备度，也不自动导入或替换正式计算模型。

主要落点：后端 `grid_source_topology.py` 保护性投影；前端 `gridSource.ts`、
`GridSourceWorkspace.tsx` 的分层读取；新纯接线投影与局部正交布局模块；
`networkScene.ts`、`networkSceneIndex.ts`、`networkScene.worker.ts`、
`networkWebGL.ts`、`networkSymbols.ts` 及相应聚焦测试。
当前 `networkStationLayout.ts` 是站点矩形分区和 BFS 排列，并非电气单线布局。
当前 `loadGridSourceView` 会读完选择范围的全部页面，并不等于完整的按层按需下载。

## 8. 联合验收与交付条件

| 用例 | 必须核对 |
| --- | --- |
| 两个不同登记模型 | 同一发现、用途选择、读取和布局组件运行；无 North 名称/ID 特判 |
| 单/双母线及母联 | 母线条身份、隔离/断路器端子、真实连接节点；无按状态未知值归并 |
| 两/三绕组变压器 | 设备/绕组/端口构成一致；未知侧角色保留；归属线不冒充导线 |
| 接地开关、负荷、发电机 | 原始接线与中性状态；缺接线对象可查，不生成假连接 |
| 缺失/多值端子与跨站节点 | 有明确缺口及冲突；不任取端点、不强行归站、不虚报完整 |
| 并行线路及交叉线 | 稳定原始 ID、成员数/详情/逐条选择；视觉交叉不表示导通 |
| 跨页、跨区及下钻 | 端点/成员最终一致，边界有来源；原始 ID 跨层可追踪 |
| 刷新、重试、源变化 | 同修订可恢复；版本变化拒绝拼图；相同页不改变记录内容 |
| 四种用途 | 共同源/模型基线可核对；阻塞潮流仍可显示源拓扑；潮流通过不自动宣布优化就绪 |
| 100K+ 层级场景 | 首次不全量预取；有界页面/分区/布局/绘制/拾取；逐层显示原始总数与完整度 |
| 实际模型复核 | 对照保存的源端子/关系验证单线图，并完成真实指令、下钻、选择和刷新 |

性能验收记录设备/浏览器、源及视图版本、下载字节/请求数、首个可交互时间、
局部布局耗时、帧耗时分布、内存（可测时）、搜索和拾取延迟。分别测有坐标与
无坐标路径；合成 120K+ 压力样本只补充容量证据，不替代实际接线与可读性验证。

gateway 交付应提供版本化 schema、工具发现记录、可复现请求/脱敏响应、能力与
缺口清单、跨页/跨层版本测试及兼容说明。Capstone 独立验收对应契约、布局和
真实使用路径。任何尚未提供的字段、尚未通过的准备度及未测容量都须明确记录。
