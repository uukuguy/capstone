# 交付 data-gateway：省级电网接线、预热缓存与业务定位

日期：2026-10-27。状态：用户已确认产品方向；本文是网关协作需求与验收提案，
不是接口已发布或功能已完成的声明。由 data-gateway 项目实现网关部分，Capstone
实现消费与交互；本文不修改 data-gateway 仓库。

## 1. 本期目标与优先级

优先提供区域、省级及局部厂站的**源电气接线展示**，让查询设备、统计电源、
查看设备资料等业务结果能联动定位。典型省级范围先以北京电网验证。

由网关预构建、预热少数常用范围，其它范围首次请求时从数据库构建，之后复用。
使用同一套范围解析、构建和版本机制，不为每个省开发单独接口或客户端组件。
潮流模型、边界等值和求解接入放到后续，不作为本期接线展示的门槛。

本期三项主要交付：

1. 可发现、可打开、可逐层下钻的省级源接线范围。
2. 网关拥有的典型范围预热、其它范围按需构建及版本化缓存。
3. 业务对象和统计成员到图中实际元件的准确定位依据。

## 2. 责任分工

| 事项 | data-gateway | Capstone |
| --- | --- | --- |
| 范围与身份 | 解析源业务对象、目录归属、模型范围及边界，返回准确引用 | 根据用户任务选择返回的范围；不拼造省级 model_ref/target |
| 构建与缓存 | 数据库读取、结构索引、预热、并发合并、版本更新、失效和资源管理 | 请求、显示进度、按需读取；浏览器仅保留已加载图形和视图状态 |
| 电气结构 | 提供设备、端口、连接节点、实际连接、构成关系、边界与缺口 | 统一图例、布局、缩放、分层、选择与高亮 |
| 业务联动 | 提供对象到模型元素的可核对身份、范围及读取/定位入口 | 查询结果点击、统计下钻、局部图加载、定位及资料联动 |
| 数据可信度 | 保留源版本、选择口径、时效和质量；未知值不补造 | 展示这些限制，不将目录归属解释为实时运行连接 |

模型缓存的正确性由网关负责。Capstone 不直接访问数据库，不复制一套网关模型
构建器，也不以浏览器缓存判定源数据是否更新。

## 3. 优先复用现有电气视图 v2

本次捕获的实际契约中，v1 支持 model/station/device；v2 声明支持
model/grid/station/device/summary_edge/unresolved，且提供
`summary_nodes`、`summary_edges`。这说明省级下钻可能可复用已有 grid 目标。

请先验证：区域或国网 v2 概览能否发现北京电网对应的 grid 节点，是否返回可用的
`expand_target`，以及下钻结果是否满足下述范围、接线和身份要求。如果已有，
直接发布验证结果并由 Capstone 适配；不要求另建“北京模型”工具或重复的模型 ID。

现有模型清单的区域/组合入口，不等于所有省级范围已经完成构建。此前一次 v2
试验只取得 preparing，尚未验证北京 grid 目标。因此本文不将省级支持列为已完成。

下文描述**信息要求**，不是要求使用同名的新 JSON 字段。优先复用现有工具、
版本和返回引用；实际调用参数必须通过 MCP 自描述发布后才能由客户端使用。

## 4. 省级及其它子范围的语义

### 4.1 业务范围不是行政区名称筛选

“北京电网”首先是源系统中的业务对象及目录范围。应通过准确对象引用识别，
而不是按设备名称含“北京”、地图行政边界或编码前缀筛选。

范围解析至少说明：源实例、业务对象身份、所属/包含关系、范围定义版本、成员
选择规则，以及是否包含本级对象、下级目录、跨界设备和外部边界。
行政区、调管范围、资产归属和电气连接范围有差别时，保留各自含义，不能合并为
一个未说明的“全省电网”。同名或多义对象应返回候选，不自动任选一个。

省级、地级、厂站通过通用范围机制处理。模型根、grid 分组、厂站和设备引用可以
不同，但网关应明确它们的转换或下钻关系；客户端不自行推导引用格式。

### 4.2 展示范围与边界

- 提供省级概览，再按厂站或已核准分组下钻，不要求首屏下载全省全部元件。
- 概览站点聚合边只用于导航；展开后可读取其实际线路成员，不能称为电气等值。
- 设备图保留母线、开关、变压器及绕组、线路及端子、连接节点等真实记录。
- 明确区分端口—节点连接与变压器—绕组等构成关系，后者不是导通边。
- 跨省线路保留完整身份、已知端点和外部边界引用，不因对端在范围外删除线路。
- 局部闭包不递归扩成整个连通网络；缺接线、未加载、被筛选排除和外部对象分别表达。
- 电压门槛须可发现并明确展示。区域概览的默认筛选不应被默认为省级全电压或完整站内接线。
- 选中变压器时保留其已知绕组及必要依赖，不因初始电压筛选静默丢失低压侧。
- 设备存在但无接线时，仍可返回设备资料和明确缺口，不补画虚构线路。

## 5. 网关预构建与缓存

### 5.1 典型范围预热

预热名单是网关运维配置，首期建议北京电网及少量实际常用范围。配置引用网关
解析后的稳定范围身份、展示表示和选择策略，而不是写入 Capstone 的省名分支。

预热应使用与按需请求相同的构建器及缓存身份规则。预热失败只影响相应范围，
不能阻止网关启动、轻量发现或其它已缓存范围的访问。优先预热概览、分组目录及
定位索引；局部细节可按实际成本继续按需物化，无须把所有图形布局预生成。

### 5.2 未预热范围

首次请求先解析准确范围并检查缓存；命中则复用，没有可用缓存则建立有界任务，
快速返回准备状态与后续查询引用。相同内容身份的并发请求应复用同一构建任务，
避免多个用户重复扫描同一数据库范围。

状态应区分排队、构建中、可读取、失败和失效。说明当前阶段、可查询状态的引用、
建议查询间隔及是否可纠正后重试。客户端不会因等待而反复提交同一构建请求。

### 5.3 缓存身份与修订

缓存必须区分至少以下维度，具体如何组成索引键由网关实现：

- 数据源/租户及适用权限范围，防止不同连接或授权范围复用不该看到的内容。
- 已解析业务范围和成员选择规则的版本。
- 源数据捕获身份及内容修订；连接地址、名称或单独时间戳不能代替内容身份。
- 表示、选择 profile、电压筛选、边界策略及结构转换规则版本。
- 契约/数据结构版本；分页或局部切片还需绑定准确父视图、选择和游标。

同一个冻结视图的分页、下钻和定位必须使用同一基线。新版本完成前保留可用旧
版本；发布时原子切换“最新”入口，不能让读者看到半成品或混合新旧记录。

已有会话在声明的有效期内可继续使用其冻结版本。过期或被回收时明确返回错误
及重新打开方式，不能把同一 view_ref 偷换成新内容。客户端不会跨版本拼接分页。

### 5.4 更新和资源管理

- 明确缓存命中、构建/捕获时间、当前是否陈旧、失效时间和源一致性声明。
- 数据库变化通过可用修订、发布批次、变更检测或明确的刷新策略触发新版本；
  未建立变更检测时应承认时效未知，不能将命中缓存称为实时数据。
- 显式刷新生成新捕获；旧视图与已有任务不应因刷新被静默修改。
- 未证明源事务一致时继续标明未核验；本期不强制实现跨表强一致快照。
- 配置缓存容量、TTL、并发、队列和处理预算；回收优先考虑未使用版本，不能
  无提示回收仍承诺有效的引用。管理操作不由普通业务查询自动触发。
- 局部读取、后续分页和定位不能每次重新扫描全网；应复用网关侧结构与反向索引。

## 6. 查询结果到电气图定位

### 6.1 单个对象

业务查询已有 `object_ref={source_instance,object_type,object_id}`。部分查询另有
`source_evidence.table/key`；电气记录已有 `source_ref` 的源实例、表和对象身份。
请明确二者可使用的匹配条件，优先复用现有身份，而不是要求客户端猜测类型到表的映射。

一次定位所需信息包括：

1. 准确业务对象引用及适用源/模型版本。
2. 候选模型或 grid/厂站范围；同一对象可能存在于多个模型范围，不能强行一对一。
3. 可打开的局部目标/展开引用、待高亮的实际元素身份，以及定位依据。
4. 未加载时的有界读取方式，不要求客户端下载十万级元件后逐项找对象。
5. 多义、版本不匹配、范围外、未提供接线和对象不存在等不同结果及下一步建议。

若已有 source_ref 与 expand_target 足以完成上述操作，请通过 MCP 契约给出明确
组合规则，无须新增专用定位工具。若不足，再提供通用、批量有界的定位能力。
网关返回业务与模型引用；不返回 Capstone URL，也不承担浏览器跳转或布局坐标。

Capstone 优先在用户当前视图中定位准确匹配对象；需要打开其它范围时使用网关
返回的候选和展开引用。不能只按 object_id、名称或“第几行”关联，也不能将目录
对象强制定位到一个同名计算母线。

### 6.2 统计分组与成员

统计结果点击后应先取得**同一范围、同一口径、同一版本**的成员清单，再分页显示
或批量定位。需保留统计分组键、去重规则、准确总数、当前返回数及继续读取方式。

当前一个重要差异：`summarize_region_resources` 按电厂主分类去重，
`list_power_resources` 使用可重叠的电源子类型。不能把后者直接当成前者的成员，
否则会出现统计数量与高亮对象不一致。请提供同口径的可分页成员入口，或通过
自描述明确如何用现有查询能力得到该组的准确成员。

大量成员只返回有界批次或服务端选择引用；批量定位同样有预算。未定位成员和
原因保留在结果中，不能只显示成功部分并声称覆盖整组。对统计快照与当前图版本
不同的情况明确返回冲突或重定位条件，不自动跨版本关联。

## 7. 通过 MCP 自描述交付

所有可用范围、层级、缓存状态、版本规则、输入来源、分页、定位组合条件及错误
恢复方式应可通过 initialize、tools/list、discover_gateway、describe_gateway_contract
等当前发布机制发现。本文件是研发交接材料，不能成为运行时必须预读的说明书。

沿用标准 Result 的来源、质量、完整性和错误表达；next_actions 是建议，不是固定
调用顺序。省级能力未实现时返回准确状态，不回退到全华北结果冒充北京。

请网关交付时标明：复用的已有接口、新增或扩展的正式 Schema、兼容范围、实际
发布版本、北京验证回执，以及其它范围的按需构建示例。Capstone 在发布后适配。

## 8. 分阶段验收

| 阶段 | 场景 | 验收要点 |
| --- | --- | --- |
| A：范围与现有 v2 | 发现华北/国网中的北京 grid 并打开概览 | 引用来自网关；范围/电压/边界明确；不存在省名硬编码或静默全网回退 |
| B：热点预热 | 预热北京，再多次打开同一选择 | 命中同一内容身份，不重复取全源；记录实际响应时延、读取量和缓存命中 |
| C：冷请求 | 选择另一个未预热且实际支持的省级范围 | 及时返回结果或作业引用；并发相同请求合并；失败可诊断，不盲重试 |
| D：局部接线 | 下钻厂站、母线、变压器和跨界线路 | 真实端口/节点连接保留；未知开关状态和缺口显式；全程同版 |
| E：业务定位 | 从设备资料点击准确对象 | 找到正确范围与图元；同名对象不串联；未加载对象按需读取 |
| F：统计联动 | 点击某电厂主分类统计组 | 成员与原统计同口径、去重和版本；分页总数正确；未定位原因可见 |
| G：版本与异常 | 源更新、刷新、过期、任务失败及版本冲突 | 新旧引用分离；不会混页、换内容、补造接线或将错误解释为空数据 |

性能验收分别记录冷准备、暖打开、分页和定位的耗时与规模，避免用暖缓存表现
代替冷请求。建议本机联调以暖打开约2秒内、冷请求约5秒内返回作业确认作为
初始交互目标；这是待实测校准的目标，不是已达成指标，也不要求5秒内构建完整模型。
对大范围不能在同步调用超时后才让客户端知道正在构建。

Capstone 的业务指令验收将在 Vivaldi 工作台中新建会话可见执行，连续指令留在
同一会话。后台工具只作技术诊断和数据核对。首先验证北京目录/查询与接线定位；
不把目录测试通过当作省级电气图通过，更不算潮流验收。

## 9. 本期不要求

- 不要求网关绘图、生成屏幕坐标、编写业务分析结论或执行潮流求解。
- 不要求为所有省份提前构建缓存，也不要求为每个省单独注册一个实现。
- 不要求补造缺失的开关位置、电气参数、历史状态或连接。
- 不要求同时完成潮流边界等值、优化模型、强一致数据库抽取等后续能力。
- 零碎文案和非阻塞细节先记录，优先交付可发现范围、可用接线、可复用缓存和准确定位。
