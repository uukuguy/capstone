# 业务工具组合优先

用户确认：业务数据访问优先使用已发布MCP工具的合法组合；高级数据探索用于未覆盖的必要操作，或有已观察记录的疑似工具缺陷。正常缺测、参数错误、分页和返回限制不自动等于工具缺陷。契约矛盾或合法路径不可用可以据实报告，不要求盲目重试。

本地联调实测暴露了原策略的缺口：只限制原生 SQL，不能保证业务工具组合优先。通用结构化表查询同样可能替代本应使用的业务操作。本轮发布68个工具，却执行154次通用表查询、53次失败；未尝试曲线、运行统计和气象专用工具。此事实不证明未尝试工具在该实例均有数据，也不证明全部通用查询都多余。

选择指导补充如下，并在应用任务上下文、工具检索和工具激活入口提供，不新增模型评审调用：

- 按当前业务操作和发布语义选择工具，不按熟悉的通用查询参数选择。已知契约可直接复用，不强制重新发现或固定调用顺序。
- 适用的业务工具及其合法组合优先。结构化表查询和原生 SQL 均是必要操作未覆盖、或已观察到疑似工具缺陷时的补充；说明缺口或保留失败引用。
- 单个工具的未配置或不可用仅作用于其声明的能力范围。目录检索不可用，不能推出对象、曲线、统计和气象访问均不可用；检查有关替代能力，不遍历探测全目录。
- 参数错误先按精确契约纠正。超时后依据发布的计划、约束或返回建议改变路径与选择；仅修改行数或扩散为大量近似查询不算有效进展。无合理修正时保留缺口，推进其它可完成部分。
- 新参数结构先用一个有界调用验证业务状态，再组合独立且已验证的调用。共同契约错误出现后停止该批次，不能逐对象重复同一错误。

上述是智能体当前推理循环的选择指导，不是将通用表查询隐藏或一律拒绝；现有结构化高级探索准入仍仅适用于发布标注的`readonly_sql`组。Capstone不从工具名称猜测新的强制准入类别，不引入表、地区或指标专用路由。本次修改不依赖网关新增接口；只有后续实测证明发布语义不足时，才提出独立契约改进。

Capstone按已发布`_meta["data-gateway/toolset"]`呈现工具组并支持组内检索。在相同检索匹配范围内，普通发布操作排在高级探索之前，不隐藏高级工具，不更改网关Schema。网关适配器将其已发布的`readonly_sql`组解释为高级探索；不依赖固定SQL工具名，也不维护问题、模型、表、列、指标或索引映射。其他业务工具组之间不设固定顺序。

高级工具激活和组合程序入口共享选择规则。调用方在同一次选择中提供`advanced_exploration`：`reason=capability_gap`与必要操作说明，或`reason=tool_defect`与说明、工具名及真实观察引用。引用须匹配本任务已返回工具的记录；缺陷是否成立仍是智能体判断，不增加独立模型校核或用户审批。普通业务访问不需要这份声明。权限、停止条件和工具契约不改变。

任务内引用索引只记录工具与引用身份，不保存业务内容；成功通过宿主回执验证的网关调用登记call ID及原生观察别名，组合调用登记实际返回的program-call引用。不同任务不共享索引。未覆盖说明也是模型声明，不认证覆盖结论；旧任务引用不因字符串相似而自动准入。

声明随原调用保留，疑似缺陷和高级探索给出可见警告。失败的工具原因在对应节点的折叠详情外显示，后续成功不删除原错误。申请阶段标为申请；取消不解释为成功。程序失败仍保留路径声明。告警文字受现有凭据过滤和私有路径过滤约束。

网关拥有业务查询实现和性能，库侧拥有索引维护。SQL例外读取当前`describe_data_table.index_use`；Capstone不复制实例索引，也不将网关内部SQL计作智能体自行编写SQL。

验证先覆盖动态工具改名、普通操作直达、两类例外、伪造/错属引用、组合入口、失败/取消告警及原回执不变；再从Vivaldi新会话使用新MCP连接跑完整迎峰度夏。验收核对调用构成、每次SQL选择依据、工具缺陷记录、产物与耗时；单轮完成不代表稳定提速或研究质量接受。
