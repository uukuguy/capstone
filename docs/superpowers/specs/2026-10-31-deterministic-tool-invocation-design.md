# 通用工具调用校验与诊断修复方案

状态：用户已确认继续；实现候选通过相关本地检查，运行环境验证另记。

## 目标与边界

基于新疆消纳率会话的七条失败，修复过小且分散的工具容量约束、可确定校验的调用错误、
保存上下文错误和不可读诊断。Capstone 负责通用机制；网关负责业务标识、可用性和语义约束。
所有名称与合法值来自当前会话冻结发布、当前实例响应和已注册接口。
固定网关入口只属于 MCP 适配器，执行器不增加固定业务工具、表名、字段或路由。
不启动 CI，不新增重试任务，不引入额外语义注册系统。

## 方案比较

1. 只改上限到 1024：改动小，但 24,000 字符契约限制仍存在，错误标识和诊断问题也不解决。
2. 推荐：集中容量配置、按上下文预算加载契约、复用返回动作与引用、统一调用前校验和错误投影。
   能在现有动态发现链上实施，且不需要猜业务含义。
3. 为全部业务字段建立独立语义注册系统：覆盖面大，但要重复网关已有契约，当前不采用。

## 容量

工具激活数量默认 256，可配置为 1024 或适合部署的更大值；它是容量，不是权限。
只能激活该任务冻结发布允许的工具。工具总数、单轮模型菜单、契约体积、调用次数、
并发数和结果预览分别配置，不能共用一个数字或整体乘倍数。

当前确认的限制：

| 位置 | 当前值 | 处理 |
| --- | --- | --- |
| general-tool-discovery：工具数量 | 8，含常驻入口 | 改为集中配置，默认256，可配置1024；模型看到的剩余容量与实际校验一致 |
| general-tool-discovery：契约字符 | 24000 | 移除独立硬编码限制，服从实际模型上下文与请求体预算；超出时返回具体维度和可处理动作 |
| 工具搜索 | 每页8项、每项描述240字符 | 参数化分页与摘要；摘要不能代替完整契约，完整说明必须可按需访问 |
| tool-result-context | 预览6000字符 | 保留完整结果引用；摘要提取不能破坏错误结构，不以扩大预览替代按需读取 |
| progress：失败显示 | 头100+尾497字符 | 截断前提取结构化原因；原始结果不变 |
| tool-composition-policy | 每程序64次、并发4、输出32768字节 | 独立审查并记录用途；不能因工具菜单扩容就自动提高外部请求并发 |
| application-capacity | mcp_call_count1024、context_references4096等 | 已有较高独立容量；检查实际消费者，不能仅按数值认定过低 |

实施时扫描直接消费这些配置的限制和常量，并记录范围、单位、来源、溢出行为。
256/1024 工具承载测试不能用真实业务调用放大流量；使用生成的动态发布契约做本地测试。
实际 Provider 对工具数量/请求大小的约束要作为独立兼容条件核对，不能声称所有模型都支持1024个同时输入。

## 精确调用：代码能保证什么

所有入口统一进入当前任务的身份解析与参数校验。SDK 直调、组合 tools.call、
加载和网关契约查询共用发布身份映射。未知名称只给诊断，不自动做相似名称替换。
参数名、类型、必填、枚举和禁止额外字段遵循原 inputSchema；接口未禁止额外字段时，
Capstone 不擅自收紧网关契约。组合内置函数同样校验结构与引用。

对返回中已带工具及完整参数的动作，提供通用的“选取返回动作并执行”路径：
从受控观察引用和 JSON pointer 取得动作，按当前发布做名称、参数、实例、版本和授权校验，
参数从原观察复制，不要求模型重写 table_ref、游标、版本或函数名称。
模型仍负责业务选择；动作属于异步链时沿用网关等待和终止约束。

表名/字段名若在 inputSchema 中只是 string，JSON Schema 只能证明它是字符串，
不能证明数据库中存在。优先使用原响应中的动作/合法值；对模型新组合的业务查询，
仅在网关已给明确机器可读合法值或引用约束时做本地成员校验。
没有这类约束时由网关权威校验并返回具体字段位置，不能通过拼接命名规律伪造确定性。
不把“本次没有发现”自动等同“权威目录不存在”，尤其是搜索结果分页或不完整时。

## 声明表与物理表

当前目录已有 readable、physical_registered、data_availability 与 next_actions。
模型没有照返回动作执行是已知调用错误；确定执行返回动作可以避免重新抄工具名和表名。
但选择哪个业务意图仍需要模型。网关契约应明确声明结构工具与物理结构工具的适用条件。
如需在调用前拒绝选错工具，必须有网关提供的通用可机读前置约束，不能在 Capstone
写死 describe_source_table 或 readable 的业务路由。
第一阶段沿用现有动作并补充清晰错误，不要求新增完整语义注册体系。

## 统一诊断与保存恢复

从完整 MCP 包装中提取 status、error/gaps、request_id 和已有参数校验细节后，
再做保护信息过滤与展示长度限制。中立字段覆盖错误来源、原因、参数路径、
是否执行、重试条件和原始诊断引用。缺失字段保持未知，不能捏造 executed=false。
前端展示短句与定位信息，不要求用户解析嵌套 JSON；保留受控的原文展开入口。
保持既有旧记录兼容，不能声称只修新事件就能恢复旧摘要的中间内容。

saveContext 在查引用前验证 datasets[i].call/pointer，错误直接指出字段路径；
保留已成功子调用及来源引用，以便保存失败后恢复，不隐式重跑整个程序。
模型提交的 value 数组不能被当作来源可信的观察数据。

## 网关协查

沿用协查稿内五个 request_id。需要确认 -DATE 的拒绝位置及排序契约、声明表拒绝信息、
发现 contract_revision 与错误 guidance.contract_revision 的版本范围。
补充具体错误字段路径与合法值来源；不要求兼容错误表名或新增工具别名。
确认当前实例能否提供指定年份新疆十月的消纳率数据；没有接入时明确数据缺口。
仅有 declared_only 不能推导出真实业务记录总数为零。

## 验证与交付

只做受影响模块的本地检查：256/1024规模动态工具目录、数量与字符预算、身份/参数拒绝、
原动作参数保真、未知引用、成功子调用后的保存失败，以及真实已保存 MCP 错误投影。
涉及后端执行源变更时按仓库入口统一重建一次，再复用现有浏览器标签验证可读诊断。
不跑发布或完整仓库套件，不推送以触发 CI。生产功能实现前先确认本方案。
