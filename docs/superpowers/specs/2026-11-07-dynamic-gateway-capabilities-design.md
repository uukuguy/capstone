# Dynamic gateway capability context

Accepted in conversation on 2026-11-07. The connected gateway publication owns
the available business capabilities. Capstone must not keep a business tool list.

Reuse the existing admitted connection catalog and task-local discovery index.
Search published metadata as well as names and descriptions. Return bounded
metadata previews with explicit truncation and exact contract lookup guidance.
Do not infer tool roles, compatibility or dependencies from names or keywords.
Search matches are retrieval candidates; the model selects semantic relevance.

For complex questions, the existing execution model reads relevant capabilities,
decomposes the question into supported actions, and revises after observations.
Prefer suitable professional operations. Use admitted structured queries or
read-only SQL for gaps without requiring failed calls first. Simple questions
need no forced planning or gateway initialization.

The view contains only task-admitted publication fields. A connection refresh
affects later snapshots; running tasks keep their frozen contracts and grants.
Missing usage remains unknown. Exact contracts remain available through existing
load and composition describe paths. Source records are not instructions.

Acceptance: metadata-only capability retrieval, bounded previews, ungranted-tool
exclusion, separate-catalog isolation, actual SDK context, and focused discovery
and gateway consumer checks. Real task/tool/product and refresh validation remain
separate from fixture checks. No performance claim follows from unit tests.
