# Gateway contract context reuse

The user requested the measured follow-up optimization. Existing professional
capabilities remain dynamically published by the selected gateway.

Keep a bounded connection-local cache of successful exact tool-contract sections.
Only the MCP adapter recognizes the agreed contract-lookup protocol. Business
observations, jobs, datasets, errors and unverified identities never enter it.
Bind entries to the full admitted publication revision and returned contract
revision. Changed publication clears future reuse; late old-task responses cannot
populate the new cache. Connection objects isolate instances and credentials.

At task admission export only sections for tools in that task's grant, and only
when contract lookup itself is granted. Stage read-only JSON files in the private
task workspace. Inject a compact index with tool/section/revision/path/hash, not
all schemas. The model reads needed cached sections locally and requests only
missing published sections. Files are capability metadata, not live health,
business results or Authority evidence. No fixed business tool list is introduced.

Bound aggregate cache/export size by the existing history-context byte budget;
evict oldest entries and fall back to normal contract lookup. Cache failure must
not change the returned business observation. Existing task files remain frozen.

Acceptance: exact metadata survives the next task; grants, instance and revision
changes prevent reuse; errors and business observations are excluded; size is
bounded; actual SDK context and staged files work. Repeat the same real two-turn
trial and record contract reads, JSON bytes, model responses and elapsed time.
Do not infer speedup from cache hits or byte savings alone.
