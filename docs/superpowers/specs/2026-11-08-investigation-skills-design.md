# 调查技能设计：已接受基线

状态：2026-11-08 用户接受；尚未实现、预装或部署。

## 技能职责

| 技能 | 职责 |
|---|---|
| brainstorming | 澄清目标、观察角度与成功条件；明确请求直接执行，不强制问答 |
| task-planning-and-tracking | 整合 writing-plans 与 planning-with-files；统一计划、依赖、预算、分支、进度与恢复 |
| systematic-debugging | 对执行失败、异常返回和证据矛盾开展调查、假设与最小验证；不将业务异常直接解释为软件故障或确定根因 |
| verification-before-completion | 阶段和最终交付前核验来源、覆盖、可比性、算法前提、产品与结论限制 |
| data-investigation | 分层探索、选择基线、提出备选解释、安排对照与反例；依据新增信息和成本选择下一项观察 |
| data-quality-and-comparability | 核对身份、来源、单位、时区、采样、缺口和可比性；判断分析前提并记录限制 |

模型根据当前指令、上下文、描述和授权选择技能，不设固定首步、关键词路由或必须经过全部技能的流水线。

## 统一状态与执行显示

六个技能共用现有任务记录和私有任务工作区。保存目标、计划版本、依赖、发现、假设、支持与反证、质量限制、预算、选定不可变引用、任务状态、停止原因及恢复条件。不另建平行账本，不将大文件装入模型上下文。

调查计划与 Provider 的探索计划、计算计划及任务引用分开。确定依赖可以预先编排；依赖观察结果的分支在读取结果后由模型决定。

执行记录按实际事件展示技能名称、版本、加载、公开应用阶段、关联工具及产品、结果和恢复。加载不证明流程完成；模型报告的阶段标明来源；验证通过须关联真实检查。不要求输出内部思维链。记录须持久保存并支持刷新和继续执行。

## 宿主边界

技能提供方法。宿主及网关适配层负责引用类型、版本与归属校验、预算计数、分页边界、禁止重放和显式异步推进协议。技能不扩大权限，也不替代 Authority 计算或证据准入。

请求完成、任务完成、数据完整和结论成立分别核验。相似不等于因果，未找到不等于不存在，样本发现不外推为总体规律。

## 服务总线组合覆盖

依据 data-gateway/docs/integration/服务总线Provider设计逻辑与组合使用指引.md 第四章：

1. 运行概览：有界分层选样，兼顾常见、低频和边界时段，记录未知总体及未探索范围。
2. 变化调查：明确度量与可比基线，结合绝对和相对变化；贡献分解须有互斥可加关系证据并保留残差。
3. 历史匹配：核对连续单对象窗口、距离模式、历史候选覆盖，以背景和反例复核，禁止由形状相似推出原因。
4. 长程调查：显式推进任务，保存每批输出和预算；恢复前核对实例、环境、契约、引用及任务状态，不隐式重发未知源请求。

服务总线专属工具、参数和限制保留在按需加载的 Provider 指南，不写入通用技能或 Kernel。已有 epri-investigation-orchestrator 示例仅作素材；其旧探索工具名须对照实际发布契约修订后才可接入。

## 后续实现与验收

先检查已有技能管理、加载、任务状态和过程投影入口，再制定执行计划。验证须覆盖按需选择、统一计划修订、真实工具关联、四类调查、质量不足、预算停止、断连和刷新恢复。离线检查不能代替真实模型、执行和产品验收。

本设计不授权 CI，不改变既有候选分支的集成或部署状态。CI 仍须逐次明确批准。
