# 大资源范围读取与恢复：首期设计提案

上位要求：[企业设计第9节](2026-10-15-enterprise-design-final.md#9-企业文件资源与任务上下文2026-10-18-用户确认)。文件容量、上传配额、处理预算和模型上下文预算必须分开。首期不代表企业大文件要求全部完成。

## 方案比较

| 方案 | 收益 | 限制 |
| --- | --- | --- |
| A：复用上传，增加有界范围读取和持久回执（建议） | 小片段任务不必先复制整个文件；直接复用分片存储、冻结授权和现有执行器 | 需扩展应用内部资源请求/回执契约，不能宣称完整分析可恢复 |
| B：只补验现有整文件打开路径 | 改动少，可先整理环境证据 | 少量读取仍承担整文件传输/复制成本，范围覆盖仍不明确 |
| C：一次建立通用流式解析/索引平台 | 同时处理长文档和大表局部定位 | 范围过大；解析、索引和业务处理检查点应分别设计验收 |

选择A作为首期提案。保留现有 agent_resource_open 和隔离原生工具；模型按当前任务选择范围读取或整文件处理，不强制固定第一工具，不按业务关键词路由。

## 用户闭环

用户在现有工作台上传或选择一个已发布资源，提出只需部分内容的问题。模型按需请求确切范围，宿主返回已校验片段及来源回执。模型保存明确说明取样范围和限制的报告。刷新和服务重启后，资源、已确认读取回执与报告来源仍可恢复。取消或读取失败保留此前可用内容。

不新增文件管理页、会话类型或第二套任务生命周期。原有上传/续传入口保持不变。复用现有来源详情与成果预览；覆盖描述优先使用精确字节范围，不把字节位置自动解释为页码或业务行号。

## 所有权与契约

- 仅用于应用拥有的通用原生执行路径。专业 Domain Pack 不取得文件路径、shell或新增资源权限；不改变 Kernel、Authority 和当前运行证据规则。
- 请求只接受已冻结授权目录中的 resource_id、版本/哈希身份、非负 offset、正 length及幂等请求身份。宿主从已准入契约推导实际来源；拒绝任意路径、URL、对象键和跨Thread访问。
- 每次请求、累计读取、返回文本和保留片段分别采用显式可配置预算；预算不成为文件容量上限。范围越界、整数溢出、版本变化、取消及I/O超时机械拒绝。禁止静默截断成功。
- 复用现有 API/worker/原生执行器受保护控制通道与 ResourceUploads.read，按相交分片校验。仅为此范围准备私有只读片段；不触发整文件暂存或复制。工具的名称和具体传输字段在实施计划中与现有发现机制核对，不能重复注册同义工具。
- 回执绑定 Thread、Attempt、资源完整身份、请求范围、实际返回范围、片段摘要和保留内容引用。返回内容有界；文本解码状态明确。二进制或UTF-8边界不能伪装为完整文本；只读片段路径由宿主生成，不能由模型选择。
- 已确认读取和必要片段随现有持久存储保存；同一Attempt的精确重试返回同一接受结果，不重复计量或扩大授权。跨Attempt复用必须重新经过现有显式输入准入，不从模型历史自动扩大范围。源失效或回执缺失给出准确状态。
- 回执表示“返回了这些字节”，不表示模型理解、计算完成或业务结论正确。展示已读范围及未覆盖范围；摘要和报告仍是派生成果，不成为Authority事实。

实现不得仅依赖模型提示来执行权限、版本、范围、预算、续读指令或回执一致性检查。来源内容始终是数据，不是系统指令。

## 首期接受

1. 在当前本地部署上传或复用一个超过1GB的真实持久测试文件。测试内容和期望值由验收端保留，不把答案注入模型。不使用稀疏文件的声明尺寸代替实际传输证据。
2. 读取首部、中部、末部及跨上传分片边界的范围；内容与验收端逐字节一致。记录实际存储I/O、传输字节、内存和临时磁盘占用，证明小范围读取未触发整文件复制。历史性能数字不代替本次测量。
3. 通过真实PostgreSQL验证原子接受、并发精确重试、取消、重启恢复及源失效后的已接受回执恢复；跨Thread、伪造版本/摘要、越界与非法预算均拒绝。
4. 真实模型选择范围读取工具，保存一个准确标注取样和未读部分的报告；浏览器查看来源，刷新/切换后恢复。原资源摘要及已有成果不变。
5. 规范本地重建、API/worker同源、范围缓存维护和受影响消费者检查通过。任何CI单独申请批准；dev集成和远端发布分开。

真实调用若仍选择整文件处理，记录实际行为；不能将整文件打开结果记成范围读取验收。需调整任务场景或修复实际能力接缝，不能在模型答案中伪造工具使用。

## 复核结论

已核对复用上传、资源身份和原生执行边界；不把上传能力误列为缺失，不把读取回执误列为业务处理完成。首期限定范围读取和读取恢复。字段细化、迁移兼容测试和定向门禁在用户复核后进入实施计划，当前不声明已实现。
