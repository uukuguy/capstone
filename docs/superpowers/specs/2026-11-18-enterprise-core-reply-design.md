# Enterprise core reply

An open model in the enterprise model workspace is part of an instruction's
accepted context. Freeze the model context ID, model revision, selection
revision and enabled Domain Pack versions with the Attempt. The unified
reasoning chain receives those identities and the host grants the selected
Pack's published tools. The Authority retains the model data, calculations
and evidence. Opening a calculation context inside a gateway tool has that
tool's scope. The application workspace owns model selection across turns.

The main conversation shows a concise core reply alongside its execution
preview. The right-side reader shows the complete committed answer and its
execution record. The core reply is presentation text about that same
answer. It does not carry separate result or evidence references.

For a new enterprise instruction, the final answer composition requests
both the formal answer and a short synthesis of its conclusions,
key values and units, material limits and the name and purpose of products
created by the instruction. Use the existing answer-bundle format
where the execution path supports it. Keep the two strings distinct in
admission and persistence. A summary must describe the admitted final
answer. If answer admission changes or replaces the answer, discard an
earlier summary.

An older record without a committed summary offers the full-answer
reader directly. Reading or refreshing a session does not generate a
summary, submit a command or create an Attempt. Existing conversation
reading controls keep their current behavior.

Verify a real grid instruction in the enterprise route. Compare its
one- or two-sentence core reply with the formal answer and current-run
results. Verify that replay restores both texts by Attempt. Cover an
older record, an invalid summary and a failed or cancelled Attempt.
