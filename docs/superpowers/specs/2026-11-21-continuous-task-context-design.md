# 持续任务上下文与三级执行设计

状态为设计基线。产品实施与验收按[工作计划](../plans/2026-11-21-continuous-task-context.md)逐包登记。

## 用户契约

会话建立时即具有任务上下文。即使还没有明确目标、Work 或制品，初始状态也有效。上下文贯穿会话，逐步积累当前关注的对象、已接受的方向、未决问题、观察、约束和可用制品。目标是可选内容，可以形成、修订、搁置或并存。Work、Attempt 和制品修订记录具体事项与执行；单个 Work 的生命周期不能代替整个会话的上下文。

用户指令可以新增问题、纠正事实、改变优先级、切换关注点、暂缓事项、索取阶段制品，也可以只是询问现状。每轮先结合已有状态理解这句话影响哪些事项，再结合当前授权的数据与工具环境推理、反馈或执行。已知且获准推进的未决事项可在委托范围内继续；待用户决定、暂缓或依赖不可用的事项保留其原因。未决清单本身不构成自动执行授权。纯询问保留交互记录，已有业务状态可以不变。

完成和交付均注明范围，例如“已解释原因”“华东数据已核对”“阶段表格 v2 已交付”。可以先交付一个可用版本，再由用户决定深入、改向或开始另一件事。一次回复结束、某项目标达成、暂时没有可执行工作，都允许会话停在可继续的状态。用户明确结束或归档时才按对应生命周期操作处理。

会话可以从自由 Instruction 开始。问题、讨论对象和已有资料即可形成上下文，目标和完成标准允许为空。用户可以结束讨论，也可以沿用它继续办事。同一会话可以处理旁支和不同任务。任务引用与会话身份分别保存。

同一目标可用三种机制完成。普通输入沿用当前交互语境；新委托默认 Instruction。只有用户明确选择才启动顶层 Goal 或 Mission。工作量、耗时、关键词与工具数量均不能触发升级。

| 机制 | 执行责任 | 结束依据 |
| --- | --- | --- |
| Instruction | Harness 在一次指令内持续推理、调用工具、压缩和恢复。自由提问可直接回答。 | 正式答复、适用的交付与缺口已保存。 |
| Goal | 主会话 Agent 自行规划并执行多轮 Instruction。每轮依据新事实调整下一步。 | Agent 根据最新目标和校验条件给出结论，由应用核验绑定并归档。 |
| Mission | 主会话组织者可独自执行，也可建立子会话。每次委派独立选择 Instruction 或 Goal，按需混用。 | 组织者核对总目标、可用子交付和剩余缺口，在主会话统一交付。 |

## 上下文记录与所有权

capstone-agent 复用 Work、Attempt、消息和制品记录；capstone-control 拥有 Mission 计划、委派与组织者复盘。App 读取有界投影。沿用领域 Authority 的版本和证据准入。普通工具产物保留自身来源。

每个上下文版本包含稳定任务引用、版本及前版、来源会话和事件边界、执行机制、当前工作区授权引用、用户方向和约束、校验条件、已完成与待做项、缺口、活动执行绑定、制品与证据引用。字段按需填充。每项指导和结论可定位到原消息或真实执行。历史大文件按版本引用，按需限量读取。

复用同一权威写入方。消费操作带预期版本、操作身份、执行代次。原子提交新事实与待执行意图，重复消费返回原处置。旧代次结果可留存，须按最新约束复核才可进入交付。模型决定行动及业务含义；服务检查授权、版本、引用、状态转换与副作用去重。

## 推进、干预与结束

接纳用户输入、工具返回、子交付或恢复回执后，先保存事实，再判断下一项可执行工作。允许同一句话同时改变方向、边界和校验要求。在普通查询进展时回答当前状态，主线继续。修订目标时标记受影响的后续计划并继续。插入非主线指令时先冻结 Goal 续派位置，再运行旁支；在途结果保留原绑定。`/goal resume` 基于最新有效状态恢复，同一条命令重放只派发一次。

工具不足时检查工作区已安装资源及授权替代路径。用户可自行配置；具备授权时 Capstone 可通过既有 managed-resource 契约安装、加载、验证确切版本。记录安装回执、实际加载和成功使用。越权步骤只影响其依赖项。独立步骤继续。截止、预算耗尽、持续无进展或无法取得关键资料时，保存可用工作并明确结论。归档、交付程度（完整、部分或无法完成）及用户意见分别记录。无需用户例行确认。用户主动暂停、停止优先于待派发步骤。

## 压缩、崩溃恢复与跨会话继续

自动压缩按执行上下文预算触发。保存摘要的来源区间、生成版本、未决操作和原记录引用。每次装配从持久记录重载当前有效约束、授权和校验项，防止重复压缩丢失要求。摘要不得创建证据或扩大权限。压缩失败时保留前一有效恢复点，优先装配当前必需记录。

关键边界增量保存。发出副作用前持久化操作身份，返回后绑定回执；会话正常结束时保存最后位置。异常退出从最近提交恢复。对未知结果先查原操作；无法证明安全重试时保留诊断并继续独立工作。禁止凭超时再次发出非幂等动作。

新会话显式加载获准版本，按目标会话权限重新解析资源与证据。历史回看和已有的版本化交接继续可用。若用户要接管仍在执行的同一任务，建议采用单一有效执行代次，通过条件写入转移推进权。原会话保留历史和回看能力。独立派生任务使用新身份。刷新页面仅恢复阅读与订阅。

## 主会话呈现

复用企业工作台的输入框、正式答复、成果区和执行详情。自由问答直接回复。Goal 展示当前方向、已交付、正在做什么及下一步。Mission 在同一位置增加可展开的委派、依赖和局部缺口。每次指导显示实际影响；结束时逐项链接校验结论和产物。当前摘要从持久记录计算，刷新后可重建。使用已完成事项表达进度；无可测分母时不显示百分比。用户仅在主会话交流，无需填写任务表单或进入子会话操作。

## 2026-11-25　以任务上下文推进单轮指令

本节补充执行与验收设计。既有 Instruction、Goal、Mission 的选择和推进责任沿用上文。现场样本及对照动机见[核心能力研究记录](2026-10-07-capstone-core-evolution-discussion.md)。

### 从实际读写定位缺口

当前 TaskContext 保存 Work 绑定、目标修订、快照、模型、资源引用和可选的 task_state_ref。Work 结算按 Attempt 保存当前和前一状态引用、执行结果、待决项及可选的 business_report；沿用旧报告时保留 business_report_source。这个来源字段对于判定报告是否适用于新口径很重要。Attempt 完成只证明本轮执行结束。沿用的报告需要结合来源版本、输入和本次要求重新判断适用性。

首轮审计在同一条实际任务链上逐轮对照：受理前任务版本 → 送入 Pi 的指令、上下文及可读取引用 → 工具请求、回执和来源版本 → 结算后的状态、产物及用户可见回复。优先查找“已保存但没有装配”“模型可见但无法定向读取”“已有结果却重复派发”“本轮已经满足却继续成文”四种现象。通过真实请求和事件判断，遇到材料缺失就记录未知。

### 每轮如何执行与结算

1. 受理时读取当前会话上下文和事件边界；涉及已有 Work 的变更再绑定该 Work 与预期版本。无明确目标的讨论可直接继续；切换任务、选定历史版本或明确接管遵循已有入口。一个 Thread 可包含多个 Work，同一会话不能单独证明任务相同。
2. 装配当前有效的用户约束、待决项及相关引用。事实由拥有它的应用、Domain Pack、Authority 或制品存储提供。大型结果按引用限量读取。本轮需要的业务对象或指代无法唯一确定且选错会改变结果时，只询问该处歧义。
3. 已有确定性操作由宿主执行，例如取当前任务状态、查既有回执、返回已保存制品。其余由现有模型轮次结合当前任务解释用户意图。一个输入可以同时修正约束、提出问题和要求交付；无需给每条消息附加分类器、规划轮次或新的模式选择。
4. 模型提出要改变的业务条件和所需动作。服务核验工作区授权、预期版本及引用归属。领域契约明确支持的数据覆盖、口径、版本和依赖关系可以用代码判断；关系未知时记录缺口，必要时定向补查。不得仅凭文本相似、工具名相同或同一实例就复用结果。
5. 输入受理、约束生效、操作派发和新结果可用分别记录。中断期间仍可区分当前要求、最近有效产物及其适用条件。只读询问可留消息和 Attempt 审计记录；业务约束、目标和产物引用保持原值。每条指令有可见答复，简单确认可直接使用宿主回执，专业应用原有输出契约继续生效。
6. 本轮取得足以支持用户所问的结果即可结算。已委托的 Goal 或 Mission 按其已有机制判断是否继续。主栏呈现变化、依据或阻塞，细节可展开；用户要求正式交付时再汇总全任务的结论、适用限制和产物。

| 情形 | 宿主应保留的事实 | 下一轮可采取的动作 |
| --- | --- | --- |
| 从全国改看华东 | 新范围、数据快照、已有数据的覆盖与粒度 | 覆盖充分则从已有引用筛选；只有全国汇总时补取所缺明细 |
| 阈值从 80% 改为 85%，重算超时 | 已接受的 85%、旧结果按 80% 计算、未结算调用标识 | 查回原调用；明确显示新口径结果待确认 |
| 只改标题或询问一个数字 | 当前制品版本或该数字的来源、单位及时间 | 修订目标制品或解释该项，保留无关结果 |
| 旧计算在改向后返回 | 原调用、所用输入及修订、返回结果 | 保存为原修订的结果；按当前要求复核后才可进入最新交付 |
| 用户刷新、重复提交或撤销授权 | 已受理命令、回执、当前权限和事件游标 | 刷新恢复订阅；重复提交复用回执；读取历史材料复核现有权限 |
| 普通工作中插入调试旁支 | 原主线位置、调查范围及证据引用 | 调查结论保存在旁支；用户要求应用结论时，再把获准引用带回当前任务 |

### 实施顺序与决策门槛

第一步对照已有读写，形成一张真实链路记录。第二步先做 Debug 追问切片：询问上轮失败时按授权读取原事件，回答失败位置、编号和可知原因。生成复现材料由明确的交付要求触发。第三步在普通企业任务上验证“查异常 → 缩小范围 → 改阈值 → 解释一项 → 出报告”。再加入中途改向、响应丢失和刷新。第四步根据对照结果决定是否调整通用提示和正式回答契约。只有在现有记录无法表达一项必要事实时，才给拥有该事实的契约增加字段，并定义旧数据的未知值。

在相同数据快照、授权、模型及最终交付判据下比较。硬性验收包括最终报告同时满足两次修订，失效数据不会进入交付，未知结果不会重复派发，原产物可追溯且重载后状态一致。效率记录包含首次有效反馈及最终交付耗时、模型轮数与 token、必要和重复的网关调用、漏算、重算和人工纠正。分别报告简单追问和复杂交付。样本不足时只报告观察值；质量与恢复验收通过后，再依据基线决定能否推广。


### 连续会话的验收样例

从“看看昨天的数据有什么值得关注”开始，不要求预填目标或完成标准。发现两处异常后，用户说“先看华东，第二处留着”，再索要一张阶段表格，然后插问数据更新时间，最后要求继续第二处。验收应在同一会话逐步观察到：两个独立未决项；第一项被选中而第二项仍可恢复；表格带有生成时的范围和版本；插问得到有来源的回答且未改变原有优先级；恢复第二项时沿用有效资料并重新核对已失效的来源。期间可多次交付，每个阶段都可停止等待新指令。衡量指标增加从改向到有效反馈的时间、未决项丢失或错误续派次数、恢复后重复取数次数。仅在用户明确委托完整交付时才评价整项目标的完成时间。

### 单条指令的执行力度和停止条件

沿会话执行链判断本轮应达到的状态。分别考虑用户希望现在取得什么、已有状态还缺什么、判断或操作出错会影响什么。重要问题可能只需读取一条权威记录；一句很短的口径修订也可能让多个已交付结果失效。默认由已有推理轮次理解指代与范围；不为每次输入增加分级调用、固定配额或用户表单。

| 同一条会话链中的指令 | 本轮足够的结果 | 何时需要加深 |
| --- | --- | --- |
| “第二处先放着” | 保存暂缓状态，确认第一处仍是当前关注点 | 有在途操作时，说明已派发部分和仍可停止部分 |
| “这个数从哪来？” | 指向当前表格中该数的来源、时间和口径 | 引用缺失、过期或口径冲突时，做针对性核对 |
| “看看可能是什么原因” | 用已有观察区分有依据的解释和未知项，给出能区分关键假设的下一步 | 用户委托定位根因，或当前证据不足以给出任何有用判断时，按授权进一步验证 |
| “把阈值改到 85%，先看看影响” | 保存新要求，核对受影响项并返回差异；旧表保留原口径 | 原始粒度不足或有依赖项无法重算时，记录影响边界 |
| “按这个口径出正式报告” | 完成指定范围的覆盖、版本、证据和制品核验，交付可用版本 | 关键依赖缺失时，区分已能交付的部分和仍受阻的部分 |

执行力度允许随观察调整。一个局部问题已由有效记录回答就停止；发现矛盾只扩大到足以区分该矛盾的检查。旁支发现可记入未决事项。只有当前判断依赖它、用户已委托继续或已有执行授权明确覆盖时，才继续派发。涉及权限、证据真实性、版本一致性和重复派发的检查始终由宿主执行。主栏反馈以本轮发生的变化为准，必要的完整过程保存在记录中。

成对验收同一问题的不同要求：对“先看有无异常”和“定位原因并交付复验材料”，前者应在能回答有无及覆盖范围时停止，后者应完成相应证据链；对“先放着”和“继续查”，前者应无新增探查，后者从保存的位置续作。同时检查过度执行与提前停止，不能用调用次数少单独判定成功。
