# 浏览器研发调查与离线复验

整体方向已接受。本文为实施前契约草案。Capstone 应用负责调查，data-gateway 负责内网服务适配与网关诊断。实施分支 feat/browser-debug-investigations，目标 dev。

## 浏览器与服务端

复用企业会话、输入框、执行过程、制品和恢复机制。在输入框选择调试时显示目标环境和调查名称。只有用户主动提交且位于指令起始处的独立 /debug 命令进入调试路由。代码块、引用、工具返回、历史文本均作为数据处理。服务端对未知子命令返回用法，不降级为普通任务。开发环境默认开放调试，沿用已有 Thread 和工具授权。正式部署在服务端关闭调试。公开演示凭据仅可用于脚本样例。

|命令|语义|
|---|---|
|start 目标|建立调查并启动首轮，可附选中的同工作空间 Attempt 或调用引用|
|run 指令|在指定调查启动后续轮次，继承调查目标并按当前权限执行|
|status|读取调查状态、已用预算、当前调用和开放问题|
|stop|禁止继续派发，等待已派发调用结算，未知结果显式保留|
|compare 两条引用|并列显示版本、参数、数据时间范围、观测及不可比项|
|report|按环境策略生成报告和最小复验材料|
|replay 用例引用|重新校验授权及当前契约，创建独立轮次；契约不兼容时记录差异|
|close|封存已结算调查，保留授权查阅；活动轮次需先停止或完成|

每个写入携带幂等请求标识、调查引用和预期版本。持久化调查与任务关联后再派发；重复提交返回原回执。并发追加或停止按版本结算。任务恢复沿用已有 Attempt 租约，派发结果未知时先查原请求。普通指令继续走原入口。调查选择随工作空间、会话与用户恢复，不能跨会话隐式继承调试身份。

## Pi 调查能力

以已有 data-investigation、systematic-debugging 和 data-quality-and-comparability 为基础，补充服务探索、跨层定位和复验设计。加载按当前问题、工具描述与授权选择。Pi 可直接利用原回执，也可在限定调用次数、耗时、结果量及并发数内做多轮对照。一次改变一个需要区分的条件，记录可推翻假设的观察。结果分为可引用事实、判断、未知项。预算耗尽仍交付已有工作。

应用为 Pi 发布有界的调查记录读取、观测比较和复验用例保存操作。精确业务能力从当前网关发布契约发现，只读试调通过现有 MCP 适配器。脚本只处理私有任务空间的准入样例；用于现场取数的身份由网关持有。普通调查制品与 Authority 结果分别按原有规则保存。

## data-gateway 研发交接

请网关维护方以现有 diagnostic_mcp、diagnostic_reader、diagnostic_summary 为基础，核对哪些字段和读取操作已经对受权客户端发布，提供版本化契约、允许与拒绝示例、兼容范围和离线包标识。优先复用现有操作名。只在缺失时扩展。Capstone 在 data_gateway_mcp 适配器中完成名称与协议转换。

- 从受认证主体和绑定推导可见范围。task、run、trace、request ID 用于关联；客户端填写的诊断元数据不能充当授权凭证。
- 支持按当前调查关联请求读取有界回执。含网关实例与版本、能力契约身份、请求身份、阶段、状态、分页或截断及允许公开的错误原因。未观测到的阶段保留未知。
- 异步请求提供状态查询与明确的续查指示。处理请求完成但响应丢失、事件重复、部分响应和取消未知。排除凭据、原始 SQL 参数、任意日志读取及越权业务数据。
- 给出只读服务发现、参数解释、只读试调的公开契约。服务操作及目标由授权目录确定。网关内部实现、总线写入和发布仍由现场管理。
- 联验样例含成功、partial、unavailable、超时、截断、跨工作空间拒绝、旧网关缺少诊断能力。旧网关仍支持原有业务调用，调查报告标出不可见阶段。

## 回放、离线交付和验收

### 调查使用的双仓源码

Capstone 研发镜像携带两仓的只读源码及版本索引。调查优先按该次执行记录的 Capstone 和 data-gateway 部署身份分别选择源码。调查历史故障时沿用故障发生时的版本。索引将已知镜像或发布标识映射到仓库、精确源码版本和内容摘要。现场无法观测或匹配某侧身份时显示待确认，可手动选择参考版本。

浏览器允许独立切换两仓的阅读版本。选择保存在调查内，并随源码引用和候选补丁记录；并行调查可以阅读不同版本。实现按不可变版本读取文件，服务进程继续使用其部署版本。验收覆盖两侧版本不同、历史回看、手动切换、缺少匹配版本和两项调查并发读取。

保留调查 ID、原 Attempt、每轮请求与结果引用、软件及契约版本、对象和时间范围、观测判据与导出策略。固定数据按快照复验；动态数据比较契约性质。历史诊断曾出现模型通信等待约 300 秒、网关调用并发以及嵌套 span，耗时展示应标注模型、网关和源端，并区分墙钟时间与累计耗时。详见 [迎峰度夏联合诊断](../../reports/2026-10-30-data-gateway-joint-diagnosis-handoff.md)。

受控区默认保留完整回执，外带材料按部署策略生成与审查。分别登记两个产品的候选与回滚版本。安装后浏览器核对真实运行身份，针对同一用例创建新记录。失败时保持原始用例和既有制品可读。

验收覆盖普通消息隔离、直接 API 越权、重复提交、并发停止、重启恢复、跨工作空间引用、契约变化、预算耗尽、脱敏导出及禁导出。最终在受控主机通过浏览器完成真实问题调查、对照、报告、离线更新后复验。单侧模拟结果只用于开发回归。首先由两侧核对读取授权、版本发布和复验样例，之后分别实现并在共同契约上联验。
