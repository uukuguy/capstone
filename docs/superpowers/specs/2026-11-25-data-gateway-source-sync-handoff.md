# 给 data-gateway 的研发交接：按运行版本同步调试源码

## 本次请求

请在每次 data-gateway 发布时，将该构建对应的调试源码包随服务部署，并通过当前已认证的 MCP 连接提供按摘要读取的能力。Capstone 在连接或刷新会话网关时自动补齐本地缺失的源码。这条链路需要支持受控主机离线运行。调查绑定、回执和日志继续沿用 v1。

## 请 data-gateway 交付

1. 沿用 MCP initialize 中的 `capabilities.experimental["data-gateway/identity"].source_sha256` 作为运行源码标识。请用实际部署产物生成源码包，覆盖本机发布和离线容器各自的源码。两个产物分别以各自的真实握手摘要为准。
2. 在握手中声明版本化的只读源码获取能力。请回传正式的能力名、资源或操作名、Schema 和合成样例。Capstone 按声明发现契约。源码获取使用后端服务主体，并服从网关的源码读取授权；请明确所需权限和拒绝语义。
3. 读取请求指定完整的 `source_sha256`。响应清单绑定该摘要、包格式、包字节数及包文件的 SHA-256。请说明源码摘要的计算规则，以及包内文件清单和文件校验规则，供 Capstone 校验入库。交付内容限于获准共享的发布源码和配套清单，排除凭据、业务数据和运行日志。
4. 通过同一网关连接提供有界读取，明确单次大小、分页或分块、结束条件和中断重取方式。一次传输的全部内容须属于同一个不可变包。若读取 A 时网关已升级到 B，可以继续提供 A；若 A 已不可用，返回可识别的版本缺失结果。请区分无权限、版本缺失和暂时不可用。

## Capstone 负责

按当前 Thread 的实际连接重新握手，查询本地持久化源码库。命中则复用，缺失则获取指定版本，校验完成后原子入库。传输失败时保留缺失状态；若网关已换版，重新握手后再选择版本。浏览器和 Pi 使用后端授权的源码读取入口。历史调查保存当次可确认的版本，缺少历史摘要时标记未知。

## 联验

| 场景 | 验收结果 |
| --- | --- |
| 同一 Thread 切换两个网关实例 | 每次取所选实例的握手摘要，读取对应源码。 |
| 保持同一 Thread、端点和软件版本，将源码从 A 升到未缓存的 B，再回滚 A | 刷新后自动取得 B，回滚后复用 A；全程无需人工导入、重建或重启 Capstone。 |
| 首次读取缺失版本 | 有权限时自动补齐，再次查询命中；权限不足时显示原因。 |
| 分块传输中升级、中断或校验失败 | 不发布残包，不混用 A/B 内容，后续刷新可恢复。 |

请提供可用于联验的 A/B 两份合成包及其握手、清单、读取成功和错误响应。当前本机联调参照为发布 `20261125-offline-source-identity-v1`，软件版本 `1.1.0`，实际握手摘要 `dc1fdca53c369ba5e60eb887999e489940080e95004ca02513be2a92ef05584f`。现场容器以自己的握手为准。
