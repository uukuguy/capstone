# 给 data-gateway 的会话调试证据交接

Capstone 在受控主机上按会话生成离线调试包，供研发环境复现和定位。Debug 分页直接下载当前会话的包，并按时间展示历次补查证据。主会话的 `/debug` 触发 Pi 补查，范围覆盖整个当前会话。下载包的生成无需启动 Pi。

## 先复用当前契约

Capstone 通过实际连接声明的调查绑定、日志、渐进发现和发布身份接口接入。网关继续认证专用服务主体、检查绑定和调用归属。Capstone 核验工作空间和会话，并在后端保存绑定，浏览器和 Pi 只使用受限代理操作。

调试包需要保存与 Capstone 执行事件对应的网关回执、日志投影、调用契约版本、网关实例和实际发布身份。每项材料只按网关声明的外带规则输出。会话涉及多个发布时，按调用发生时的版本分别登记。请保留 `client_call_id`、网关 `request_id` 和版本等已获准的关联字段。回执未查回时，交接包记录「网关结果未知」。补查原调用只读原记录。

## 请网关侧协助核实

1. **普通会话调用查回。** 确认普通业务工具调用如何在派发前登记可验证的归属，以便 Capstone 在会话包下载和补查时按授权查回。同一故障用例需要验证响应丢失后仍能用原 `client_call_id` 取回结果、跨工作空间或绑定读取被拒绝，以及查询原回执不会派发业务。请说明当前发布能查回哪些普通会话调用。若只支持已登记的调查调用，请指出缺口、建议接入点及新旧版本的行为。
2. **现场数据信息补查。** 请指出当前工具目录中可按需读取数据目录、结构、来源、口径、覆盖范围、查询元信息和最少样本的入口。Capstone 从实际 MCP 发布读取精确 Schema，并在会话补查中使用已获准的只读工具。每次补查保存实际实例、发布和工具契约版本、查询范围及网关回执。若现场发布与原调用不同，补查结果作为当时的观察登记。
3. **外带规则与缺口。** 请按回执、日志、工具契约、查询元信息、统计和样本分别确认可外带范围、脱敏方式、保留期限、裁剪及缺失状态。现有日志契约仅允许外带状态与裁剪标志，逐条日志留在现场。若这种投影不足以支持复现，请明确缺少的关键证据，再讨论需要补充的脱敏投影。网关未声明授权时，Capstone 在现场保留材料并在下载包记录缺口。

请回传已发布的正式操作名、契约版本和 Schema 路径。优先提供可复用的合成样例，覆盖授权成功、未声明、查回未知、日志裁剪、跨绑定拒绝和旧发布缺少能力。现有契约支持的部分，Capstone 会先完成接入。

## 联合验收

本机握手已确认普通业务凭据未声明调查绑定。专用调查凭据声明了绑定与离线证据 v1，但离线外带策略仍是 `undeclared`。请为合成用例提供一个保留原业务授权范围并声明调查绑定的测试连接，并确认该测试部署可启用 `allow_sanitized`。Capstone 将在原连接上登记和派发，避免通过专用调查身份扩大业务读取权限。授权关闭的场景仍使用当前配置验证缺口。

双方选同一故障、同一会话事件范围、同一输入版本和同一组服务发布。在线调试先保存首个可确认的异常阶段、责任侧、已确认原因、关键证据和复验结果。

- 研发人员仅用下载包和包内记录的版本独立定位和复验，关键结论与在线结果无实质冲突。
- Pi 通过 `/debug` 在现场独立补查。关键证据可追溯，能支持与在线调试一致的异常阶段、责任侧和已确认原因。获准材料可从 Debug 分页单独下载，也能随新版会话包交付。
- 记录或授权缺失时，清单应给出具体缺口。缺口阻止独立验证关键结论时，该用例验收失败。双方据此确认由哪一侧修复。
