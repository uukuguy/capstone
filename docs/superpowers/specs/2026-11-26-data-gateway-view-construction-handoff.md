# 给 data-gateway 的研发交接：通过 MCP 指导智能体构建业务视图

## 请求与分工

请让连接当前网关的智能体能回答三个问题：这个视图应该表达什么业务含义，当前发布支持怎样实现，用户决定执行后怎样验证和交付。请先盘点已有目录、工具说明和契约能回答哪些问题，再补齐缺项。本文是 Capstone 的接入需求，具体资源、操作名和 Schema 由 data-gateway 确认。

Capstone 结合连续会话识别本轮意图，例如比较方案、验证一个疑点、创建试点、修改已有视图。data-gateway 提供当前授权范围内可信的业务含义、实现约束和操作效果。Capstone 根据这些信息决定何时回答、何时需要用户选择、何时执行。网关在执行时继续核验权限和参数。

## 构建视图时需要哪些指导

| 设计问题 | 请网关提供的依据 |
| --- | --- |
| 已有什么可以复用？ | 可发现的现有视图及其适用对象、来源、版本、输入、输出粒度。说明何时可以直接使用，何时需要另建定义。 |
| 选哪类视图？ | 对当前发布支持的各类视图说明适用场景、可变维度、保存时固定的维度和限制。例如对象时序与记录切片各自能表达什么。 |
| 哪些条件应该成为参数？ | 对对象、地域、指标、口径、时间窗等维度说明业务角色和组合约束。区分调用方可选、定义固定、依对象自动解析和待业务方确认。列出必填条件、默认值及省略后的实际范围。 |
| 如何解释结果？ | 说明行代表什么、对象键、单位、时间粒度、聚合规则，以及来源、覆盖范围、缺测与空结果的含义。注明跨对象、跨来源合并或比较的前提。 |
| 怎样验证和保存？ | 声明准备、只读校验、样本查询、持久保存、运行已有视图各阶段的前置条件、副作用、可复用引用及有效范围。注明校验覆盖哪些条件，哪些只能运行时确认。 |
| 遇到限制怎么办？ | 区分契约明确不支持、当前授权不可见、元数据未声明、样本超时和数据缺失。给出有依据的替代方式与适用条件，保留尚未验证的部分。 |

## 示例：一个入口查询各省网的同一指标

用户先讨论各省网的同一指标，继而提出统一视图。Capstone 可以直接建议将省网作为调用参数。网关需要说明当前视图形态能否绑定该参数。如果原生时序视图固定对象，应明确这个限制。应用按省网选择底层视图可以作为设计选项，其覆盖和映射仍需单独验证。

同一指标在不同省网使用不同源编码时，若网关有权威映射，应按对象解析，并能说明实际选用的来源。如果同一对象同时存在多个有效统计口径，选择会改变数值含义，网关应说明差异、适用条件和有无业务认可的默认值。只有一个适用口径时可以自动解析；需要用户选择时，Capstone 展示有意义的选项。映射或口径未知时，请显式标记。字段名称相似不足以据此合并指标。

如果省网参数省略后会查询全部授权对象，契约应明确该行为。面向单省的视图应能约束必填参数，或明确由调用应用承担这项校验。一次样本超时仅支持报告该次校验未完成；索引结构和原因需要独立依据。

## 如何通过 MCP 交付

请优先复用渐进契约发现 v1。在工具集摘要中给出适用范围和指导入口，在按需读取的使用说明中解释业务选择，在精确契约中表达类型、必填、依赖、效果和错误。跨工具共享的视图构建指南可由多个工具引用同一份版本化内容。随对象或数据源变化的事实应从当前授权元数据按需取得。无需给每次会话注入整份指南，也无需为此预设新工具名。

请声明指导内容与数据语义的适用版本、更新信号和授权范围。Capstone 按实例、授权视图和发布绑定复用已读信息；同端点升级、切换实例或授权变化后重新核对。旧发布缺少声明时，客户端仍可使用已发布契约，将未声明事项列为未知。

## 联验与回传

1. 用合成会话先问“各省统一查询能否以省网为参数”。智能体从指导和当前契约解释业务设计、原生支持与缺口；网关记录应显示本轮没有创建视图。
2. 同一会话继续要求“创建两个试点并验证”。复用仍有效的信息，按正式契约完成授权的保存与运行，核对对象、口径、实际参数、结果粒度和来源回执。
3. 用合成样例区分同义编码映射、同对象多口径及未声明口径；验证必填参数省略、无权限、空结果和超时在客户端可区分。
4. 用两个发布或授权视图验证指导随当前连接更新。旧缓存不能使智能体宣称当前网关支持已经撤回的能力。

请回传现有能力与缺口清单、实际发现入口、版本与失效约定、正式契约和上述场景的合成请求及回执。可以分别标出已发布、拟补充和需数据提供方确认的事项。Capstone 将据此接入并用连续指令验收。
