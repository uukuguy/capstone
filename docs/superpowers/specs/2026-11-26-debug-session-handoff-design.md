# 受控主机会话调试交接

## 用户流程

右栏 Debug 分页的「下载调试包」直接下载当前会话的交接包。服务端在收到下载请求时固定事件范围，从会话开始到当时最后一条已登记事件。生成过程不调用模型。主会话中的 `/debug` 用于补查证据，范围是整个当前会话。用户可以附上排查问题。

会话继续接收正常指令。已生成的包保持原范围。新问答或补查证据可以生成下一版，旧版本使研发人员能重现当时的上下文。主会话中的调试卡显示补查状态和结论。右栏 Debug 分页顶部提供「下载调试包」，下方按时间从新到旧叠放本会话每次补查的证据。每项可展开查看结论、证据引用、缺口和执行记录，也可单独下载获准的证据。下载会话包时同时纳入该边界内获准外带的补查证据。

## 包内容与权限

| 目录或文件 | 内容 |
| --- | --- |
| `manifest.json` | 格式版本、会话与包身份、事件边界、涉及的发布和源码版本、每个文件的内容摘要、缺口和裁剪状态 |
| `conversation.jsonl` | 按会话顺序投影已获准的用户指令与 Capstone 答复，保留问答标识、状态和关联文件引用 |
| `files/` | 获准且被选中问答实际使用或产生的文件，按交互发生时的版本保存 |
| `execution/capstone/` | 当前会话的执行事件、异常阶段和可核对的调用关联 |
| `execution/data-gateway/` | 按对应调用或调查绑定保存获准的网关回执、日志、工具契约和实际发布身份。保留关联标识、裁剪、结果未知和未获准外带的状态 |
| `repro.md` | 入口问答、可用的复验输入和版本、已有事实与缺口。没有结论时保留现象和可复验边界 |

文件候选来自已登记的会话输入和产物引用。允许用户取消选择或显式选择当前会话有权访问的其他版本化文件。历史文件版本无法解析、内容缺失、策略禁止或有记录裁剪时，清单记下具体原因。问答和文件也需经过对应的外带规则。网关字段继续由网关决定外带权限。下载时重新核验当前授权。授权范围收紧后，原包版本保持可审计，新的下载只交付当前获准的投影及匹配的清单。整个会话无权外带时，服务端拒绝下载。

网关材料按执行当时的实例、发布修订和源码摘要登记。会话用过多个发布时分别记录。服务端按已记录的调用关联和绑定读取，并用网关返回的外带授权裁剪字段；无法查回的调用保留「网关结果未知」。源码版本用于研发侧匹配。只有获准外带且能按摘要核对的源码归档才可纳入包。

网关回传确认普通会话可复用调查绑定 v1。Capstone 转发层须在只读调用派发前登记原绑定和客户端调用标识。收到响应时按现场授权保存正文。响应丢失时按原绑定和标识查回回执，正文缺失单独登记。旧调用无法补登记，旧发布缺少握手能力时记录查回不可用。

现有 v1 仅允许外带获准的状态、耗时和裁剪标志。调用标识、实例身份、操作名、错误码、逐条日志和业务数据保留在现场。包内使用独立编号与 Capstone 事件关联。能证明故障阶段和责任侧的脱敏分类及数据外带范围仍需双方确认。以实际契约声明为准。

网关回传建议增加独立、版本化的离线证据投影。Capstone 可按此方向接入，待网关发布正式 Schema 和外带声明后启用。投影字段包括组件、阶段类别、观测状态、错误类别及缺失和裁剪标志。类别使用固定枚举。没有结构化证据时保留未知。组件记录异常发生位置，责任侧由调查人员结合 Capstone 与网关证据判断。联验用同一次合成故障比较现场和离线结论。如果只能定位异常发生位置，清单要说明现有材料无法独立证明业务原因。

后端根据事件边界、版本化文件引用和补查引用登记包。会话历史按页处理，文件按已有对象或分块接口读取、增量计算摘要并写入私有临时存储，避免把大文件装入模型上下文、单个 JSON 或浏览器内存。包生成与下载分别显示状态，重复请求返回原构建回执。下载得到的精确成员与清单逐项匹配。离线导入校验格式、路径、大小和摘要，在私有目录打开已验证的文件。包内命令和脚本始终作为数据。

## Pi 补查

用户输入 `/debug` 时，Pi 在当前会话的固定事件范围内，以用户的问题和材料缺口为输入。应用授予现有只读工具，按需读取持久执行记录、匹配版本的源码和绑定网关回执或日志。受限网关复验沿用现有只读契约与请求登记。Pi 保存新增证据、对应引用和仍未确认的缺口。补查可以停止、续做或中途下载已有包，也可以完全略过。其执行过程不会改变普通会话任务状态。

补查可以向受控主机部署的 data-gateway 请求业务数据信息，例如数据目录、结构、来源与口径、覆盖范围、查询元信息和定位所需的最少样本。按调查范围选择已授权的历史实例或当前连接，并先读取该实例发布的工具契约。后端只派发授权范围内的只读调用，记录实际实例、工具修订、查询范围、回执和结果限制。连接或发布已变更时，新查询记录为补查时的观察，历史事实继续以原调用证据为准。写入和重新派发原业务任务不属于补查。业务数据留在现场，只有经对应政策批准的字段、统计或样本进入交接包。

### data-gateway 协作边界

- 优先接入现有调查绑定、回执、日志、渐进发现和已发布的只读业务工具。工具 Schema 和允许范围由实际连接声明。Capstone 负责会话关联、调查界面、证据包和验收对照。
- 网关侧共同确认两类覆盖情况。其一是普通会话的原调用能否按可验证的归属和关联查回。其二是现场补查需要的数据元信息和最少样本能否取得并获得明确的外带裁剪声明。实测有缺口时再补网关接口。当前日志契约只允许外带状态及裁剪标志，逐条日志只能现场读取。

## 实现接缝

- Capstone 应用拥有会话交接、包审批与浏览器投影。复用 `ThreadService.read_history`、执行记录分页、过程产物目录和版本化资源读取。现有问答投影还需核对输入与文件版本是否足够，缺失时读取对应事件或入参登记。
- 数据文件通过现有资源及产物授权入口解析。导出和下载流程增加会话交接的版本、许可与清单校验。浏览器通过受权下载入口读取包。
- 现有调查注册、冻结快照、Pi 工具和 data-gateway 绑定用于补查。旧调查和证据包继续可读，新入口直接创建会话交接版本。
- 复用离线证据校验思路，为会话交接格式校验成员和校验和。导入结果保留可定位的问答、文件版本、执行记录和缺口。

## 验收

以同一会话故障的在线调试结果为基准。三条路径使用相同的会话事件边界、输入版本、Capstone 和 data-gateway 发布版本。在线调试先保存故障现象、首个可确认的异常阶段、责任侧、可确认的原因、关键证据及复验结果。交接包和 Pi 补查各自独立完成后，再逐项对照。

| 路径 | 通过条件 |
| --- | --- |
| 下载证据包 | 研发人员仅凭下载包和包内记录的版本，在研发环境定位同一故障。首个异常阶段、责任侧、已确认的原因及复验结果与在线基准无实质冲突。 |
| 补查证据 | Pi 从现场运行环境取得可追溯的补充证据，定位到与在线基准一致的异常阶段和责任侧。已确认的原因有证据支持，补查结果可随新版包交付。 |

表述、步骤顺序和证据呈现方式可以不同。首个异常阶段、责任侧、已确认原因或复验结果存在冲突时，验收失败。权限或留存限制导致关键证据缺失时，记录缺项和原因。只要缺项使关键结论无法独立验证，该用例便记为未通过，并标明受限范围。两条路径均通过后，才算完成该故障的离线调试验收。

1. 在真实会话中从 Debug 分页直接下载，期间没有 Pi 任务。核对问答顺序、文件内容、版本和执行边界。追加一轮问答后再下载，核对两份包各自的边界。
2. 在研发环境导入，定位出错的输入、问答和对应执行版本，并用允许外带的原始或合成材料运行同一复验。验证大文件流式处理、篡改拒绝、跨会话拒绝和权限撤回。
3. 在有明确缺口的真实会话使用 `/debug` 补查，让 Pi 能读到最近一轮之前的相关证据。生成新版包并核对新增证据、原包身份及权限控制，验证补查停止时仍可下载已有材料。
4. 在受控主机用浏览器执行现场下载，在独立研发环境完成导入与复验。另用允许外带的网关实例核对两侧记录，用受限实例核对缺口标记。
