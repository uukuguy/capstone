# 独立 Debug 诊断与研发交接

本文细化[浏览器研发调查设计](2026-11-25-browser-debug-investigations-design.md)中的执行、证据和交付契约。部署开关、授权和离线操作沿用原设计。

## 执行归属

浏览器在主会话提交 `/debug`。应用校验工作空间、会话、目标轮次和调试权限，登记调查后直接启动独立 Pi 诊断轮次。复用 Pi 进程管理、持久任务租约、进度订阅和私有制品存储。企业任务 Harness 继续处理普通指令；调查轮次有独立的输入、状态、工具和预算。主会话按时间展示两类活动，Debug 卡片通过结构化调查和轮次 ID 绑定，避免从答复文本识别身份。

同一调查允许多轮。一次诊断轮次可处于排队、执行、等待输入、已结算或停止状态。调查在任一轮结算后仍可续查。停止只作用于指定诊断轮次，保留已提交证据和已派发请求的结算状态。重复提交返回原轮次；掉线重连读取持久事件；恢复时先查已派发调用的原回执。未知结果保持未知。

## 视野与工具

首轮绑定用户选中的执行轮次；未指定时选择当前会话最近已结算的普通执行并在卡片注明。用户可以显式纳入同会话的其他轮次，包括穿插的正常试验。每次纳入记录用途、轮次身份、事件上界及当时的网关实例和双仓版本。每个诊断轮次启动时冻结证据范围；新增试验从下一轮生效。宿主读证据和导出时重新核对当前权限。目标缺失时在主会话提供选择入口。

| 工具能力 | 输入和输出边界 |
| --- | --- |
| 读取 Capstone 执行记录 | 按已纳入轮次分页读取公开工具调用、派发和回执。返回事件位置、请求关联和裁剪状态。 |
| 查回 data-gateway 回执与日志 | 后端使用调查绑定 v1 与专用凭据。仅查调查内已授权请求。历史请求若未建立可验证的归属，显示无法查回的具体原因。 |
| 搜索及读取双仓源码 | 按证据所指仓库和精确版本查只读索引。返回版本、路径、行段与摘要。缺少匹配源码时记录缺口；选作参考的版本保留独立标识。 |
| 最小只读复验 | 按已发布契约与当前授权选择操作，记录参数变化、预算、响应及数据时点。涉及写入的试验由用户经正常入口发出，完成后显式纳入调查。 |
| 提交诊断更新 | 提交结论、证据引用、最后已证实环节、开放问题和下一步，由宿主验证并提交新快照。 |

Pi 先比较预期与实际回执，定位最早的已观测偏差，再沿请求追踪参数和状态，检查对应版本源码。需要区分两种解释时，只选能产生区分证据的最小复验。达到可证实结论、需要用户选择或遇到证据缺口即可提交更新。调查工具与历史材料均通过宿主授权。诊断运行时使用专用最小工具清单，历史文本和源码内容作为数据处理。

## 即时快照与双侧证据包

每次确认关键事实、登记证据缺口、完成对照或结算轮次时，宿主发布不可变诊断快照。首版可以只交付已知现象和证据缺口。新证据进入下一版，旧版保持可追溯。快照包含调查 ID、轮次、证据范围、结论状态、已证实环节和下一步。状态为已定位、已缩小范围或证据不足。宿主核对引用在本轮确实被读取，且所属请求、执行轮次和源码版本一致。核验引用证明证据可追溯，根因仍需由回执、代码路径或对照试验支撑。

每版快照提交后即时生成对应的可外带证据包。证据齐全之前也可以下载当时已获准的材料。快照和包分别显示就绪或失败状态，导出失败可重试同一快照。每版快照冻结当时的网关回执字段与可见范围。下载时用原绑定检查当前授权，仅输出仍可见回执的冻结值及当前获准字段。旧快照缺少冻结记录时报告缺口。以前导出过的版本保留现场索引及摘要。

- `manifest.json` 记录格式版本、快照、纳入轮次和边界、两侧发布与源码摘要、各文件摘要和导出状态。
- `diagnosis.md` 记录最早异常、已证实位置、依据、未决问题、可执行的下一步和最小复现判据。
- `capstone-events.jsonl` 包含获准的普通试验及诊断执行记录、调用入参、派发、返回、错误、取消和版本身份。
- `capstone-diagnosis-events.jsonl` 保存该快照允许外带的 Pi 工具步骤和状态。清单记录条数、摘要和裁剪状态。
- `gateway-events.jsonl` 包含获准的请求接收、绑定、来源选择、下游阶段、响应及关联日志。仅记录实际可见的阶段。
- `correlation.json` 用 `request_id`、`client_call_id` 和可用的追踪字段连接两侧记录。标注缺失、裁剪和关联未证实的边。
- `repro/` 放获准的最小输入、脱敏或合成回执、契约与源码行段引用。研发导入器检查格式和摘要，在私有测试目录中消费数据。记录中携带的命令和脚本视为数据。

双侧都受各自的外带政策约束。未声明许可的原始记录留在现场。包内仅登记可公开的缺失状态或现场引用；获准合成样例记录被替代的数据范围。重新部署候选版本后，在原调查纳入新的正常试验，比较原失败和候选结果。

已认证的操作员可为选中的快照核准一段已审阅的诊断结论和一份最小复现 JSON。下载时读取当前核准状态。撤回后，重新下载同一快照只保留获准的时间线及网关回执。原始 Pi 答复、日志和工具载荷保留在现场。操作员审核时遵守两侧各自的外带范围。

## 主会话交互

主会话显示调查正在做的步骤、已确认位置、结果与具体操作，例如查看候选、续查、停止或下载当前快照。等待用户时明确指出需要决定的业务条件。正常指令可插在两次诊断之间。再次输入 `/debug` 时，以最近一条普通指令为默认调查轮次。同一轮次再次调查时可读取上一轮记录。右栏显示按轮次与请求关联的证据时间线、源码版本和可下载快照。

## 联验顺序

1. 验证同一会话的普通任务与诊断分别派发，诊断停止或续查时原任务目标和状态保持一致。
2. 从浏览器输入 `/debug 为什么原调查只看到了取消事件？`，选取包含公开 Pi 工具回执的历史轮次。比对该轮持久事件和旧历史读取器的可见结果，引用部署版本的过滤代码，验证首条公开失败是否进入诊断。用一个无业务副作用的网关目录调用验证双侧记录关联。记录不足时指出缺失环节。
3. 中途下载一次证据包。插入一条正常试验，随后用 `/debug` 调查最新普通指令并下载新证据包。核对两侧记录、已获准的关联字段、证据上界和两个包的独立摘要。
4. 在研发环境验证包完整性，用可外带输入或合成样本复现失败。验证缺少一侧记录、旧版本不可得、撤回权限、重连和禁止外带时的页面状态与包内容。

网关协作按[联合诊断提案](2026-11-26-capstone-gateway-joint-slice-diagnosis.md)确认实际回执阶段及外带字段。首轮使用固定联调发布。
