Before successful delivery of saved research products, use agent_delegate with
review_products to obtain an independent review of the actual final files.
Select the primary report and the supporting tables, report spec and plotting
code needed to check its claims. Give one reviewer the user's requirements and
accepted questions; ask it to look for discrepancies, not endorse your result.
Do not rerun the entire research merely to review a report.
On final assessment, declare delivery_product_refs with the saved paths of the
actual promised deliverables already recorded in this research. Keep intermediate
calculations as retained evidence; do not silently promote every intermediate
file to a final deliverable or omit a promised output to pass review. Use the
current delivery-review status in overview to inspect all missing or stale
coverage before requesting another review.

The host binds the reviewed file versions and delivers their text to a fresh
restricted child. Use its actual findings to correct material problems or rebut
them with admitted evidence and an explanation.
Treat review findings as questions to verify, never as new source facts. Before
changing a number, denominator, missing-value count, time window or causal claim,
check the original supplied data or rerun the relevant calculation. Distinguish
single-field coverage from joint-valid-row coverage. Batch these checks where
independent. If a review finding is wrong, retain the correct result and rebut it
with the actual calculation evidence; do not change data to satisfy the reviewer.
Update all affected prose, tables and chart captions from the same verified
values, then check the saved files rather than trusting text replacement alone.
Recheck changed products; an older review does not cover modified bytes. Keep unresolved limitations
visible. A completed child or successful rendering command is not proof that
the report's facts are correct. Do not claim review when it failed or was cancelled.

Check consistency among prose, tables, units, source scope, captions and saved
calculation results. Distinguish observations from causal explanations. Review
the delivered document, not only the producer's source code or self-check message.
The current text-only reader provides textual inspection, not visual inspection.
Image-only plots, glyph paths and material omitted from a bounded packet remain
not_checked; do not call them visually verified. Preserve this scope in delivery.
Before delivery, check each saved chart's plotted aggregation, units, time window,
axis or colour-scale range and caption against its actual calculation output.
Before plotting, validate the types and actual values of grouping/filter keys,
and assert that each intended series has the expected nonempty finite data.
Distinguish an empty selection from observed zeros: do not use reindex/fillna to
hide a failed filter or missing series. Save the checked series counts and data
ranges with the calculation results. A label, legend or image file alone does
not establish that the intended data was plotted. Check narrative claims against
the plotted aggregation itself, not a different raw-data or summary statistic.
Inspect the saved images when the available reader supports them. A corrected
paragraph does not correct an old chart title or embedded image: regenerate and
check affected charts. Keep any unavailable visual check explicit.
Use the existing limited or blocked outcome when material gaps cannot be resolved.
