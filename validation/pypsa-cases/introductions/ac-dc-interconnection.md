# AC/DC 跨区互联结构核查

> 在不求解潮流的前提下，按端点母线载能类型核查 AC/DC 示例网络的 Line 与 Link 组件连接关系。

- 适用读者：互联规划分析员
- 案例模型：`pypsa-example/ac_dc_meshed`，固定版本的官方示例网络
- 分析类型：模型结构核查，不执行调度或潮流求解

## 当前用户输入

默认本地入口接收案例 ID ac-dc-interconnection 并提交清单中的单条固定问题；显式演示模式接收完整的三条登记指令。当前脚本不接受任意自由文本问题或可编辑分析范围。

提交给应用的固定问题是：“识别 AC/DC 示例网络中的母线及 Line、Link 组件，按端点母线的 AC/DC 类型说明连接关系和后续潮流研究需要的条件。”

## App 示范指令列表

以下三条指令已通过本地确定性脚本的连续回合验收，可作为 App 自动演示输入；真实 LLM 的自主理解和工具选择仍待验证。

1. 打开已登记的 AC/DC 示例网络，核对来源、AC/DC 母线以及 Line 和 Link 组件数量。
2. 沿用这个模型，按端点母线的 AC/DC 类型说明 Line 与 Link 组件的连接，并标明拓扑预览的范围。
3. 基于已核查的结构，说明后续潮流研究还需要哪些工况与约束；不要把连接关系说成功率流或输电能力结论。

## 业务问题

互联规划需要先弄清模型怎样表达交流网络与直流连接、各组件接入何处，才能定义后续潮流或输电能力研究的范围。

## Capstone 完成了什么

1. 打开来源已登记的 AC/DC 示例网络，检查母线及 Line、Link 等组件，区分端点母线的 AC/DC 类型。
2. 输出受限拓扑视图，说明组件端点、坐标可用性和任何省略数量。
3. 将结构核查与本轮结果和证据关联；本案例没有调用调度或潮流求解。

这里的 `Line` 与 `Link` 是 PyPSA 组件类型：示例中有连接 DC 母线的 `Line`，也有充当换流器的 `Link`。解读连接性质时应结合两端母线的 `carrier`，不能只凭组件类型命名。

## PyPSA 与框架支持

- Network Modeling 能力包提供已登记模型的打开、组件检查和有界拓扑能力；模型内容由 PyPSA authority 持有，不作为原始对象交给智能体或 Kernel。
- 虽然应用准备了建模与运行计算两个绑定，本案例只调用建模能力；结构结果及证据仍通过同一框架运行链路准入。

## 智能体机制如何改变交互

专业人员选择结构核查任务即可查看受限的模型连接关系，无需先操作 PyPSA 组件表或启动求解器；Capstone 同时明确哪些运行结论尚未计算。

- 任务边界只允许模型打开、组件检查和拓扑提取；同一智能体运行框架会记录这些语义步骤，但本案例不会触发调度或潮流能力。
- 最终答案绑定经本轮准入的结构结果与证据，模型拓扑与尚无依据的功率流、输电能力判断保持区分。

## 专业价值

提供可追溯的模型结构底图，便于互联规划人员核对研究对象，并明确后续分析仍需设定的工况与约束。

## 框架价值

展示同一框架也能完成无求解的结构类任务，并在展示层明确区分模型拓扑事实与尚未计算的运行结论。

## 解读边界

连接关系只能说明模型结构，不能推出实际功率流、输电能力、损耗或运行可行性。

## 当前验证范围

单条固定问题和三条连续指令均已通过确定性脚本验收；多回合复用同一运行的模型修订、结果与证据。尚未验证开放式 LLM 自主理解和选择工具。

具体组件数量、连接关系和引用应从所查看的那次运行结果读取，本介绍不预设结果。
